# 06. 通知与推送能力实现（APNs + Firebase/FCM）

## 6.1 目标与边界
- 提供可直接复用的 iOS 通知链路实现：Firebase 初始化、APNs 注册、FCM token 拉取与上报、前后台回调处理。
- 冷启动不主动弹系统通知权限；仅在首页弹窗链末位触发权限引导，避免打断主流程。
- 仅在系统通知权限已允许时，才向后端上传 `googleToken`（与现有接口约定保持一致）。

## 6.2 关键文件与职责
- `AppDelegate`：
  - 实现 `UNUserNotificationCenterDelegate`、`FIRMessagingDelegate`。
  - 在 `willFinishLaunching` 早期确保 Firebase 已 configure，避免 `I-COR000003`。
  - 在 `didRegisterForRemoteNotificationsWithDeviceToken` 设置 APNs token 并触发 FCM 拉取链路。
  - 转发 `didReceiveRemoteNotification:fetchCompletionHandler:` 给 `FIRMessaging`。
- `SceneDelegate`：
  - 回到前台时触发“通知权限重校验 + token 刷新 + user/info 重试上报”。
- `HQEPushNotificationManager`（统一管理器）：
  - 统一管理通知权限、FCM token、本地缓存、`/app/v3/user/info` 上报、首页权限引导弹窗。

## 6.3 启动阶段实现要求（必须）
1. **早期初始化 Firebase**
   - 在 `application:willFinishLaunchingWithOptions:` 调用 `ensureFirebaseCoreConfiguredEarly`。
   - 若默认 App 未配置则执行 `[FIRApp configure]`，并通过 `dispatch_once` 防重复。
2. **启动注册代理与远程通知**
   - 在 `application:didFinishLaunchingWithOptions:` 调用 `configureFirebaseAtAppLaunch`：
     - `UNUserNotificationCenter.currentNotificationCenter.delegate = AppDelegate`
     - `[FIRMessaging messaging].delegate = AppDelegate`
     - 若已授权通知权限，则执行 `registerForRemoteNotifications`。
3. **Info.plist**
   - `UIBackgroundModes` 至少包含 `remote-notification`。

## 6.4 通知权限策略（首页弹框链末位）
- **触发时机**：首页弹框优先级链的最后一个（版本更新 → 待提现 → 复借 → **通知**）。
- **检查时机**：在复借弹框完成后延迟0.3秒执行，确保前面的弹框已完全展示或关闭。
- **状态处理**：
  - `Authorized/Provisional/Ephemeral`：静默刷新 token（注册 APNs + 刷新 InstallationId + FCM + user/info）。
  - `NotDetermined`（未决定）：
    - 今日未处理过：直接 `requestAuthorization`（**仅系统弹窗**，不先弹 b15）。
    - 同意埋点 **600**，拒绝埋点 **601**；当日记入频控，拒绝后当天不再弹 b15。
  - `Denied`（系统已拒绝）：
    - 今日未处理过（通常为拒绝系统的**次日**）：展示 **b15**（Settings / Cancel）→ 跳转系统通知设置。
- **每日频控**：`HQE_LAST_NOTIFICATION_PROMPT_DATE`（`yyyy-MM-dd`），同一天只走系统或 b15 一步。
- **b15 文案**：配置 **b15**；缺省见 `HQEPermissionSecondaryPresenter`；**仅** `Denied` 分支使用。
- **与弹框链的关系**：通知权限弹框是弹框优先级链的最后一个，在所有其他弹框完成后展示。

## 6.5 Token 链路与上报策略
1. `didRegisterForRemoteNotificationsWithDeviceToken`：
   - 设置 `FIRMessaging.APNSToken`（`Unknown` 类型）。
   - 触发 `onAPNsDeviceTokenRegisteredFetchFCMIfNeeded`，进入 FCM 拉取。
2. FCM 获取策略：
   - 首选 `tokenWithCompletion`。
   - 无 token 时回退读取 `FIRMessaging.messaging.FCMToken`。
   - 必要时回退 `retrieveFCMTokenForSenderID`。
   - 增加重试、超时兜底与并发保护，防止重复回调导致并发拉取卡死。
3. 本地落库：
   - FCM token 持久化（如 `HQN_GOOGLE_FCM_TOKEN`）。
   - Firebase InstallationId 持久化（如 `HQE_FIREBASE_INSTANCE_ID`）。
4. `/app/v3/user/info` 上报约定：
   - `signedData`：`adid`、`firebaseInstanceId`（按后端签名约定）。
   - `unsignedData`：仅在通知权限允许时传 `googleToken`。

## 6.6 生命周期补偿（必须）
- `sceneDidBecomeActive`：
  - 调 `onAppBecameActiveRevalidatePushAndUpload`。
  - 处理用户从系统设置页返回后权限变化，补发注册和 token 上报。
- 首页加载：
  - 调 `prepareSDKWhenHomeLoads`，确保 SDK 就绪并刷新 InstallationId。

## 6.7 埋点与日志要求
- 权限弹窗埋点：
  - 同意：`eventCode = 600`
  - 拒绝：`eventCode = 601`
- 点击系统推送打开 App（`UNNotificationDefaultActionIdentifier`）：
  - 仅当 `applicationState` 为 `inactive` 或 `background` 时上报 **602**（`recordPushNotificationOpen602Debounced`）。
- 日志最小集：
  - Firebase 是否已配置
  - APNs token 注册结果
  - FCM token 获取来源（delegate / tokenWithCompletion / senderID）
  - user/info 上传结果（成功/失败）

## 6.9 生成代码时的硬性约束（给 AI）
- 不改变现有网络层签名规则：`googleToken` 必须保持 unsigned。
- 不在冷启动时强弹系统权限框。
- 通知权限弹框加入首页弹框优先级链，作为最后一个弹框展示（版本更新 → 待提现 → 复借 → 通知）。
- 自定义弹框实现每日频控（同一天只弹一次）。
- 未决定状态：展示自定义弹框 → 点击 Confirm 触发系统权限弹框。
- 已拒绝状态：展示引导弹框 → 点击 Confirm 跳转系统设置。
- 不允许将通知能力散落在多个页面，必须通过统一管理器封装。
- 保留可观测日志与去抖/重试机制，避免 APNs 重复回调导致并发问题。
