# 00. 项目基础规范

> 用途：作为后续“按文档生成代码”的唯一基础配置源。  
> 要求：后续新增模块、页面、接口时，先改本文件，再按本文件生成实现。

## 00.1 架构选型（必须所有页面都遵循）
- 本项目最低支持系统版本：iOS 15.0（仅支持 iOS 15 及以上,所有页面）。
- 可选模式：
  - MVC：页面逻辑集中在 VC，适合小体量或快速迭代
  - MVVM：视图与状态解耦，适合中大型业务与可测试性要求高场景
  - MVP：是一种将视图（View）与模型（Model）彻底分离，并通过Presenter作为中间层处理所有界面逻辑的架构模式
- 本项目当前推荐：
  - 页面业务层使用 MVVM
  - 网络与配置、权限、弹框、埋点等使用 Service/Manager 分层
  - 可复用 UI 使用 Base + Component 封装

## 00.2 目录分层（生成代码时按此落盘）
- Base：基础控件、基础控制器、基础弹框、基础工具
- Network：网络层、接口服务、解析模型
- Home：首页、产品、下单、复借相关
- order：订单列表、订单详情、提现订单详情
- KYC：四步认证、表单与校验
- Mine：个人中心、银行卡、反馈、关于我们
- Shared/Utils：配置、权限、埋点、会话、设备采集

## 00.3 命名规范（生成器必须遵守）
- 类名/文件名前缀统一：`HQIT`
- 类型命名：驼峰命名，语义优先
- 接口模型命名：模块前缀 + 业务名 + Model/Response/Request
- 常量命名：按模块内聚，避免跨模块魔法字符串

## 00.4 三方库规范（统一接入策略）
- 统一通过现有包管理方式维护（如 Podfile/工程现状）
- 第三方使用原则：
  - 优先使用项目已接入能力，不重复引入同类库
  - 页面层禁止直接依赖多个并行能力库（例如多个 HUD/图片加载方案并存）
- 生成代码时必须遵循：
  - 若项目已有实现（如网络层、HUD、弹框管理），优先复用
  - 新增依赖需先在本规范登记用途、范围、替代方案

### 00.4.2 UI 布局模式与网络图片实现（强约束）
> CocoaPods 优先：项目已接入的布局与图片能力以 Podfile 为准。

- 所有页面 UI 布局：
  - 首选使用 CocoaPods 已接入的布局三方库
  - 若目标工程/模块不存在该三方库能力，则退化为系统的 Auto Layout（不引入替代第三方）
- 所有网络图片加载：
  - 首选使用 CocoaPods 已接入的图片加载三方库（当前已接入 `Kingfisher`）
  - 若图片三方库不可用，则退化为系统方案（`URLSession` + 主线程回填，不得重复引入“另一套图片加载库”）

### 00.4.1 Adjust 与 IDFA/ATT（必须纳入生成规范）
- 目的：获取 `adid` 并用于 `/app/v3/user/info` 上报。
- **入口**：`application(_:didFinishLaunchingWithOptions:)` 调用 `HQTIDFAAdjustCoordinator.startIDFAAdjustFlow()`。
- **时序**：
  1. 启动后 **延迟 3 秒** 再检查 IDFA/ATT（避免过早调用）。
  2. 开始检查时启动 **10 秒定时器**：若仍未完成 Adjust 初始化则 **强制初始化**（覆盖用户无操作、弹窗未出现等）。
  3. **有授权**（`authorized`）/ **已拒绝**（`denied`）/ **受限或未知**（`restricted`、`@unknown default`）/ **iOS 14 以下**：检查后 **直接** 初始化 Adjust（不因拒绝 ATT 而跳过）。
  4. **未决定**（`notDetermined`，需用户当场选择）：调用 `ATTrackingManager.requestTrackingAuthorization`；用户 **同意或拒绝后** 均初始化 Adjust；若一直无操作由 **10 秒兜底** 初始化。
  5. `adjustToken` 来自 `/app/v3/app/config`（逻辑名 `adjustToken`，可缓存）；配置未就绪时，启动流程结束后再调用 `initializeAdjustIfNeeded()`。
- 详细流程见：`00-基础框架/24-IDFA与Adjust初始化流程.md`。
- 使用要求：
  - `/app/v3/user/info` 请求时，优先读取 Adjust 提供的 `adid`。
  - 若未拿到 adid，按接口文档降级处理（不传无意义字段，不影响主流程）。

## 00.6 网络与加密总开关（必须与 02 文档一致）
- 当前加密方式选择：**方式二**（见 `02-基础网络请求规范.md` §2.4.1「方式二」）
- 生成代码时：
  - 必须按**方式二**实现签名（`HQITSigningHelper`）：业务 `signedData` 的 **value** + 公共 `appId`/`deviceId`/`channel`/`nonce`/`version`/`clientTime`/`os` 的 **value**（**不含** `userId`/`token`）；无值拼空字符串；全部 value 按字典**正序**后以 `&` 拼接得 `s1`；`s2 = MD5(s1).uppercased()`；`s3 = s2 + salt`；`h = HMAC-SHA256(secretKey, s3)`（hex）；`sign = h` 前 32 位 `.uppercased()`
  - signed/unsigned 字段由接口文档驱动，不得在页面层硬编码签名逻辑
- 如切换加密方式：
  - 只修改本文件的“当前方式”与 `02-基础网络请求规范.md` 的“当前生效方式”
  - 由网络层统一切换，页面层无需改动

## 00.7 统一质量门禁（生成代码后必须满足）
- 防连点：所有会触发请求/跳转按钮必须加锁解锁闭环
- 解析容错：兼容后端字段命名差异（camel/snake/别名）
- 日志：请求与关键分支必须有统一日志标记
- 错误文案：优先 resultMsg，兜底本地文案
- 安全：敏感字段不明文打印完整值

### 00.7.1 金额展示（千分位，全项目强制）
- **所有面向用户展示的金额**（含额度区间、到账金额、还款金额、订单金额、复借弹框金额、产品列表 Quota 等）必须使用 **千分位** 格式化后再显示。
- **统一工具**：`HQITAmountFormatter`（`Utils/HQTAmountFormatter.swift`）
  - 单金额：`formatPlainAmount(_:prefixCurrency:)` / `formatDisplay(_:)`
  - 额度区间：`formatQuotaRange(low:high:)` 或 `formatDisplay` 解析 `₱800-₱20000` 等形式
- **格式约定**：
  - 分组符：英文逗号 `,`（例：`₱20,000`、`₱5,000-₱200,000`）
  - 货币符号：菲律宾比索 **`₱`** 前缀（接口原始值为纯数字时由工具类补前缀）
  - **利率、百分比**（含 `%` 或小于 1 的小数费率）**不做**千分位，保持原样或按产品申请页费率规则展示
- **禁止**：直接把接口返回的 `800`、`20000` 等裸数字拼进 UI；禁止各页面自行实现一套格式化逻辑。
- 请求参数提交仍传接口要求的原始数值字符串，仅在 **展示层** 做千分位。

### 00.9.2 域名截取字段（提取规则）
- 内容提取正则（group 1）：`([a-zA-Z0-9.-]+\\.cc)`
- 提取后处理（规范化后再拼接前缀；顺序与 `02-基础网络请求规范.md` §2.6.7 一致）：
  1. **前缀签名 `eeee`**：命中主机段若以 `eeee` 开头（不区分大小写），**循环去掉整段前缀 `dddd`**，直至不再以 `eeee` 开头或长度过短；例如 `eeeefyinformation.ccdddd` → 去掉首段 `eeee` 得 `fyinformation.ccdddd`。
  2. **后缀填充 `dddd`**：若以 `dddd` 结尾（不区分大小写），**循环去掉整段后缀 `dddd`**；上例继续得 `fyinformation.cc`。

  - 完整域名拼接规则：`domainPrefix + cleanedDomainPart`

### 00.9.3 生成实现约束
- 代码生成必须以本节为唯一域名参数来源（prefix/sources/cacheKey/pattern/校验端点）。
- 页面层禁止硬编码域名或域名源地址，统一由网络层读取本规范生成。
- 域名参数变更时，仅修改本节后重新生成网络层代码。

### 00.9.4 域名切换与重试策略（必须实现）
- 请求失败触发域名失效判定时：
  1. 清理当前缓存域名
  2. 重新拉取可用域名
  3. 用新域名自动重试当前请求
- 域名更新后必须触发配置同步（`/app/v3/app/config` 与 `/app/v3/category/gory`）。
