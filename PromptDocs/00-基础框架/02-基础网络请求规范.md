# 02. 基础网络请求规范（signed/unsigned 与返回口径）

## 2.1 统一请求体结构
- 请求方式：POST，JSON 请求体。
- 统一公共请求参数由网络层注入；业务层只传 data 业务字段。
- 公共请求参数清单如下（与项目历史文档同步）：

| 字段 | 类型 | 长度 | 是否可空 | 默认值 | 描述 |
|---|---|---|---|---|---|
| userId | String | 0-32 | 是 | - | 用户ID |
| token | String | 0-32 | 是 | - | Token令牌 |
| appId | String | 1-32 | 否 | hqteconsmpton | APP应用标识 |
| deviceId | String | 1-64 | 否 | - | 唯一设备标识 |
| os | String | - | 否 | "2" | iOS 固定值 |
| channel | String | - | 否 | "app_store" | 渠道固定值 |
| clientLanguage | String | - | 否 | "en" | 语言固定值 |
| clientVersion | String | 1-16 | 否 | - | 客户端版本号 |
| clientTime | Long | - | 否 | - | 客户端请求时间（毫秒） |
| version | String | - | 否 | "2.0" | 接口规范版本号 |
| nonce | String | 16 | 否 | - | 16位随机字符串 |
| sign | String | 32 | 否 | - | 请求签名（32位） |
| data | Dictionary | - | 否 | - | 业务请求体 |

## 2.2 公共返回格式（统一）
- 公共返回字段清单：

| 字段 | 类型 | 是否可空 | 描述 |
|---|---|---|---|
| data | Object | 否 | 返回的业务数据，结构由具体接口定义 |
| resultCode | Integer | 否 | 响应状态码，200 表示成功 |
| resultMsg | String | 否 | 响应消息描述 |
| timestamp | Long | 否 | 服务端响应时间戳（毫秒） |

- 常见状态码说明：
  - `200`：操作成功
  - `401`：未登录或登录已过期
  - `403`：无权限
  - `404`：资源不存在
  - `500`：服务器内部错误

## 2.3 signed / unsigned 的核心约定
- 某些接口要求“仅少量字段参与签名”：
  - 这些字段属于 signedData（或签名参与字段）
  - 其余字段属于 unsignedData，不参与签名
- 文档要求：
  - 必须严格区分参与签名字段 vs 不参与签名字段
  - 若参与签名字段错误，后端可能返回签名错误或业务失败

## 2.4 签名策略（项目实现口径）
- 项目支持 4 种加密方式，统一由网络层实现，页面层不感知算法细节。
- **当前生效方式：`加密方式二`**（与 `00-项目基础规范.md` §00.6 一致；HQIOneCaptn 印度项目）。

### 2.4.1 四种加密方式定义

#### 方式一
- 参与字段：
  - 请求业务字段（按接口要求）
  - 公共字段：`appId/deviceId/channel/nonce/version/clientTime/os`
- 排序：按值字典正序
- 拼接：`&`
- 计算：
  1. 先对拼接串做 MD5 并转大写，得到 s2
  2. `s3 = s2 + salt`
  3. 对 s3 再做 MD5 并转大写，得到 sign

#### 方式二
- 参与字段同方式一（业务侧仅 `signedData` 中标记参与签名的字段；`unsignedData` 不参与）。
- 排序：取所有参与签名字段的**value**，按字典正序。
- 拼接：`&`
- 计算：
  1. `s1 = join(sorted(values), "&")`
  2. `s2 = MD5(s1).toUpperCase()`
  3. `s3 = s2 + salt`
  4. `h = HMAC-SHA256(secretKey, s3)`（hex）
  5. `sign = h.substring(0, 32).toUpperCase()`
- 空值规则：字段参与签名但无值时，以空字符串参与 value 列表。
- nonce 要求：16 位随机字符串，每次请求应尽量唯一。

#### 方式三（历史，已停用）
- 参与字段：业务 `signedData` 的 value + 公共 `appId`/`deviceId`/`channel`/`nonce`/`version`（**不含** `clientTime`/`os`）。
- 排序：参与 value 按字典**倒序**。
- 拼接：分号 `;`。
- 计算：`sign = MD5(拼接串 + salt).toUpperCase()`（**无** `MD` 标记）。
- 仅作历史对照；**当前项目不启用**。

#### 方式四（当前生效，与后端 Java 网关一致）
- **实现类**：`HQTSigningHelper.swift`（全项目唯一签名入口；禁止在 VC 内自行拼 `sign`）。
- **appId / salt**：见 `00-项目基础规范.md` §00.6（`HQTNetworkConstants`）。

**步骤（与后端 `@SignatureField` + 公共参数逻辑一致）：**

1. 后端为每个 APP 分配独立 **appId** 与 **salt**。
2. 客户端每次请求生成 **16 位**随机 **nonce**，同一请求内唯一，不同请求间尽量不重复。
3. 将请求体中**参与签名**的业务字段转为 value 列表（仅 value，不含 key）：
   - 以接口文档为准；带 `@SignatureField`（或项目 `signedData`）的字段才参与。
   - **不参与签名的字段不得加入列表**（对应客户端 `unsignedData`，合并进 `data` 但不进签名）。
   - 业务字段在 `signedData` 中按 **key 字典正序**依次取 value 追加（与 Java `ReflectUtil.getFields` 遍历顺序无关，最终统一按步骤 6 对全部 value 倒序）。
4. 将以下公共参数的 **value** 追加到同一列表（**不含** `clientTime`、`os`、`userId`、`token`）：
   - `appId`、`deviceId`、`channel`、`nonce`、`version`
5. 列表每一项只取 **value** 并字符串化；字段参与签名但无值时拼接 **空字符串** `""`（`nil` / `NSNull` → `""`）。
   - 埋点等接口若在 `data` 内显式写入字面量 `"NULL"`，则按字符串 **`NULL`** 参与签名（非空串）。
6. 对上述所有 value 按**字典倒序**排序（字符串 `compare` 降序，等价于 Java `Collections.reverse` 后的顺序）。
7. 用 `*` 连接排序后的 value，末尾拼接固定标记 **`MD`**，再拼接 **salt**，得到 `s1`：
   - `s1 = String.join("*", sortedValues) + "MD" + salt`
8. `sign = MD5(s1).toUpperCase()`（32 位大写十六进制）。

**signed / unsigned 与请求体 `data`：**
- **仅** `signedData` 来源的业务字段参与签名；`unsignedData` 合并进 `data` 但**不参与**签名。
- 无业务参数时请求体仍传 **`data: {}`**（网关反序列化需要字段存在）。
- **仅公共参数参与签名**的 endpoint（网络层 `publicParamOnlyEndpoints`，忽略传入的 `signedData`）：
  - `/app/v3/app/config`
  - `/app/v3/category/gory`
  - `/app/v3/user/suphome`
  - `/app/v3/user/info`（`data` 内 `adid` 等走 **unsignedData**，**不参与签名**）
  - `/app/v3/mobile/registerDevice`
  - `/app/v3/auth/close`
  - `/app/v3/payAccountInfo/update`（`data` 内 `recordId`、`defaultFlag`、`kycCommitItemList` 等**不参与签名**，仍明文写入 `data`）
- **须带业务字段签名**的示例：`/app/v3/bury/record`、发 OTP、`termV3` 等——`signedData` 的 value 与五个公共 value 一并进入步骤 6 倒序列表。

**与方式三差异（联调时注意）：**
| 项目 | 方式三（历史） | 方式四（当前） |
|------|----------------|----------------|
| 分隔符 | `;` | `*` |
| salt 前标记 | 无 | `MD` |
| 公式 | `MD5(join + salt)` | `MD5(join + "MD" + salt)` |

**secretKey（仅方式二使用）**：`MFwwDQYJKoZIhvcNAQEBBQADSwAwSAJBALHlrsKZ`（见 `00-项目基础规范.md`）。

### 2.4.2 生成实现约束
- 代码生成时必须先读取 `00-项目基础规范.md` §00.6 的“当前生效方式”（**方式二**）。
- 网络层统一调用 `HQITSigningHelper` / `HQITNetworkClient`，按**方式二**计算 `sign`。
- 页面层仅提供：
  - signedData（参与签名的业务字段）
  - unsignedData（不参与签名字段）
- 禁止在 VC/ViewModel 中自行拼签名。

### 2.4.3 切换加密方式操作
1. 修改 `00-项目基础规范.md` §00.6 的“当前生效方式”。
2. 同步修改本文件 §2.4 的“当前生效方式”与对应方式定义。
3. 仅调整 `HQTSigningHelper`（及必要时 `publicParamOnlyEndpoints`）；业务页面无需改动。

### 2.4.4 常见接口签名字段明细（生成/联调必读）

> **实现约束**：业务层只组 `signedData` / `unsignedData`；`sign` 由 `HQTNetworkClient.buildPOSTRequestBody` 统一计算。  
> **签名 value 必须与最终写入 `data` 的字符串完全一致**（先 merge `signedData` + `unsignedData` 成 `data`，再按 `signedData` 的 key 从 `data` 取 value 参与签名，见 `HQTNetworkClient.buildPOSTRequestBody`）。  
> **经纬度**：凡参与签名的 `longitude` / `latitude` 一律为 **6 位小数字符串**（`String(format: "%.6f", value)`，实现 `HQTSigningHelper.coordinateSignValue`），禁止用 `Double` 直接签名（避免 JSON 序列化精度与验签不一致）。

#### `/app/v3/order/userSubmitV3`（下单 / 复借下单）

| 字段 | 参与签名 | 类型 | 取值说明 |
|------|----------|------|----------|
| `productId` | **是** | String | 当前产品 ID（逻辑字段名；`termV3` 同口径） |
| `loanAmount` | **是** | String | 当前选中额度，如 `"11000"` |
| `longitude` | **是** | String | 6 位小数；强抓：真实经度；非强抓：`-360.000000` |
| `latitude` | **是** | String | 6 位小数；强抓：真实纬度；非强抓：`-360.000000` |
| `imei` | **是** | String | 固定字面量 **`"null"`**（非 JSON null） |
| `serialNo` | **是** | String | 与公共参数 `deviceId` 相同 |
| `showTerm` | 否 | String | 当前期限展示值，如 `"50"`、`"7"` |
| `orderType` | 否 | String | **仅复借**传 `"1"`；普通 H5 下单**不传** |
| `bankCardBindId` | 否 | String | 可选；有默认/选中绑卡时传 |

- 业务字段按 key **字典正序**取 value 进入签名列表（示例顺序：`imei` → `latitude` → `loanAmount` → `longitude` → `productId` → `serialNo`），再与 `appId/deviceId/channel/nonce/version` 的 value 合并后 **倒序**、`*` 拼接（方式四）。
- 原生复借组装：`HQTAPIFieldMapper.userSubmitV3SignedData(productId:loanAmount:longitude:latitude:)`（`HQTReloanFlowCoordinator`）。
- **`h5_interface_confuse=1` 时仅混淆 `data` 内业务字段**；顶层公共参数始终为逻辑名（`appId`、`version`、`sign`、`data` 等），不得把 `version` 写成 `imagination` 等 wire 名。
- `data` 内字段 wire 后，**签名 value 以 merge 进 `data` 的最终 value 为准**（公共参数仍用逻辑名参与签名）。

**请求 `data` 示例（复借，confuse=0）**：

```json

  "loanAmount": "11000",
  "longitude": "-122.406417",
  "latitude": "37.785834",
  "imei": "null",
  "serialNo": "5AE4C98A-6D44-417E-B9B4-22525C2B7FAB",
  "showTerm": "50",
  "orderType": "1"
}
```

## 2.5 错误处理与重试
- 网络错误由基础网络层映射为项目错误类型（例如域名不可用、签名失败、解析失败等）
- 域名不可用时自动切换域名并重试
- 业务层只关心成功/失败回调与错误文案展示

## 2.6 域名获取及使用流程（统一规范）

### 2.6.1 域名来源与获取顺序
- 网络层维护“域名源列表”（多个远端源）。
- 获取时按顺序尝试：
  1. 读取本地缓存域名（若有效优先生效）
  2. 逐个请求远端域名源，解析可用域名
  3. 首个可用域名写入本地缓存并设为当前域名

### 2.6.2 启动阶段使用规则
- 应用启动时网络层必须完成一次“域名可用性判定”：
  - 若缓存域名可用，直接使用
  - **若无本地可用缓存**（首次安装、缓存缺失、校验失败），须**立即**按域名源拉取远端并校验，不得延迟到用户操作业务按钮时再拉（与 `04-应用启动配置管理.md` §4.2.1 一致）。
- 域名生效后继续配置请求：
  - `/app/v3/app/config`
  - `/app/v3/category/gory`

### 2.6.3 请求阶段使用规则
- 每次请求使用“当前生效域名 + endpoint”拼接完整 URL。
- 若请求出现“域名不可达/网络层判定域名失效”：
  1. 标记当前域名失效
  2. 触发下一可用域名切换
  3. 自动重试当前请求（按统一重试次数上限）

### 2.6.4 缓存与回退策略
- 域名缓存需持久化，供下次启动快速使用。
- 缓存域名校验失败时不得阻塞业务，必须自动回退到“远端源重新拉取”。
- 域名切换成功后应触发配置同步，避免新域名下配置不一致。

### 2.6.5 并发控制
- 域名刷新流程要有并发锁：
  - 同一时刻只允许一个域名刷新任务
  - 其它请求等待刷新结果或按策略快速失败重试

### 2.6.6 生成实现约束
- 生成代码时，域名管理必须放在网络层（Manager/Service），禁止页面层自行拼域名。
- 页面只传 endpoint 与业务参数，不感知域名切换细节。

### 2.6.7 README 域名占位与拼接规则（`ssss` / `gggg` ）
- 远端 README / 配置源中用正则提取的 `*.cc` 主机名，除历史约定的 **`ssss`** 外,**后缀填充 `gggg`**（均为连续 4 个字母，不区分大小写），例如：`ssssfyinformation.ccgggg` 表示真实主机为 `fyinformation.cc`（去掉前缀 `ssss` 与后缀 `gggg`）。
- 客户端在拼接 API 基址前缀（如 `https://test-phl-api.`）之前，必须按下述顺序规范化：
  1. **前缀 `ssss`**：**循环去掉前缀 `ssss`**（只要仍以 `ssss` 开头且剩余长度大于 4，就继续去前缀）。
  2. **后缀 `gggg`**：**循环去掉后缀 `gggg`**（只要仍以 `gggg` 结尾且剩余长度大于 4，就继续去后缀）。

- 规范化后再拼接为完整基址，例如：`https://test-phl-api.fyinformation.cc`。
- **健康检查**：对候选基址发起探测请求（如 `GET /api/test`）时，若 HTTP 状态为 **2xx～4xx**（含 **404**），视为**主机可达**、域名可用；仅 **5xx** 或网络错误视为不可用。避免因测试路径未部署导致误判。

## 2.7 统一日志
- 请求开始：接口名称、端点、请求参数
- 响应：打印原始返回（便于联调定位字段命名问题）
- 失败：打印错误类型 + 错误文案
