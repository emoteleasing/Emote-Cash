# 08. 接口出参字段混淆映射

服务端 JSON **出参**使用混淆字段名；客户端通过 `HQEAPIResponseField` 统一转换。

## 使用方式

- 头文件：`HQElenFiae/Shared/Utils/HQEAPIResponseField.h`
- 逻辑名 → 混淆 key：`NSString *wire = HQEAPIKey(@"policyHref");` → `fatal`
- 读字典：`id v = dict[HQEAPIKey(@"userStatus")];` 或 `HQEAPIDictGet(dict, @"userStatus")`

代码中**保留逻辑名**（如 `policyHref`、`orderId`），仅在访问接口 JSON 时经 `HQEAPIKey()` 映射。

## 约定

| 类型 | 处理 |
|------|------|
| `/app/v3/app/config` 等响应体 | 全量映射表见 `HQEAPIResponseField.m`（214 对） |
| `dynamicParameter` | `dywogpe`；其内 `fjtip` → `pelkcat` |
| 响应 envelope 的 `data` | **逻辑名 `data`**（本包不再使用 wire `quality` / `correspond`） |
| 请求体 envelope 根级 | **逻辑名**：`appId`、`deviceId`、`version`、`channel`、`nonce`、`sign`、`data`、`userId`、`token`、`os`、`clientLanguage`、`clientVersion`、`clientTime`（勿用 `majority`/`purpose`/`lavatory` 等） |
| 请求体 `data` **内部**业务字段 | 出网前由 `HQEAPIRequestDictEncode` 转为 wire key；映射表 **`HQEAPIRequestField.m`**（326 对，与 `python_replace.py` 同步，改表后运行 `sync_request_field_map.py`）；业务代码仍写逻辑名 |
| H5 `mobileUserdata`（`userId`、`token`、`orderId` 等） | 仍为逻辑名，与 H5 约定一致；**不要**对 H5 注入 JSON 跑 Python 字段替换 |
| 本地 UI 字典 key | 不使用 `HQEAPIKey` |

## 与 Python 脚本的关系

- `python.py`：仅替换接口 **路径**（如 `/app/v3/app/config` → `/app/obvious/app/breakfast`）。
- `python_replace.py`：对 `.m/.h/.swift` 中**引号内字符串**做逻辑名→wire 名批量替换。
- **禁止**让 `python_replace.py` 改网络层 envelope 字段名（否则会出现 `version 不能为空`：网关只认 `version` 不认 `purpose`）。
- 推荐流程：业务源码保留逻辑名字符串 → `HQENetworkClient` 组装 envelope 用逻辑名 → `data` 内字典经 `HQEAPIRequestDictEncode` 再 POST；读响应继续 `HQEAPIKey()`。

## 维护

增删接口字段时：在 `HQEAPIResponseField.m` 的 `HQEAPIResponseFieldMap` 中增加 `逻辑名 : 混淆名` 一对；业务代码继续写逻辑名 + `HQEAPIKey()`。
