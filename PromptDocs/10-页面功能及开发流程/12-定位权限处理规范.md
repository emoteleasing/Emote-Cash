# 定位权限处理规范

## 概述

本文档说明产品下单页面的定位权限处理逻辑，与参考项目 HQFApplyVC 保持一致。

---

## 核心设计原则

### 1. 状态管理

使用三个标志位管理定位权限状态：

```swift
private var isLocationAlertShowing: Bool = false      // 防止重复显示弹框
private var isFirstTimeLocationRequest: Bool = false  // 区分首次和非首次请求
private var isLocationDataSent: Bool = false          // 防止重复发送位置数据
```

### 2. 强抓模式配置

- **配置字段**：`retrieveMobileContact`
- **强抓模式值**：`1`
- **非强抓模式值**：`0` 或其他值

### 3. 无效坐标标识

- 非强抓模式、**非首次**且无权限时使用：`"-360", "-360"`（JSON 对象字段）

### 4. 产品申请 / 订单详情 H5：`positionPermission` 回传（iOS → H5）

与 `04-产品申请与下单.md` §4.4.6 一致：

| 场景 | payload |
|------|---------|
| 有真实坐标 | `{"longitude":"…","latitude":"…"}` |
| 非强抓、非首次、无权限 | `{"longitude":"-360","latitude":"-360"}` |
| 首次系统拒绝；强抓无法定位；b3 取消/去设置 | 字面量 `""` |

**禁止** `{"longitude":"","latitude":""}`。  
**实现类**：`HQTProductApplyLocationBridge`。

**注入 H5 时**：`HQTProductApplyH5ViewController` 须依次调用 `window.positionPermission(对象)` 与 `window.positionPermission(JSON.stringify(对象))`，并同步 `localStorage`/`sessionStorage` 键 `positionPermission`；联调日志 `ok_obj` / `ok_str` 均视为成功。

## 详细实现

### 1. 初始化定位管理器

```swift
override func viewDidLoad() {
    super.viewDidLoad()
    
    // 配置定位管理器
    locationManager.delegate = self
    locationManager.desiredAccuracy = kCLLocationAccuracyHundredMeters
    locationManager.distanceFilter = 100
    
    loadTermV3()
}
```

### 2. 解析定位坐标

```swift
private func resolveCoordinatesForSubmit(completion: @escaping (_ ok: Bool, _ longitude: String, _ latitude: String) -> Void) {
    let mode = readRetrieveMobileContactMode()
    
    // 非强抓模式，直接使用默认坐标
    guard mode == 1 else {
        completion(true, "-360", "-360")
        return
    }
    
    let status = locationManager.authorizationStatus
    
    // 重置状态
    isLocationAlertShowing = false
    isLocationDataSent = false
    
    switch status {
    case .denied, .restricted:
        // 已拒绝（非首次，显示二次弹框）
        isFirstTimeLocationRequest = false
        handleLocationDenied()
        
    case .notDetermined:
        // 首次请求系统权限
        isFirstTimeLocationRequest = true
        locationManager.requestWhenInUseAuthorization()
        // 不调用 completion，等待回调
        
    case .authorizedAlways, .authorizedWhenInUse:
        // 已授权，获取位置
        isFirstTimeLocationRequest = false
        startLocationUpdate()
        
    @unknown default:
        isFirstTimeLocationRequest = false
        handleLocationDenied()
    }
}
```

### 3. 开始定位更新

```swift
private func startLocationUpdate() {
    print("========== startLocationUpdate ==========")
    locationManager.startUpdatingLocation()
}
```

**注意**：
- ✅ 使用 `startUpdatingLocation()`（持续更新）
- ❌ 不使用 `requestLocation()`（单次请求）
- ❌ 不设置超时机制

### 4. 处理定位拒绝

```swift
private func handleLocationDenied() {
    let mode = readRetrieveMobileContactMode()
    
    // 防止重复显示弹框
    guard !isLocationAlertShowing else { return }
    isLocationAlertShowing = true
    
    // 显示二次弹框
    HQTDialog.showPermissionSecondaryAlert(
        on: self,
        kind: .location,
        messageOverride: "Please allow location access in Settings to complete the loan application.",
        onCancel: { [weak self] in
            guard let self = self else { return }
            self.isLocationAlertShowing = false
            self.submitLock.unlock()
            self.spinner.stopAnimating()
            
            // 强抓模式下，点击取消返回上一页
            if mode == 1 {
                self.navigationController?.popViewController(animated: true)
            }
        },
        onConfirmAfterOpenSettings: { [weak self] in
            guard let self = self else { return }
            self.isLocationAlertShowing = false
            self.submitLock.unlock()
            self.spinner.stopAnimating()
            
            // 用户从设置返回后，停留在当前页面
            // 不执行任何导航操作，让用户可以重新尝试提交
        }
    )
}
```

**关键点**：
- ✅ 点击"取消"：强抓模式下返回上一页
- ✅ 点击"去设置"并返回：**停留在当前页面**，让用户可以重新尝试提交
- ✅ 非强抓模式：点击取消不返回，停留在当前页面

### 5. 定位成功回调

```swift
func locationManager(_ manager: CLLocationManager, didUpdateLocations locations: [CLLocation]) {
    guard let location = locations.last else { return }
    
    currentLocation = location
    locationManager.stopUpdatingLocation()
    
    let longitude = String(format: "%.6f", location.coordinate.longitude)
    let latitude = String(format: "%.6f", location.coordinate.latitude)
    
    // 防止重复发送
    guard !isLocationDataSent else { return }
    isLocationDataSent = true
    
    sendUserSubmitV3(longitude: longitude, latitude: latitude)
}
```

**关键点**：
- ✅ 使用 `isLocationDataSent` 防止重复发送
- ✅ 获取位置后立即停止更新
- ✅ 格式化坐标为6位小数

### 6. 定位失败回调

```swift
func locationManager(_ manager: CLLocationManager, didFailWithError error: Error) {
    locationManager.stopUpdatingLocation()
    
    // 检查是否是权限问题
    let status = CLLocationManager.authorizationStatus()
    if status == .denied || status == .restricted {
        handleLocationDenied()
    } else {
        // 已授权但获取位置失败（GPS问题）
        handleLocationFailed()
    }
}

private func handleLocationFailed() {
    submitLock.unlock()
    spinner.stopAnimating()
    
    HQTDialog.showCardAlert(
        on: self,
        title: "Location Error",
        message: "Failed to get location. Please check your GPS settings and try again.",
        icon: UIImage(systemName: "location.slash.circle.fill"),
        actions: [
            HQTDialog.Action(title: "Retry", style: .normal, handler: { [weak self] in
                self?.submitTapped()
            }),
            HQTDialog.Action(title: "Cancel", style: .cancel)
        ]
    )
}
```

**关键点**：
- ✅ 区分权限问题和GPS问题
- ✅ 提供重试选项

### 7. 权限状态变化回调

```swift
func locationManagerDidChangeAuthorization(_ manager: CLLocationManager) {
    let status = manager.authorizationStatus
    
    // 忽略 notDetermined 状态
    guard status != .notDetermined else { return }
    
    let mode = readRetrieveMobileContactMode()
    
    DispatchQueue.main.async { [weak self] in
        guard let self = self else { return }
        
        switch status {
        case .authorizedWhenInUse, .authorizedAlways:
            // 用户授权，开始获取位置
            self.isFirstTimeLocationRequest = false
            self.startLocationUpdate()
            
        case .denied, .restricted:
            if self.isFirstTimeLocationRequest {
                // 首次请求被拒绝
                self.isFirstTimeLocationRequest = false
                self.submitLock.unlock()
                self.spinner.stopAnimating()
                
                // 强抓模式下，首次拒绝返回上一页
                if mode == 1 {
                    self.navigationController?.popViewController(animated: true)
                }
            } else {
                // 非首次请求被拒绝，显示二次弹框
                DispatchQueue.main.asyncAfter(deadline: .now() + 0.5) {
                    self.handleLocationDenied()
                }
            }
            
        default:
            self.submitLock.unlock()
            self.spinner.stopAnimating()
        }
    }
}
```

**关键点**：
- ✅ 使用 `isFirstTimeLocationRequest` 区分首次和非首次
- ✅ 首次拒绝：强抓模式下返回上一页
- ✅ 非首次拒绝：显示二次弹框

## 业务规则

### 强抓模式（retrieveMobileContact = 1）

| 场景 | 行为 | 说明 |
|------|------|------|
| **首次请求被拒绝** | 返回上一页 | 不显示二次弹框，直接返回 |
| **已拒绝 + 点击取消** | 返回上一页 | 显示二次弹框后点击取消 |
| **已拒绝 + 点击去设置** | **停留当前页面** | 用户从设置返回后可以重新尝试 |
| **授权成功** | 获取位置并提交订单 | 正常流程 |
| **定位失败（GPS）** | 显示重试弹框 | 提供重试选项 |

### 非强抓模式（retrieveMobileContact = 0）

| 场景 | 行为 | 说明 |
|------|------|------|
| **任何情况** | 使用默认坐标 `-360,-360` | 不请求定位权限 |

## 与通讯录权限的对比

| 特性 | 定位权限 | 通讯录权限 |
|------|---------|-----------|
| **触发时机** | 点击提交按钮前 | 订单创建成功后 |
| **首次拒绝** | 返回上一页 | 返回上一页 |
| **已拒绝 + 取消** | 返回上一页 | 返回上一页 |
| **已拒绝 + 去设置** | **停留当前页面** | 返回上一页 |
| **订单状态** | 未创建 | 已创建 |

**差异说明**：
- **定位权限**：用户从设置返回后停留在当前页面，因为订单还未创建，用户可以重新尝试提交
- **通讯录权限**：用户从设置返回后返回上一页，因为订单已创建，需要用户重新进入订单详情页继续流程

## 关键差异说明

### 与之前实现的差异

| 特性 | 之前实现 | 当前实现（与参考代码一致） |
|------|---------|--------------------------|
| **定位方法** | `requestLocation()` | `startUpdatingLocation()` |
| **超时机制** | 5秒超时 | 无超时 |
| **状态管理** | `isPendingSubmitAfterLocationAuth` | `isFirstTimeLocationRequest` |
| **防重复** | 无 | `isLocationDataSent` |
| **首次拒绝** | 仅解锁 | 返回上一页 |
| **已拒绝+取消** | 不返回 | 返回上一页 |

### 为什么去掉超时机制？

1. **与参考代码保持一致**：HQFApplyVC 没有超时机制
2. **避免误判**：某些环境下定位可能需要较长时间
3. **用户可主动取消**：用户可以通过返回按钮退出
4. **系统会自动处理**：iOS系统会在定位失败时触发 `didFailWithError`

### 为什么使用 startUpdatingLocation？

1. **持续更新**：可以获取更准确的位置
2. **自动重试**：系统会自动重试获取位置
3. **更可靠**：不会因为单次失败而放弃

## 注意事项

### 1. 防止重复发送

```swift
guard !isLocationDataSent else { return }
isLocationDataSent = true
```

**原因**：`didUpdateLocations` 可能被多次调用，需要防止重复提交订单。

### 2. 停止定位更新

```swift
locationManager.stopUpdatingLocation()
```

**原因**：获取到位置后应立即停止更新，节省电量。

### 3. 主线程执行UI操作

```swift
DispatchQueue.main.async { [weak self] in
    // UI操作
}
```

**原因**：定位回调可能在后台线程，UI操作必须在主线程。

### 4. 延迟显示二次弹框

```swift
DispatchQueue.main.asyncAfter(deadline: .now() + 0.5) {
    self.handleLocationDenied()
}
```

**原因**：避免与系统权限弹框冲突。
