# 14. 订单详情 H5（Order Detail）

## 14.1 页面目标
- App 内需要查看「订单详情」的场景，统一进入 H5 订单详情页（与产品申请页共用同一套原生容器能力：桥接、定位、数据抓取、成功回跳与好评引导）。
- H5 链接由运营配置下发；进入时在 URL 上携带订单维度参数，在 `mobileUserdata` 中携带通用登录与设备参数。

## 14.2 配置与入口
- **链接字段**：`/app/v3/app/config` 中的 `orderDetailsLink`（解析方式与 `productApplyLink` 相同，使用 `HQEAppConfigHelper stringForHrefConfigKey:@"orderDetailsLink"`）。
- **原生入口**（示例）：
  - 订单列表点击某条订单进入详情。
  - 其它业务（如产品申请异常码跳转详情）在拿到 `orderId` 后同样打开该容器。

## 14.3 URL 查询参数
| 参数 | 必填 | 说明 |
|------|------|------|
| `orderId` | 是 | 当前订单编号 |
| `productId` | 否 | 列表或上下文能拿到时再传；无则不要带该参数 |
| `orderType` | 否 | **待提现**等需要区分 H5 模板/流程时传递；取值以服务端与 H5 约定为准（可与列表项字段 `orderType` 一致）。原生侧：当订单状态为待提现（如 `orderStatus`/`status` 为 32）且列表未给值时，可传兜底占位 `1`，联调时可替换。 |

说明：通用环境参数（`baseUrl`、`userId`、`token` 等）由原生在页面加载后通过 `mobileUserdata` 注入，不要求全部堆在 URL 上。

## 14.4 与产品申请页一致的原生能力
下列行为与 `04-产品申请与下单` / `05-数据抓取` / `13-下单成功与好评引导` 保持一致：
- **JS 通道名**：`iosHandler`。
- **注入数据**：`mobileUserdata`（含 `baseUrl`、`userId`、`token`、`UA`、`deviceId`、`clientVersion`、`appId`、`salt`、`countryCode`、`appName` 等）；订单详情模式下额外包含 `orderId`，若打开时带了 `productId` / 需在 H5 使用的约定字段则一并下发。
- **定位**：`positionPermission`，强抓/非强抓与回传规则同申请页（payload 口径见 `04-产品申请与下单.md` §4.4.6）。
- **抓取链路**：`uploadData&&{orderId}` → 设备上报 → 通讯录分片 → `order/ready` → `uploadDataSucc` / `uploadDataFail`（实现：`HQTOrderDataCaptureCoordinator` + `HQTOrderDetailH5ViewController`）。

### 14.4.1 抓取结果与通讯录二次弹框（订单详情）

| 结果 | H5 | 原生导航 |
|------|-----|----------|
| 抓取全流程成功 | `uploadDataSucc()` | 留在详情 H5 |
| device / contact / ready 等失败 | `uploadDataFail()` | 留在详情 H5 |
| 强抓通讯录**二次引导**（去设置 / 关闭） | `uploadDataFail()` | **不**自动 pop，由 H5 决定后续 UI |

- 启动抓取时：`failOnContactsSecondaryInteraction: true`（与产品申请页一致）。
- 二次弹框任一点击：不 Toast「Contacts permission is required」，直接结束抓取并 `evalH5Callback("uploadDataFail")`。
- 与产品申请页差异：申请页在二次弹框失败且 `uploadDataFail` 执行后会 **pop 一层**；订单详情**无**此自动返回。
- **申请成功回跳与好评**：`successfulGoBack`（及与申请页一致的反馈类 action）→ 在当前订单详情 H5 上展示好评（**不先**离开页面）；流程结束后 `pop` 并触发 `HQE_orderDetailDidCloseBlock`；星级与导航规则同 `13`（含 **13.2.1**）。
- **其它**：`getUserData` / `getMobileUserdata` / `getAppData` / `mobileUserdata`、`cameraPermission`、`loginOut` / `deleteAccount` 等同申请页。

## 14.5 订单详情专用：返回与列表刷新
- H5 在详情页点击返回（关闭详情）时向原生发送：**`orderGoBack`**。
- 原生行为：`pop` 回到上一级（一般为订单列表），并**刷新当前订单列表**（重新请求当前 Tab 对应的 `/app/v3/order/list`）。
- 注意：与申请页的 **`productGoBack`** 区分；若在订单详情 H5 中误发 `productGoBack`，原生在订单详情模式下宜与 `orderGoBack` 同等处理（可选兼容）。

## 14.6 H5 自测建议
- 仅带 `orderId`、带 `orderId+productId`、待提现带 `orderType` 三种 URL 均能正常拉单与展示。
- 抓取全链路、成功页 `successfulGoBack`、好评与低星感谢弹框与申请页一致。
- `orderGoBack` 返回后列表数据与后台一致（刷新生效）。
