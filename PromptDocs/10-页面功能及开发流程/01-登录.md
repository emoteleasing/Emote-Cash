# 01. 登录（OTP）

## 1.1 页面目标
- 通过手机号获取 OTP（一次性验证码），用户输入验证码完成登录/注册。
- 登录成功后关闭登录 Modal、刷新首页流水线并上传设备注册信息（根页面始终为首页，非强制登录）。
- 协议（Privacy Policy / Service Agreement）点击可打开统一 Web 展示页面。

## 1.2 页面开发流程（研发实现顺序）
1. 页面初始化：读取本地应用配置；无缓存则回源配置。
2. 用户输入手机号、点击“Get OTP”
3. 倒计时期间禁用 Get OTP；倒计时结束后允许再次获取
4. 用户输入 OTP、勾选协议，点击“Sign in”
5. 登录成功：
   - 保存会话（userId/token/isRegister）
   - 上传设备注册信息
   - 进入主 Tab（首页作为默认）

## 1.3 输入校验规则（验收要点）

> 手机号规则全文见 **`00-基础框架/25-印度手机号规则.md`**；实现类 `HQTIndianPhoneValidator`。

- **输入长度限制（输入框层，与校验一致）**：
  - 手机号：**仅数字**；首位为 **`6`–`9`（非 `0` 前缀）时最多 10 位**；**首位为 `0`（含 `06`–`09`）时最多 11 位**；尚未输入数字时按 11 位上限放行。粘贴时自动去掉非数字字符，输入框只显示数字。
  - OTP：**仅允许数字**，**最多 6 位**；达到 6 位后拒绝继续输入；禁止粘贴含字母或符号的内容。
- 手机号校验（印度本地规则）：
  - **10 位**：首位为 `6`、`7`、`8`、`9`
  - **11 位**：前两位为 `06`、`07`、`08`、`09`
  - 提交接口前规范化为 10 位（去掉 leading `0`）；`09876543210` 与 `9876543210` 等价
- OTP 校验：
  - 必须为 6 位数字
- 协议勾选：
  - **默认勾选**；用户可取消勾选；未勾选则阻断登录并提示用户（与产品区「默认勾选协议」策略一致）
- 提示与错误文案（与 Swift 登录页一致，英文）：
  | 场景 | 文案 |
  |------|------|
  | 手机号为空（无有效数字） | `Please enter mobile number` |
  | 手机号不符合印度规则 | `Please enter correct phone number` |
  | OTP 非 6 位纯数字 | `Please enter correct OTP` |
  | 未勾选协议 | `Please read and accept` |
  | 重复点击 Get OTP（请求进行中） | `Sending OTP... Please wait` |
  | 重复点击 Sign in（请求进行中） | `Signing in... Please wait` |
  | 发验证码成功（接口 `resultCode=200`） | `OTP has been sent`（非阻断 Toast；**不改变**既有倒计时与按钮文案逻辑，仅在成功后**追加**展示） |
  | 发验证码网络失败（无服务端文案时） | `Failed to send OTP, please try again` |
  | 登录网络失败（无服务端文案时） | `Login failed, please try again` |
  | 登录成功但本地会话保存失败 | `Login data save failed` |
  | 协议链接未就绪 | `Agreement link is not ready yet. Please wait for app config to load, then try again.` |
  | 加载中（HUD） | `Sending OTP...` / `Signing in...` |
  | 倒计时结束后按钮 | `Reacquire` |
- 接口返回业务错误时，若有 `resultMsg`（或项目约定的等价字段），优先展示服务端文案；网络层 `error.localizedDescription` 仅在无业务文案时作兜底。
- 发码成功：在**保持原有倒计时与 Get OTP 按钮状态机不变**的前提下，**额外**弹出非阻断 Toast，固定英文 **`OTP has been sent`**。
- 点击防连点：
  - Get OTP 与 Sign in 均需要节流/锁定，避免并发请求

## 1.4 网络接口与参数口径

### 获取 OTP：`/app/v3/sms/sendVerifySms`
- 请求：无 signed/unsigned 特殊约定时按项目通用公共参数 + data
- data 必填字段：
  - `mobile`：手机号（参与签名）
  - `verifyType`：验证码类型（项目约定为 1：登录/注册，参与签名；建议 `data` 内为字符串 `"1"` 与网关验签口径一致）
- 成功后：先按原逻辑启动倒计时并更新按钮文案；再展示 Toast **`OTP has been sent`**（仅追加提示，不修改倒计时实现）

### 登录/注册：`/app/v3/auth/registerOrLogin`
- 签名字段明细见 `00-基础框架/02-基础网络请求规范.md` §2.4.4。
- data 必填字段（**均参与签名**）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `mobile` | String | 手机号 |
| `verifyCode` | String | OTP |
| `longitude` | String | 不采定位时固定 **`-360`**（字面量，非 6 位小数） |
| `latitude` | String | 同上 **`-360`** |
| `imei` | String | 固定 **`"null"`** |
| `serialNo` | String | 与 `deviceId` 一致 |
- 关键响应字段：
  - `sponsor` 或 `userId`：用户标识
  - `spur` 或 `token`：会话令牌
  - `userSubmit`：是否已提交 KYC
  - `isRegister`：是否已注册

### 登录成功后设备注册：`/app/v3/mobile/registerDevice`
- data：设备信息字典（来自设备信息收集器）
- 成功/失败通常不阻断主流程；失败需按项目策略提示或降级

## 1.5 协议与埋点
- 协议 Web 链接（`/app/v3/app/config` → `data` 缓存）：
  - Privacy Policy：`policyHref`
  - Service Agreement：**`agreementHref`**（与「我的」页 Terms of the loan 的 `conditionsHref` 区分）
- 协议 Web 页（`HQITAgreementWebViewController`）导航与问题反馈页一致：隐藏系统导航栏 + `loan_bg` 头图 + `back_icon` 36×36 + 白字 Regular 14 标题。
- 协议点击埋点：
  - Privacy Policy：事件码 2
  - Service Agreement：事件码 3
- Get OTP 点击：事件码 4
- Sign in 点击：事件码 5

## 1.6 本地存储与退出
- 保存：`HQT_USER_SESSION` / `HQT_USER_ID` / `HQT_TOKEN` 等（见 `HQTStorageKeys`）
- 登出 / 注销成功 / Token 失效：清理会话 → 首页访客态 → **2 秒后**自动弹出登录页（`HQTAppShell.returnToGuestHomeThenShowLogin`）
