# 28. 印度市场原生产品下单完整流程

## 28.1 适用范围

本文档描述 **印度（DC）市场、原生产品下单页** 从首页点击产品到下单成功、数据抓取、成功页与好评引导的 **完整功能规格**。实现时须复用项目既有网络层、统一弹框、HUD、防连点、金额格式化等基础能力，**禁止平行重复造轮子**。

**包含范围：**

- 首页 → termV3 → 原生下单页（Loan confirmation）
- 定位权限获取与坐标解析
- 下单接口 `userSubmitV3`
- 通讯录权限、印度联系人清洗与分片上传
- 设备信息上传、`ready` 通知
- 抓取进度弹框
- 下单成功页（Loan details）
- 好评引导（Support us!）与感谢弹框
- 返回拦截与复借弹框

**不包含：** H5 产品申请容器、`positionPermission` / `uploadData` JS 桥接（见 `04-产品申请与下单H5-提示词-直接使用.md`）；订单详情待抓取、首页复借完整链路（见 `07-订单详情与待提现.md`、`08-复借流程.md`），但数据抓取与好评规则与本节一致。

**变体：首页自动下单 / 精准推荐** 不进本页；现行规格为 `dcRecommend` → 全部产品最大额+最高期 → `userSubmitDcUpgrade` → 抓取 → 精准推荐成功页，见 [`31-精准推荐与自动下单.md`](./31-精准推荐与自动下单.md)（首页入口摘要见 `02` §2.7）。定位/抓取/好评可与本节及 `05`/`13` 复用。

## 28.2 端到端流程总览

```
首页点击产品 Apply
    ↓
POST /app/v3/product/termV3（signed: productId）
    ↓
进入原生下单页，解析额度/期限/费用/银行卡
    ↓
用户选择额度、期限（如有），勾选协议，点击 Apply now
    ↓
校验协议勾选 → 解析定位坐标（见 §28.6）
    ↓
POST /app/v3/order/userSubmitV3 → 获得 orderId
    ↓
阶段 A：HUD Loading → POST /app/v3/mobile/device
    ↓
阶段 B：通讯录权限解析 → 抓取进度弹框 → contact 分片（可选）→ ready
    ↓
替换下单页为成功页（Loan details）
    ↓
用户点击 Feedback / Confirm / 返回
    ↓
按配置展示好评弹框（可选）→ 回首页并刷新
```

## 28.3 页面入口与 termV3

### 28.3.1 触发入口

- 首页产品列表项点击 **Apply**，经统一申请处理器进入流程。
- 若处于 **自动下单态**（`02-首页Loan.md` §2.7）：不进本页，改走自动下单协调器（固定列表第一项产品）。
- 入口须防连点（同一 `productId` 在 termV3 请求完成前不可重复触发）。

### 28.3.2 termV3 接口

- **端点：** `/app/v3/product/termV3`
- **signed：** `productId`
- **成功：** 将 `data` 传入原生下单页并渲染。
- **失败：** Toast 展示服务端文案，不进入下单页。

### 28.3.3 termV3 异常码分流

| 业务码 | 行为 |
|--------|------|
| 拒量相关（如 `6234303`） | 若配置了拒量 H5 则打开；否则展示处理中弹框 |
| 进行中订单相关 | 展示处理中弹框，Confirm 可跳转订单详情 |
| `6230002` / `6230003` | 弹框提示后跳转对应订单详情 |
| 其它失败 | 业务错误 Toast |

### 28.3.4 进入原生下单页

- 导航标题：**Loan confirmation**
- 隐藏底部 TabBar；展示原生导航返回按钮。
- 将 termV3 返回的完整 `data` 作为页面数据源（含 `amountDetailList`、`productName`、`productLogo`、银行卡信息等）。

### 28.3.5 页面构造入参

进入原生下单页时须传入以下参数（由申请处理器在 termV3 成功后组装）：

| 入参 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `productId` | String | 是 | 当前产品 ID，与 termV3 请求一致 |
| `termData` | `[String: Any]` | 是 | termV3 成功返回的完整 `data` 字典 |
| `prefillProductName` | String? | 否 | 首页产品名兜底；termData 无 `productName` 时使用 |
| `prefillProductLogoURL` | String? | 否 | 首页产品 Logo URL 兜底；termData 无 `productLogo` 时使用 |

页面初始化后调用 `applyTermPayload(termData)` 完成数据绑定；**不在此阶段**请求定位或下单。

### 28.3.6 termV3 接口参数与响应

#### 请求

| 类型 | 字段 | 说明 |
|------|------|------|
| signed | `productId` | 唯一签名字段 |
| unsigned | — | 通常为空 |

#### 响应根级字段（`data`）

| 逻辑字段 | 用途 | 展示/提交 |
|----------|------|-----------|
| `productName` | 产品名称 | 产品卡片标题；成功页产品名 |
| `productLogo` | 产品 Logo URL | 产品卡片、成功页 Logo |
| `amountDetailList` | 额度分档列表 | 额度区、明细联动数据源 |
| `bankCard` / `bankCardList` | 嵌套银行卡 | 见 §28.3.7；解析默认卡 |
| `lowestLoanInterestRate` 等 | 日利率等 | EMI 计算兜底 |
| `userType` | 用户类型 | 好评 `feedbackGuidance=2` 时判断是否首单（`2`=复借/老客） |

> 工程内解析器对 wire 混淆字段有兼容别名（如 `amountDetailList` / `lamp`），实现时以逻辑字段名为准，解码层统一映射。

#### 额度分档 `amountDetailList[]`

| 逻辑字段 | 别名/兼容 | 用途 |
|----------|-----------|------|
| `loanAmount` | `furnish`、`review` | 额度数值；**提交 `userSubmitV3.loanAmount` 取此原始字符串** |
| `termDetailList` | `mission` | 当前额度下的期限列表 |
| `feeAmount` | `impose`、`serviceFee` | 服务费 |
| `receiptAmount` | `mouse`、`arrivalAmount` | 到账金额 |
| `interestAmount` | `typist`、`interest` | 利息 |
| `taxAmount` | `lively`、`gst` | GST |
| `loanTime` | `borrowingDate`、`applyTime` | 申请日期 |
| `dueTime` | `repaymentDate`、`repayDate` | 到期日 |
| `lowestLoanInterestRate` | `clothes`、`dayRate` | 日利率（EMI 计算） |

**额度列表处理规则：**

- 按 `loanAmount` **从大到小**排序。
- **同一 `loanAmount` 去重**，只保留一档。
- `count > 1` → 多额度 Chip；`count == 1` → 单额度大字。
- 默认选中**最大额度**（排序后 index 0）；切换额度时 `selectedTermIndex` 重置为 0。

#### 期限分档 `termDetailList[]`（当前选中额度下）

| 逻辑字段 | 别名/兼容 | 用途 |
|----------|-----------|------|
| `showTerm` | `brick` | 期限展示文案；**提交 `userSubmitV3.showTerm` 取此值** |
| `loanTerm` | `productTerm`、`control` | 天数（EMI 期数推算） |
| `EMIs` / `EMITenure` | `emiCount` | EMI 期数（有则优先） |
| `EMIAmount` | `brother` | 每期 EMI 金额（有则优先） |
| `EMIRepayDate` | `firstEMIDate` | 首期还款日 |

**期限列表处理规则：**

- `termDetailList.count > 1` → 多期限，明细首行可点击弹出单选列表，标题「Select the loan term」。
- `count == 1` → 单期限，仅展示 `showTerm` 文案（自动补 `Days` 后缀规则见 §28.4.8）。
- 期限展示格式：若原文已含 `day` 则原样；若为纯数字则展示为 `{n} Days`。

### 28.3.7 termV3 银行卡字段

从 termV3 `data` **只读解析**默认银行卡（不额外请求银行卡列表接口）。查找顺序：

1. 根级 `bankCard` / `bankCardList` / `payAccountInfoList`
2. 各 `amountDetailList` 项内嵌套的上述字段
3. 根级直接含 `accountNo` 的扁平结构

单条银行卡解析字段：

| 逻辑字段 | 别名 | 用途 |
|----------|------|------|
| `recordId` | `bankCardBindId`、`bindId`、`id` | 提交 `bankCardBindId` |
| `accountNo` | `account_no` | 掩码展示 |
| `bankCode` | `ifsc`、`bank_code` | 内部存储 |
| `accountName` | `account_name`、`name` | 内部存储 |
| `bankName` | `bank_name` | 内部存储 |
| `defaultFlag` | `default_flag` | `"1"` 为默认卡 |

**展示规则：** 账号掩码格式 `1234 **** **** 5678`（取数字前 4 + 后 4）；无卡显示 `—`。银行卡条当前为**只读展示**，不可点击跳转换卡。

## 28.4 原生下单页 UI 与数据绑定

### 28.4.1 页面结构（自上而下）

1. **信用提示横幅**  
   - 固定文案：「Your credit status directly affects your loan limit, and a good credit history helps you secure better loan terms.」  
   - 样式：浅灰底 `#DCE4F1` 圆角卡片，13pt 灰色居中多行。

2. **产品卡片**  
   - 产品 Logo（36×36，圆角 8）、产品名称（15pt semibold）  
   - 额度区：单额度 28pt 粗体蓝色居中 / 多额度 3 列 Chip 网格（高 44，圆角 8）  
   - 多额度时展示提示：「Tips: Select loan amount first」

3. **EMI 卡片（有条件展示）**  
   见 §28.4.6；`emiInfo` 为空时整卡隐藏。

4. **银行卡条**  
   - 浅蓝底 `#C9DFFA`，高 68，圆角 16；左侧图标 `tmgsr_loan_bank` 40×40  
   - 右侧掩码账号；无卡显示 `—`

5. **费用明细卡片**  
   白底圆角 16；随当前选中额度、期限联动刷新（§28.4.3）。

6. **底部固定区**  
   - 协议勾选（默认已勾选，20×20 方框图标）  
   - 文案：「I have read and agreed with the **Terms Of The Loan**」（Terms 蓝色下划线可点）  
   - 协议 H5：配置键 `conditionsHref`，页标题「Terms Of The Loan」  
   - **Apply Now** 主按钮（项目统一主按钮高度与圆角）

### 28.4.2 额度与期限规则

- **多额度：** `amountDetailList.count > 1`；Chip 网格展示，按金额从大到小排序；切换额度时重置期限为该档第一项。
- **单额度：** 居中大字展示，前缀 **₹**，经印度千分位格式化。
- **多期限：** 明细首行「Select the loan term」展示当前期限，右侧箭头；点击弹出统一列表单选弹框。
- **单期限：** 仅展示期限文案，不可切换。

### 28.4.3 明细区字段（与选中额度+期限绑定）

明细由 `detailSnapshot(amountDetail, termDetail, rootData)` 统一计算，字段在多数据源间按优先级查找：`termDetail` → `amountDetail` → `rootData`。

| UI 标题 | 逻辑字段（查找键，逗号分隔） | 展示格式 | 交互 |
|---------|---------------------------|----------|------|
| Select the loan term | `showTerm` / `brick` | `{n} Days` 或原文 | 多期限时右侧箭头 `tmgsr_kyc_xl`，点击弹单选 |
| Amount received | `receiptAmount`、`mouse`、`arrivalAmount` | ₹ 千分位 | ℹ️ `tmgsr_loan_sm` |
| Service fee | `feeAmount`、`impose`、`serviceFee` | ₹ 千分位 | ℹ️ |
| Interest | `interestAmount`、`typist`、`interest` | ₹ 千分位 | ℹ️ |
| GST | `taxAmount`、`lively`、`gst` | ₹ 千分位 | — |
| Date of application | `loanTime`、`borrowingDate`、`applyTime` | `MMM dd, yyyy` | — |
| Due date | `dueTime`、`repaymentDate`、`repayDate` | `MMM dd, yyyy` | 非 EMI 场景展示 |

**到账金额兜底：** 若 `receiptAmount` 缺失，且能解析 `loanAmount` 与 `feeAmount`，则展示 `loanAmount - feeAmount`（格式化后）；否则 `—`。

**EMI 场景：** 明细区**不展示** Due date；EMI 信息在 EMI 卡片展示（§28.4.6）。

**金额展示：** 页面所有金额须 `HQTAmountFormatter` 格式化，货币符号 **₹**，印度千分位；**提交接口仍用原始数字字符串，不带 ₹ 与逗号**。

### 28.4.4 费用说明浮层（ℹ️）

三行固定英文说明（与订单详情一致）：

- **Amount received：** The actual amount you receive is calculated by deducting the service fee from the loan amount.
- **Service fee：** Service fee covers the administrative costs of processing your loan application.
- **Interest：** Interest is the cost of borrowing money, calculated based on the loan amount and term.

点击 ℹ️ 以 Toast 展示对应文案。

### 28.4.5 银行卡

- 初始化时从 termV3 `data` 解析默认银行卡（§28.3.7）：`recordId` → `bankCardBindId`，掩码账号上屏。
- 提交时若 `bankCardBindId` 非空，写入 `userSubmitV3` unsigned；为空则不传该字段。
- 当前实现为只读展示，**不阻断**无卡提交（以 termV3 实际业务为准）。

### 28.4.6 EMI 卡片字段与展示

**展示条件：** `emiInfo` 解析成功（`emis > 0`）。

| UI 区域 | 内容 | 数据来源 |
|---------|------|----------|
| 标题行按钮 | `{n} EMIs` + 箭头 `tmgsr_emi_xl` | `emis`；点击 Toast 摘要 |
| 1st EMI Date | 首期还款日 | `EMIRepayDate` / `firstEMIDate`；缺失则申请日 +30 天 |
| EMI Amount | 每期金额 | `EMIAmount`；缺失则按额度、日利率、期数公式估算 |

- 内嵌浅灰面板 `#F2F5F9`，两行各高 44。
- EMI Amount 展示**不带 ₹ 前缀**的千分位数字（与下单页 EMI 行一致）；成功页 EMI Amount **带 ₹**。

### 28.4.7 日期与期限格式化

- **日期展示：** 支持毫秒时间戳、秒级时间戳、`yyyy-MM-dd`、`MMM dd, yyyy` 输入；统一输出 **`MMM dd, yyyy`**（如 `Jun 24, 2026`）。
- **期限展示：** `showTerm` 含 `day` 不追加后缀；纯数字追加 ` Days`。
- **期限单选弹框：** 标题「Select the loan term」；选项文案与明细区 `showTerm` 一致；确认后刷新明细与 EMI 卡片。

## 28.5 提交前校验与防连点

### 28.5.1 点击 Apply now 时顺序

1. 若正在提交中 → 忽略。
2. 协议未勾选 → Toast：「Please agree to the Terms Of The Loan before applying.」，阻断。
3. 获取提交防连点锁。
4. 禁用 Apply 按钮（半透明），进入定位流程（**此阶段不展示 HUD**，HUD 在定位完成、真正发起下单时展示）。
5. 定位结果返回后：取消则解锁并恢复按钮；有坐标则进入 `submitOrder`。

### 28.5.2 防连点要求

- Apply 按钮、termV3 入口、成功页 Feedback/Confirm 均须防连点。
- 仅失败/取消分支恢复按钮；成功路径由成功页或抓取流程接管。

## 28.6 定位权限（原生下单）

配置字段：`/app/v3/app/config` → `retrieveMobileContact`（与通讯录强抓共用）

- **1：** 强抓定位  
- **0 / 2：** 非强抓定位  

### 28.6.1 强抓模式（retrieveMobileContact = 1）

| 权限状态 | 行为 |
|----------|------|
| 已授权 | 获取真实经纬度（6 位小数）后提交 |
| 未决定 | 弹出系统定位授权；用户选择后见下表 |
| 系统授权后拒绝 / 受限 | 若属**本次首次系统弹窗结果**：结束定位流程，**不提交订单**，恢复按钮 |
| 此前已拒绝 / 受限 | 展示**居中二次引导弹框**（见 §28.16.2）；Cancel 或 Confirm（去设置）均结束定位、不提交 |
| 已授权但拿不到坐标（超时约 4s / GPS 失败） | 视同强抓无法定位，结束流程，不提交 |

**强抓核心：** 无真实坐标则**不调用** `userSubmitV3`。

### 28.6.2 非强抓模式（retrieveMobileContact ≠ 1）

| 权限状态 | 行为 |
|----------|------|
| 已授权 | 真实坐标提交 |
| 未决定 → 用户拒绝 | 使用降级坐标 **-360 / -360** 继续提交 |
| 此前已拒绝 / 受限 | 直接使用 **-360 / -360** 提交，**不展示**定位二次弹框 |
| 已授权但拿不到坐标 | 降级 **-360 / -360** 继续提交 |

### 28.6.3 坐标提交格式

- 签名字段 `longitude`、`latitude` 为 **6 位小数字符串**（如 `-360.000000`）。
- `imei` 固定 `"null"`；`serialNo` 与设备 `deviceId` 一致。

### 28.6.4 与 H5 的差异说明

原生下单**不回传** H5 `positionPermission`；坐标直接用于 `userSubmitV3`。H5 空串 `""` 等口径仅适用于 H5 容器，见 `04-产品申请与下单.md` §4.4.6。

## 28.7 下单接口 userSubmitV3

### 28.7.1 请求

- **端点：** `/app/v3/order/userSubmitV3`
- **签名：** 方式四（项目统一签名助手）

**signed（参与签名）：**

| 字段 | 取值来源 | 说明 |
|------|----------|------|
| `productId` | 页面入参 | 当前产品 ID |
| `loanAmount` | 当前 `amountDetail.loanAmount`（兼容别名） | **原始数字字符串**，不含 ₹/逗号 |
| `longitude` | 定位桥输出 | 6 位小数字符串，如 `77.123456` |
| `latitude` | 定位桥输出 | 6 位小数字符串；非强抓降级 `-360.000000` |
| `imei` | 固定值 | `"null"` |
| `serialNo` | 设备 ID | 与 `deviceId` 一致 |

**unsigned（不参与签名）：**

| 字段 | 取值来源 | 说明 |
|------|----------|------|
| `showTerm` | 当前 `termDetail.showTerm`（兼容 `brick`） | 用户选中的期限展示值 |
| `bankCardBindId` | termV3 解析的 `recordId` | 有默认卡时传入 |
| `orderType` | — | **普通下单不传**；复借传 `"1"` |

### 28.7.1.1 响应

| 字段 | 兼容键 | 说明 |
|------|--------|------|
| `orderId` | `orderNo`、`objection`、`substantial` | 下单成功后的订单号；**为空则视为失败** |
| `resultCode` / `resultMsg` | — | 非成功时 Toast 展示 `resultMsg` |

成功拿到 `orderId` 后立即进入 §28.8 数据抓取，不再恢复 Apply 按钮可点状态。

### 28.7.2 请求过程 UI

- 定位完成后展示 HUD：「Processing...」
- 成功：取 `data.orderId`，为空则 Toast 失败并恢复按钮。
- 失败：网络/业务 Toast，恢复按钮与防连点锁。

### 28.7.3 成功后

- 立即进入数据抓取协调器（§28.8），**不**停留在可再次点击 Apply 的状态。

## 28.8 数据抓取协调器

下单成功后由统一协调器执行，宿主为下单页，`overlayHostView` 为当前 `keyWindow`（或页面 window），以保证弹框覆盖全屏含 TabBar。

### 28.8.1 阶段 A — 设备信息（无抓取进度弹框）

1. 展示 HUD Loading。
2. `POST /app/v3/mobile/device`  
   - signed：`orderId`  
   - unsigned：设备信息采集器输出的设备大字段（禁止包含规范禁止字段）
3. 成功 → 关闭 HUD，进入阶段 B。  
4. 失败 → Toast，抓取 `completion(false)`，恢复 Apply 按钮。

### 28.8.2 阶段 B — 通讯录权限

在展示抓取进度弹框**之前**先决权限：

| 系统通讯录状态 | 行为 |
|----------------|------|
| `authorized` | 进入抓取流水线，allowContact = `""` |
| `notDetermined` | 系统通讯录弹窗；弹窗后**必须再次读取** `authorizationStatus`（不可仅信 `granted` 回调） |
| `limited` / `denied` / `restricted` | 走「未完全授权」分支 |

**iOS 18+ Limited（部分授权）：** 与 denied 同等处理，**不可**读取通讯录。

#### 强抓通讯录（retrieveMobileContact = 1）

| 场景 | 行为 |
|------|------|
| 系统弹窗**首次**拒绝或 Limited | **不展示**自定义二次弹框；Toast「Contacts permission is required.」；抓取失败；写入「已走过系统通讯录弹窗」标记 |
| 非首次且仍为 denied/limited/restricted | 展示居中通讯录二次引导弹框（§28.16.3）；用户 Cancel 或 Confirm（去设置）均抓取失败；**产品下单页**额外 `pop` 回上一页 |
| 授权成功 | 进入抓取流水线 |

#### 非强抓通讯录（retrieveMobileContact ≠ 1）

| 场景 | 行为 |
|------|------|
| 拒绝 / Limited / 首次系统拒绝 | 跳过 contact 上传，直接 `ready`，`allowContact = "2"` |
| 授权成功 | 读取联系人 → 有有效数据则分片上传 → `ready`，allowContact = `""` |

### 28.8.3 抓取进度弹框阶段

权限已决且需继续时：

1. 展示 **抓取进度弹框**（§28.10），叠在 keyWindow。
2. 后台读取通讯录并清洗（§28.9）。
3. **有效联系人为 0：** 跳过 `mobile/contact`，直接 `ready`（allowContact 按 §28.8.2）。
4. **有有效联系人：** 按 `pushPerCount` 分片**顺序**调用 `POST /app/v3/mobile/contact`，全部成功后再 `ready`。
5. `POST /app/v3/order/ready`  
   - signed：`orderId`  
   - unsigned：`allowContact`（`""` = 已授权上传；`"2"` = 未授权含 Limited）
6. ready 成功 → 关闭进度弹框 → `completion(true)`。  
7. 任一步失败 → 关闭进度弹框 → Toast → `completion(false)` → 恢复 Apply（仍在下单页）。

### 28.8.4 allowContact 口径

| 值 | 含义 |
|----|------|
| `""` | 通讯录已完全授权且按授权态上传 |
| `"2"` | 未授权（含拒绝、受限、Limited）；不上传通讯录 |

**禁止**使用 `"3"` 表示部分授权。

## 28.9 印度通讯录清洗规则

### 28.9.1 读取与拆分

- 仅 `CNAuthorizationStatus.authorized` 时可枚举联系人。
- 姓名字段格式：**`familyName + " " + givenName`**，去首尾空格；**姓名为空则跳过该联系人**。
- 一个联系人多个号码 → 拆成多条记录。

### 28.9.2 印度手机号校验与规范化

校验正则口径（与 `DeviceTool` 印度规则对齐）：

`^(910[6-9]\d{9}|91[6-9]\d{9}|0[6-9]\d{9}|[6-9]\d{9})$`

规范化结果：**10 位本地号**

| 原始位数 | 处理 |
|----------|------|
| 13 位且 `910` 开头 | 去掉前 3 位 |
| 12 位且 `91` 开头 | 去掉前 2 位 |
| 11 位且 `0` 开头 | 去掉首位 `0` |
| 10 位且首位 6–9 | 原样 |

无效号、空号过滤；按规范化号码**去重**。

### 28.9.3 上传条数字段

每条 `list` 元素（均为字符串）：

| 字段 | 规则 |
|------|------|
| `contactName` | 清洗后姓名 |
| `contactPhone` | 10 位印度本地号 |
| `contactUpdateTime` | 毫秒时间戳字符串（无真实来源用当前时间） |
| `contactStorage` | iOS 统一 `"0"` |
| `contactCount` | 取不到 `"-99"` |
| `contactTime` | 取不到 `""` |

### 28.9.4 条数上限与分片

- `pushMaxCount`：最多读取/上传条数（配置默认 500）
- `pushPerCount`：每片条数（配置默认 50）
- 超过上限按顺序截断后再分片

## 28.12 好评引导流程

### 28.12.1 配置

- 配置字段：`feedbackGuidance` / `feedback_guidance`
- `0`：不展示
- `1`：满足条件时总是展示
- `2`：仅非首单展示（term 数据中 `userType == 2` 视为复借/非首单）

### 28.12.2 安装周期频控

- `UserDefaults` 标记：好评弹框**出现过一次**（无论提交、取消、关星），至卸载重装前不再展示。
- 展示前写入标记（打开弹框时即写入）。

### 28.12.3 触发时机

| 按钮 | 行为 |
|------|------|
| **Feedback** | **强制**进入好评流程（忽略 feedbackGuidance 模式），完成后执行完成流程 |
| **Confirm** | 按 `feedbackGuidance` 判断是否展示；不展示则直接完成流程 |

### 28.12.4 好评弹框 UI（居中叠层，非 push 页面）

- 叠在 `keyWindow` 上，不先离开成功页。
- 左上蓝色装饰点；标题 **Support us!**；水印 `tmgrs_tk_hpyd`。
- 五星：**默认均未选中**；图标 `tmgrs_tk_hpyd_n` / `tmgrs_tk_hpyd_u`；25×25，间距 11，**左对齐**。
- 说明文案左对齐（默认英文长文案）。
- 底部 **Cancel** + **Submit** 等宽按钮。
- 未选星点 Submit：Toast 配置键 **q9**（默认「Please select a rating before clicking Confirm」），弹框不关闭。
- Submit 防连点。

### 28.12.5 星级提交逻辑

| 星级 | 行为 |
|------|------|
| ≥ 4 | 调起系统 App Store 评分（`SKStoreReviewController`），关闭好评弹框，执行完成流程 |
| < 4 | 展示感谢弹框 |

### 28.12.6 感谢弹框

- 标题 **Thanks**；水印 `tmgrs_tk_hpyd_df`；主按钮 **Confirm**。
- Confirm 后关闭感谢弹框，执行完成流程。

### 28.12.7 不展示好评时

- 直接执行完成流程（回首页或回订单详情）。

## 28.13 返回与复借拦截

### 28.13.1 下单页点击返回

1. 若 `fjtip` 开关关闭 → 展示离开确认弹框（§28.16.4）。
2. 若开启 → 请求 `/app/v3/product/state`（unsigned: `productId`）。
   - 解析到 `userType == 2` 复借产品 → 展示复借弹框；关闭复借弹框则 `pop` 上一页。
   - 无复借 / 接口失败 → 展示离开确认弹框。

### 28.13.2 离开确认弹框

- 居中统一弹框，KYC 返回样式；文案挽留用户。
- Confirm → `popToRoot` 回首页。

### 28.13.3 离开下单页时

- 若 `pop` 离栈，发送首页刷新通知（与 Tab 切换刷新口径一致）。

## 28.16 统一弹框规范摘要

### 28.16.1 权限二次弹框通用

- 居中白卡片；左上蓝点；标题为权限类型；左对齐正文；右侧水印；Cancel + Confirm；不可点背景关闭。

### 28.16.2 定位二次弹框

- 标题：**Location**；水印 `tmgrs_tk_dw`；Confirm 跳转系统设置；Cancel / Confirm 均结束本次定位且不提交。

### 28.16.3 通讯录二次弹框

- 标题：**Contacts**；水印 `tmgrs_tk_dtx`；Confirm 跳转系统设置。
- 产品下单页：Cancel 或 Confirm 后抓取失败并 **pop 一层**（回首页前一层，非 popToRoot）。

### 28.16.4 离开确认 / 期限选择 / 好评 / 感谢

- 离开确认：复用 KYC 退出确认样式。
- 多期限：统一列表单选弹框。
- 好评 / 感谢：见 §28.12.4–28.12.6。

## 28.17 异常与错误处理

| 场景 | 用户可见结果 | 页面状态 |
|------|-------------|----------|

| 协议未勾选 | Toast | 停留下单页 |
