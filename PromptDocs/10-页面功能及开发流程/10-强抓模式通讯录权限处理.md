# 强抓模式通讯录权限处理

## 功能概述

在产品下单页面，当配置为**强抓模式**（`retrieveMobileContact = 1`）时，如果用户拒绝授予通讯录权限，系统将自动返回上一页面，不继续后续的下单流程。

## 业务规则

### 强抓模式（retrieveMobileContact = 1）

用户**必须**授予通讯录**完全授权**（`CNAuthorizationStatus.authorized`）才能完成抓取：

1. **首次系统弹窗点拒绝（Denied）**
   - **不**展示自定义通讯录弹框
   - Toast，中断抓取、**留当前页**（写入 `contactsSystemPromptedKey`）
   - 产品申请 / 订单详情 H5：`uploadDataFail`；首页复借：`completion(false)`

2. **Limited（部分授权，含系统弹窗结果）/ 已 Denied / Restricted（再次进入）**
   - **才**显示自定义通讯录引导
   - 去设置 / 关闭：强抓中断抓取（非根页可 pop）；非强抓降级 `ready` + `allowContact=2`

3. **其他错误情况**
   - 显示错误提示（Toast）
   - 1.5秒后自动返回上一页面

### 非强抓模式（retrieveMobileContact = 0 或其他值）

用户可以选择不授予通讯录权限，仍可继续下单：

1. **已拒绝权限**
   - 显示二次引导弹框
   - 用户可以选择去设置开启或取消
   - 不返回上一页面，继续下单流程

2. **其他错误**
   - 显示错误提示
   - 不返回上一页面

## iOS 18+ Limited（部分授权）

| 项 | 说明 |
|----|------|
| 系统表现 | 用户选「选择联系人」等，`authorizationStatus == .limited` |
| 与完全授权区别 | **不能**枚举全量通讯录；`buildContactRows` 返回空 |
| `requestAccess` 陷阱 | 回调 `granted` 可能为 `true`，必须以弹窗后的 `authorizationStatus` 为准 |
| allowContact | 固定 `"2"`（与拒绝相同） |
| 实现 | `HQTOrderDataCaptureCoordinator.handleContactsNotFullyAuthorized`；`HQTContactsScrapeBuilder.isContactAccessGranted` |

详见：`05-数据抓取与通讯录分片.md` §5.3（iOS 18+ 表）、`22-通讯录接口空数据优化.md` 场景 1b。

## H5 产品申请 / 订单详情 / 首页复借（`HQTOrderDataCaptureCoordinator`，PHI352-DC）

强抓且系统通讯录弹窗已走过、权限仍为 **denied / restricted / limited** 时，展示 **通讯录二次引导**（`HQTPermissionSecondaryDialog.makeContacts`）。

| 页面 | 去设置 | 关闭 | 导航 |
|------|--------|------|------|
| 产品申请 H5 | `uploadDataFail()` → JS 完成后 **pop 一层** | 同上 | 不回首页 |
| 订单详情 H5 | `uploadDataFail()` | 同上 | **不** pop，留详情 H5 |
| 首页复借 | 抓取 `completion(false)` + Toast | 同上 | **不** pop；`resetActiveReloanApplyInteraction` 恢复 Apply |

- H5：`failOnContactsSecondaryInteraction: true`；申请页另设 `onContactsSecondaryDismiss` 标记 pop。
- 复借：协调器默认 `false`（无 `uploadDataFail`）。
- 详见：`05-数据抓取与通讯录分片.md` §5.4.1、`08-复借流程.md` §8.11。

## 实现位置（PHI352-DC）

### 文件：`HQTOrderDataCaptureCoordinator.swift`

通讯录权限在 `resolveContactsThenScrape` 中处理；抓取入口为 `start(orderId:host:overlayHostView:...)`。

```swift
// 仅 .authorized 进入 runContactsPipeline(allowContact: "")
case .authorized:
    runContactsPipeline(...)
case .notDetermined:
    store.requestAccess { _, _ in
        let statusAfter = CNContactStore.authorizationStatus(for: .contacts)
        if HQTContactsScrapeBuilder.isContactAccessGranted(statusAfter) {
            runContactsPipeline(...)
        } else {
            handleContactsNotFullyAuthorized(...) // 含 Limited
        }
    }
case .limited, .denied, .restricted:
    handleContactsNotFullyAuthorized(...)
```

## 实现位置（原生 TermV3 申请页，历史参考）

### 文件：`HQTeConsmpton/Home/HQTProductApplyViewController.swift`

在 `sendUserSubmitV3` 方法中，订单提交成功后处理通讯录权限：

```swift
// 订单提交成功后
if env.isSuccess, let oid = HQTTermV3JSON.string(env.dataObject?["orderId"] ?? env.dataObject?["order_id"]) {
    let isFirst = HQTTermV3JSON.bool(env.dataObject?["isFirst"] ?? env.dataObject?["is_first"]) ?? true
    let retrieveMode = HQTOrderDataScrapeCoordinator.currentRetrieveMobileContactMode()
    
    // 在后台线程请求通讯录权限
    DispatchQueue.global(qos: .userInitiated).async { [weak self] in
        let perm = HQTOrderDataScrapeCoordinator.runContactsPermissionPhase(retrieveMode: retrieveMode)
        
        switch perm {
        case let .failure(err):
            // 权限被拒绝，根据强抓模式决定是否返回
            if retrieveMode == 1 {
                // 强抓模式：返回上一页面
                self?.navigationController?.popViewController(animated: true)
            } else {
                // 非强抓模式：显示提示但继续
                HQTDialog.showPermissionSecondaryAlert(on: self, kind: .contacts)
            }
            
        case .success:
            // 权限已授予，继续数据抓取流程
            // ...
        }
    }
}
```

## 错误码说明

### `HQTOrderDataScrapeCoordinator` 定义的错误码：

- **`permissionErrorCodeDeniedNow = 1402`**
  - 用户刚刚拒绝了系统权限弹框
  - 强抓模式下：直接返回上一页面

- **`permissionErrorCodeNeedSecondaryPrompt = 1403`**
  - 用户之前已拒绝，需要去设置中开启
  - 强抓模式下：显示二次引导弹框，然后返回上一页面
  - 非强抓模式下：显示二次引导弹框，但不返回

## 配置说明

### `retrieveMobileContact` 配置

配置位置：`appConfig` 或 `categoryConfig` 中

- **值为 `1`**：强抓模式，必须授予通讯录权限
- **值为 `0` 或其他**：非强抓模式，可选授予通讯录权限

### 读取配置的方法

```swift
// 在 HQTOrderDataScrapeCoordinator 中
static func currentRetrieveMobileContactMode() -> Int {
    HQTOrderScrapeConfig.retrieveMobileContactMode()
}

// 在 HQTOrderScrapeConfig 中
static func retrieveMobileContactMode() -> Int {
    guard let root = HQTAppConfigStore.shared.appConfigJSON else { return 0 }
    if let v = intAny(root["retrieveMobileContact"]) { return v }
    if let data = root["data"] as? [String: Any], 
       let v = intAny(data["retrieveMobileContact"]) { return v }
    return 0
}
```

## 测试场景

### 测试场景 1：强抓模式 + 首次拒绝

1. 配置 `retrieveMobileContact = 1`
2. 用户首次使用，未授予通讯录权限
3. 点击"Apply now"提交订单
4. 系统弹出通讯录权限请求
5. 用户点击"不允许"
6. **预期结果**：直接返回上一页面，不显示任何弹框

### 测试场景 2：强抓模式 + 已拒绝权限

1. 配置 `retrieveMobileContact = 1`
2. 用户之前已拒绝通讯录权限
3. 点击"Apply now"提交订单
4. 系统检测到权限已被拒绝
5. 显示二次引导弹框
6. 用户点击"取消"或"确认"
7. **预期结果**：返回上一页面

### 测试场景 3：非强抓模式 + 拒绝权限

1. 配置 `retrieveMobileContact = 0`
2. 用户拒绝通讯录权限
3. 点击"Apply now"提交订单
4. 显示二次引导弹框
5. 用户点击"取消"
6. **预期结果**：不返回上一页面，继续完成下单流程

### 测试场景 4：强抓模式 + 授予权限

1. 配置 `retrieveMobileContact = 1`
2. 用户授予通讯录权限
3. 点击"Apply now"提交订单
4. **预期结果**：正常进入数据抓取流程，显示成功弹框

### 测试场景 5：强抓模式 + iOS 18+ Limited（部分授权）

1. 配置 `retrieveMobileContact = 1`
2. 系统通讯录弹窗选择「选择联系人」/ Limited
3. **预期结果**：不上传 contact；`ready` 的 `allowContact=2`（非强抓）或强抓首次 Toast 中断（非 `allowContact=""`）
4. 再次进入抓取且仍为 Limited：展示通讯录二次引导（H5 则 `uploadDataFail`）

## 注意事项

1. **订单已创建**：即使用户拒绝通讯录权限并返回上一页面，订单已经在服务器端创建成功
2. **用户可重试**：用户可以在订单列表中查看已创建的订单
3. **权限状态持久化**：用户的权限选择会被系统记住，下次进入时不会再次弹出系统权限请求
4. **二次引导的重要性**：对于已拒绝权限的用户，二次引导弹框提供了去设置开启权限的入口
