# 04. 产品申请与下单（TermV3 -> UserSubmitV3）

## 4.1 页面目标
- 展示产品额度与期限，支持选择申请金额与期限。
- 展示费用说明（Amount received / Service fee / Interest）与借款时间、到期时间。
- 展示银行卡选择区域，并支持更换默认卡。
- 底部协议与提交按钮，提交后进入“数据抓取/抓取链路”。

## 4.1.1 页面展示字段（补充）
- 产品信息区：
  - `productLogo`：产品图
  - `productName`：产品名
  - 金额主展示：可取当前选中额度，产品区可强调最高额度（经 **`HQTAmountFormatter`** 千分位，见 §00.7.1）
- 期限区：
  - 取当前金额档的 `termDetailList`，支持单期限/多期限交互
- 明细区（与当前选中额度 + 期限绑定）：
  - Loan term：`showTerm`
  - Amount received：`receiptAmount`（缺失可兜底）
  - Service fee：`feeAmount`
  - Interest：`taxAmount`（或接口映射字段）
  - Loan time：`loanTime`
  - Due time：`dueTime`
- 还款计划区：
  - `productTermItemList`（或等价字段）
  - 计划提示文案（`repaymentPlanTip/repayHint` 等）

## 4.2 进入页面初始化
1. 调 `/app/v3/product/termV3`
2. 将接口返回解析为：
   - 多额度或单额度（根据 amountDetailList 数量）
   - 多期限或单期限（根据 termDetailList 数量）
   - 费用与还款计划字段用于渲染明细
3. 同步用户名字字段（用于表单名字控件，如有）
4. 获取银行卡列表或进入相应银行卡模块（按当前选择和回显策略）

## 4.3 TermV3 接口
- 端点：`/app/v3/product/termV3`
- 请求参数：
  - `productId`（参与签名）
- 关键响应字段（用于 UI）：
  - 金额分档列表：`amountDetailList`
  - 每个金额分档的期限列表：`termDetailList`
  - 每个金额/期限下的费用字段：
    - `feeAmount`（服务费/砍头）
    - `taxAmount`（利息/税费，对应 UI 文案 Interest）
    - `receiptAmount`（到账金额，如缺失则按约定公式兜底）
  - 借款与到期字段：
    - `loanTime` / `dueTime` / 等价字段
    - `showTerm`（用于 Loan Term 展示与提交 showTerm 值）
  - 还款计划：
    - `productTermItemList` 等（用于还款计划渲染）

### 4.3.2 单/多额度与单/多期限判断逻辑
- `amountDetailList.count > 1`：多额度模式（切换额度时刷新期限、明细、还款计划）
- `amountDetailList.count == 1`：单额度模式
- 当前额度下：
  - `termDetailList.count > 1`：多期限模式
  - `termDetailList.count == 1`：单期限模式

### 4.3.3 金额展示与 +/- 按钮规则（补充）
- **千分位**：页面上所有金额文案（额度档位、到账金额、还款金额等）须经 **`HQTAmountFormatter`** 格式化后展示（`,` 分组 + `₱` 前缀），规范见 `00-项目基础规范.md` §00.7.1；提交接口仍用原始数值。
- 多额度模式下，金额档位需按金额值**从大到小**排序后展示（默认选中最大金额）。
- 当当前为**最大金额**时，隐藏右侧 `+` 按钮。
- 当当前为**最小金额**时，隐藏左侧 `-` 按钮。
- 金额切换使用边界阻断，不循环回绕（到达边界后继续点击无效果）。

## 4.3.1 产品入口异常码处理
- 当 TermV3 返回业务错误码 `6230002` 或 `6230003`：
  - 展示错误弹框或提示（内容使用服务端 message）
  - 用户确认后跳转订单详情页（orderId/入口策略按项目约定）

## 4.4 定位权限处理

### 4.4.1 定位权限触发时机

定位权限在用户点击"Apply now"按钮时才请求，不在页面加载时请求。

**关键标志位**：
- `isWaitingForLocationToSubmit`：标记是否正在等待定位以提交订单
- `isLocationDataSent`：防止重复发送位置数据
- `isFirstTimeLocationRequest`：区分首次和非首次请求
- `isLocationAlertShowing`：防止重复显示弹框

### 4.4.2 强抓模式与非强抓模式

#### 强抓模式（retrieveMobileContact = 1）

| 权限状态 | 行为 | 说明 |
|---------|------|------|
| **已授权** | 获取真实坐标 | 正常流程 |
| **未决定** | 请求权限 → 授权/拒绝 | 显示系统弹框 |
| **首次拒绝** | 回传 H5 **字面量** `""`（`positionPermission("")`） | 不显示 b3；**禁止** `{"longitude":"","latitude":""}` |
| **已拒绝 + 取消** | 回传 `""`，停留当前页面 | b3 二次弹框 Cancel |
| **已拒绝 + 去设置** | 回传 `""`，停留当前页面 | b3 Go to Settings |
| **拿不到真实坐标** | 回传 `""` | 定位失败、超时等 |

#### 非强抓模式（retrieveMobileContact = 0）

| 权限状态 | 行为 | 说明 |
|---------|------|------|
| **已授权** | 获取真实坐标 | 正常流程 |
| **未决定** | 请求权限 → 授权/拒绝 | 显示系统弹框 |
| **首次拒绝** | 回传 H5 **字面量** `""`（与强抓一致） | 不显示 b3；**禁止**空对象 JSON |
| **已拒绝（非首次）** | `{"longitude":"-360","latitude":"-360"}` | **不显示** b3，降级继续 |

**核心差异**（已更新）：
- 强抓模式：必须获取真实坐标，拒绝则停留当前页面，允许用户重新尝试
- 非强抓模式：尽量获取真实坐标，拒绝则使用默认坐标继续

### 4.4.3 定位权限流程

```
用户点击 Apply now
    ↓
检查定位权限
    ↓
┌─────────────────────────────────────┐
│ 权限状态？                           │
└─────────────────────────────────────┘
    ↓           ↓           ↓
  已授权      未决定      已拒绝
    ↓           ↓           ↓
  获取位置   请求权限   处理拒绝
    ↓           ↓           ↓
  提交订单   等待回调   强抓/非强抓
                ↓           ↓
            授权/拒绝   返回/继续
```

### 4.4.4 二次弹框引导（已更新）

当用户已拒绝定位权限时，显示二次引导弹框：
- **标题**："Location Permission Required"
- **消息**："Please allow location access in Settings to complete the loan application."
- **按钮**：
  - "Cancel"：**停留在当前页面**，用户可重新尝试
  - "Go to Settings"：跳转系统设置

**所有场景的行为**：
- 首次系统弹框拒绝 → 回传 **`""` 字面量**，不展示 b3；下次再调 `positionPermission`
- 二次弹框（仅强抓）Cancel / Go to Settings → 均回传 **`""`**，停留当前 H5 页
- 用户可以重新点击 "Apply now"
- 避免用户重新导航和重新选择

### 4.4.6 `positionPermission` 回传 payload 汇总（iOS ↔ H5）

| 场景 | payload 示例 | 类型 |
|------|----------------|------|
| 有真实坐标 | `{"longitude":"121.5","latitude":"14.6"}` | JSON 对象 |
| 非强抓、非首次、无权限 | `{"longitude":"-360","latitude":"-360"}` | JSON 对象 |
| 首次系统拒绝 / 强抓无法定位 / b3 取消或去设置 | `""` | **字符串字面量** |

**禁止**：用 `{"longitude":"","latitude":""}` 表示“无定位”。  
**实现**：`HQTProductApplyLocationBridge`。

详细说明见：`25-下单页定位权限拒绝不返回.md`

### 4.4.5 防止自动提交

**问题**：设置定位管理器代理后，iOS 系统会自动触发授权变化回调，可能导致页面加载时自动提交订单。

**解决方案**：
- 使用 `isWaitingForLocationToSubmit` 标志位
- 只有用户点击"Apply now"按钮后才设置为 `true`
- 页面加载时的授权变化不会触发订单提交

## 4.5 下单提交入口

### 4.4.1 下单接口：`/app/v3/order/userSubmitV3`
- 端点：`/app/v3/order/userSubmitV3`
- 签名算法：方式四（`HQTSigningHelper`）；**签名字段明细见** `00-基础框架/02-基础网络请求规范.md` §2.4.4。
- **signed（参与签名，共 6 个）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `productId` | String | 产品 ID |
| `loanAmount` | String | 选中额度字符串 |
| `longitude` | String | **6 位小数字符串**（`%.6f`）；强抓真实值，非强抓 `-360.000000` |
| `latitude` | String | 同上 |
| `imei` | String | 固定 **`"null"`** |
| `serialNo` | String | 与 `deviceId` 一致 |

- **unsigned（不参与签名）**：

| 字段 | 说明 |
|------|------|
| `showTerm` | 当前期限（从 term 解析） |
| `orderType` | **仅复借**传 `"1"`；普通 H5 下单不传 |
| `bankCardBindId` | 可选 |

- 原生实现：`HQTAPIFieldMapper.userSubmitV3SignedData`；网络层 merge 后再签名，避免经纬度 `Double` 与 JSON 不一致导致验签失败。
- 关键响应字段：`data.orderId`（订单编号，后续用于抓取与详情页）

### 4.4.2 orderType 口径（已更新）
- **普通下单**：不传递 `orderType` 字段
- **复借下单**：传递 `orderType: 1`（复借链路复用抓取与后续成功/好评流程）

详细说明见：`26-下单接口orderType参数优化.md`

## 4.5 提交前置：定位与强抓策略
- 根据 `/app/v3/app/config` 配置 `retrieveMobileContact`：
  - 1：强抓（权限拒绝可能中断流程）
  - 0/2：非强抓（权限拒绝允许降级并继续下单）
- 定位失败时 longitude/latitude 使用项目约定默认值，并保持签名字段完整性。

### 4.5.1 强抓定位分支细化
- 强抓下系统定位**首次拒绝**：
  - 回传 H5 **`""`**，不展示 b3；本次下单流程结束
- 强抓下“已拒绝/受限”（非首次）：
  - 展示 b3 二次引导；**Cancel** 与 **Go to Settings** 均回传 **`""`**
  - 拿不到真实坐标（失败/超时）同样回传 **`""`**
- 非强抓下**首次**拒绝：回传 **`""`**
- 非强抓下**非首次**拒绝：回传 `{"longitude":"-360","latitude":"-360"}` 继续下单

## 4.5.2 H5 下单成功后的 Native 数据抓取（`uploadData&&orderId`）

H5 经 `iosHandler` 发送 **`uploadData&&{orderId}`**（或 JSON 含 `orderId`）后，由 **`HQTProductApplyH5ViewController`** + **`HQTOrderDataCaptureCoordinator`** 执行，与 **`05-数据抓取与通讯录分片.md` §5.2** 一致：

1. **HUD Loading** + `POST /app/v3/mobile/device`（与通讯录是否授权无关；此阶段**不**展示进度弹框）
2. 检查/申请通讯录权限
3. 权限已决后展示 **`HQTScrapeProgressDialog`** → 有有效联系人则 `contact` 分片，否则跳过 → `ready` → `window.uploadDataSucc()` / `uploadDataFail()`

**与定位的时序**：若 H5 在定位未完成时先发 `uploadData`，Native 暂存 `pendingUploadOrderId`，待 `positionPermission` 回传后再启动抓取。

订单详情 H5 与产品申请 H5 共用 **`HQTOrderDataCaptureCoordinator`**（实现类以工程为准）。

### 4.5.2.1 抓取结果回传 H5（`uploadDataSucc` / `uploadDataFail`）

| 阶段结果 | H5 方法 | 产品申请 H5 额外行为 |
|----------|---------|---------------------|
| device / contact / ready 全流程成功 | `uploadDataSucc()` | 无 |
| 任一步失败 | `uploadDataFail()` | 无 |
| 强抓且已走过系统弹窗后，通讯录**二次引导**点「去设置」或「关闭」 | `uploadDataFail()` | **`uploadDataFail` JS 执行完成后** `popViewController` 回上一页 |

- 协调器参数：`failOnContactsSecondaryInteraction: true` + `onContactsSecondaryDismiss`（仅申请页设置 pop 标记）。
- 实现：`HQTProductApplyH5ViewController.startDataCapture` → `evalH5Callback("uploadDataFail")` completion → `popPreviousPageIfContactsSecondaryCaptureFailed()`。
- 订单详情页：二次弹框同样 `uploadDataFail`，**不**自动 pop（见 `14-订单详情H5.md`）。

### 4.5.3 H5 `positionPermission` 回传实现（已联调）

除 §4.4.6 payload 表外，Native 注入 H5 时须：

1. 写入 `localStorage` / `sessionStorage` 键 `positionPermission`
2. 依次调用 `window.positionPermission(对象)` → `window.positionPermission(JSON.stringify(对象))`
3. 空串场景调用 `positionPermission("")`，**禁止**空对象 JSON

实现：`HQTProductApplyLocationBridge` + `HQTProductApplyH5ViewController.deliverPositionPermission`（base64 注入）。联调日志期望 `ok_obj` 或 `ok_str`。

### 4.5.4 H5 申请页返回（`productGoBack`）

- H5 发 `productGoBack` → Native **直接** `popToRootViewController(animated:)`。
- **不展示** §4.9.4 的返回确认卡片（该弹框仅原生 TermV3/复借页使用）。

详见：`04-产品申请与下单-Prompt模板-直接使用.md`、`04-产品申请与下单H5-提示词-直接使用.md` §9。

## 4.6 费用说明与浮层规则
- 费用三行使用统一的“信息浮层行”组件：
  - 交互：点击标题与图标展开说明
  - 浮层：黑色半透明背景，叠加在当前行下方，不撑开布局
  - 互斥：同一页面最多展开一条

### 4.6.1 固定说明文案（与订单详情一致）
- Amount received：
  - The actual amount you receive is calculated by deducting the service fee from the loan amount.
- Service fee：
  - Service fee covers the administrative costs of processing your loan application.
- Interest：
  - Interest is the cost of borrowing money, calculated based on the loan amount and term.

## 4.7 防连点与恢复
- 提交按钮需要进行中锁，避免重复提交同一笔订单。
- 仅当出现失败/早退分支时恢复按钮可点；成功路径由后续流程接管。

### 4.7.1 协议与提交规则
- 协议区默认勾选。
- 用户取消勾选后点击提交：必须先提示“需同意协议”并阻断下单。
- 页面从银行卡列表返回后必须刷新银行卡区，防止使用旧选择。

## 4.8 已实现功能点（开发必须保留）
- 强抓定位首次拒绝：当前流程结束，不继续下单。
- 复借 apply 防连点：按钮锁定与失败分支解锁必须闭环。
- termV3 特定错误码（6230002/6230003）统一弹框并跳详情，不直接静默失败。

## 4.9 导航返回确认弹框与复借检查（产品下单页）

### 4.9.1 返回按钮触发逻辑
- 适用页面：`HQTProductApplyViewController`（原生产品下单页）。
- 触发时机：用户点击导航左上返回按钮时。
- 判断逻辑：
  - **普通下单（orderType=0）**：先检查复借，根据结果决定展示哪个弹框
  - **复借下单（orderType=1）**：直接展示返回确认弹框

### 4.9.2 复借检查流程（ee2场景）
- 仅在 `orderType == 0` 时触发。
- 检查条件：
  1. `dynamicParameter.fjtip == "on"`（复借开关开启）
  2. 调用 `/app/v3/product/state` 接口
     - 请求参数：`signedData: [:]`, `unsignedData: ["productId": productId]`（productId 不加密）
  3. 解析响应中的 `amountDetailList`，筛选 `userType == 2` 的产品
- 结果处理：
  - **有复借候选**：展示复借弹框（不展示返回确认弹框）
  - **无复借候选**：展示返回确认弹框
  - **接口失败**：展示返回确认弹框

### 4.9.3 复借弹框（ee2场景）
- 弹框样式：复用 `HQTReloanDialogViewController`（详见 `08-复借流程.md`）。
- 关闭行为：返回上一页（`popViewController`）。
- Apply 行为：执行完整复借下单流程（11步）：
  1. 拉取 termV3
  2. 选择最高金额档的最低期限
  3. 提交复借订单（orderType=1）
  4. HUD Loading → 上传 device（与通讯录授权无关）
  5. 通讯录权限检查
  6. 显示抓取进度弹框（仅通讯录+ready）
  7. contact 分片（无有效联系人则跳过）+ ready
  8. 关闭进度弹框
  8. 显示成功弹框
  9. 用户点击 Confirm
  10. 返回首页（`popToRootViewController`）

### 4.9.4 返回确认弹框（仅原生申请页，不含 H5 产品申请）

> **H5 产品申请页**：`productGoBack` 直接回首页，无此弹框（见 §4.5.4）。

- 触发条件（**原生** TermV3 申请/复借容器）：
  - 复借下单（orderType=1）时直接触发
  - 普通下单（orderType=0）且无复借候选时触发
- 弹框样式：复用 `HQTDialog.showCardAlert` 卡片弹框。
  - 顶部图标：`make_pic_return`
  - 标题：`Confirm to return?`
  - 正文：
    - `It's a pity to leave. There is still a lot of loan credits waiting for you to withdraw, so think about it!`
  - 按钮：左 `Confirm`（normal）/ 右 `Cancel`（cancel）
- Confirm 行为：返回首页（`popToRootViewController`）。
- 交互约束：禁用当前页侧滑返回，避免绕过确认弹框。

### 4.9.5 实现要点
- 复借检查与返回确认弹框互斥，不会同时出现。
- 复借弹框关闭时自动返回上一页，无需用户再次点击返回。
- 复借成功后直接返回首页，不停留在下单页。
- 代码实现参考：
  ```swift
  @objc private func tappedProductApplyBack() {
      if orderType == 0 {
          checkReloanBeforeBack()  // 检查复借
      } else {
          presentProductApplyExitConfirm()  // 直接展示返回确认
      }
  }
  ```


## 4.10 下单前银行卡检查（新增）

### 4.10.1 检查时机
- 用户点击"Apply now"按钮时
- 在协议勾选检查之后
- 在获取提交锁之前

### 4.10.2 检查逻辑
```swift
// 检查银行卡是否已添加
guard !bankRows.isEmpty, selectedBankRecordId != nil else {
    let message = configMessage(forKey: "p59") ?? "Please add a bank account before submitting your application."
    HQTToast.show(message, on: view)
    return
}
```

**检查条件**：
- `bankRows` 不为空（有银行卡列表）
- `selectedBankRecordId` 不为 `nil`（已选择银行卡）

**失败处理**：
- 显示 Toast 提示（配置键 `p59`）
- 阻断下单流程
- 不消耗提交锁

### 4.10.3 提示文案
- **配置键**：`p59`
- **默认文案**：`"Please add a bank account before submitting your application."`
- **查找顺序**：categoryConfig → appConfig → 默认文案

### 4.10.4 用户流程
1. 用户点击 Apply now
2. 检查协议勾选 ✓
3. 检查银行卡 ✗
4. 显示 Toast 提示
