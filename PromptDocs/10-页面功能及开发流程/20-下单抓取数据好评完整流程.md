# 下单→抓取数据→好评完整流程

## 概述

本文档整理了所有页面的下单、数据抓取、好评引导的完整流程，包括：
1. 产品下单页面（普通下单）
2. 产品下单页面（复借）
3. 订单详情页面（复借）
4. 首页（复借）
5. 订单详情页面（待抓取状态）

---

## 1. 产品下单页面（普通下单）

### 1.1 完整流程图

```
用户点击 Apply now
    ↓
检查协议勾选
    ↓
获取提交锁
    ↓
解析定位坐标
    ├─ 强抓模式：获取真实坐标或返回
    └─ 非强抓模式：获取真实坐标或使用默认坐标
    ↓
提交订单 (orderType=0)
    ↓
订单创建成功（获取 orderId 和 isFirst）
    ↓
通讯录权限检查
    ├─ 强抓模式拒绝 → 返回上一页
    └─ 权限正常 ↓
HUD Loading → POST /app/v3/mobile/device
    ↓
检查/申请通讯录权限
    ↓
显示抓取进度弹框（不含 device）
    ↓
执行通讯录与 ready
    ├─ /app/v3/mobile/contact（有有效联系人才上传；否则跳过）
    ├─ /app/v3/mobile/installApp（已安装 App；失败不阻断）
    └─ /app/v3/order/ready（通知抓取完成）
    ↓
关闭进度弹框
    ↓
显示成功弹框
```

### 1.2 关键代码位置

**文件**：`HQTeConsmpton/Home/HQTProductApplyViewController.swift`

**关键方法**：
1. `submitTapped()` - 用户点击申请按钮
2. `resolveCoordinatesForSubmit()` - 解析定位坐标
3. `sendUserSubmitV3()` - 提交订单
4. `HQTOrderDataScrapeCoordinator.runContactsPermissionPhase()` - 通讯录权限检查
5. `HQTOrderDataScrapeCoordinator.runScrapeAPIRequests()` - 执行数据抓取
6. `handlePostOrderSuccessGuidance()` - 订单成功后的引导
7. `shouldShowRatingGuidance()` - 判断是否显示好评引导

### 1.3 好评引导规则

**配置字段**：`feedbackGuidance` 或 `feedback_guidance`

**配置值**：
- `0`：不显示好评引导
- `1`：所有订单都显示好评引导
- `2`：仅非首单显示好评引导

**会话控制**：
- 每个安装周期只显示一次
- 使用 `UserDefaults` 存储标记

**星级阈值**：
- ≥4星：调用系统好评（`SKStoreReviewController.requestReview()`）
- <4星：显示感谢弹框

### 1.4 接口调用顺序

| 步骤 | 接口 | 参数 | 说明 |
|------|------|------|------|
| 1 | `/app/v3/order/userSubmitV3` | productId, loanAmount, longitude, latitude, showTerm, orderType=0 | 提交订单 |
| 2 | `/app/v3/mobile/device` | orderId, 设备信息 | 上传设备信息 |
| 3 | `/app/v3/mobile/contact` | orderId, list（分片） | 上传通讯录（分片并发） |
| 4 | `/app/v3/order/ready` | orderId, allowContact | 通知抓取完成 |

## 6. 数据抓取详细流程

### 6.1 HQTOrderDataScrapeCoordinator 协调器

**文件**：`HQTeConsmpton/Home/HQTOrderDataScrapeFlow.swift`

**核心方法**：

#### 6.1.1 通讯录权限检查

```swift
static func runContactsPermissionPhase(retrieveMode: Int) -> Result<Void, Error>
```

**流程**：
1. 检查当前通讯录权限状态
2. 如果已完全授权（authorized only）→ 成功；**limited（iOS 18+ 部分授权）按未授权**，与 denied 相同分支
3. 如果未决定（notDetermined）→ 请求权限 → 等待用户选择
4. 如果已拒绝（denied 或 restricted）：
   - 强抓模式（retrieveMode=1）→ 失败（返回错误码）
   - 非强抓模式（retrieveMode=0）→ 成功（允许继续）

**错误码**：
- `403`：`permissionErrorCodeDeniedNow` - 首次拒绝
- `1403`：`permissionErrorCodeNeedSecondaryPrompt` - 已拒绝，需要二次弹框

#### 6.1.2 执行数据抓取

```swift
static func runScrapeAPIRequests(orderId: String, progress: HQTOrderScrapeProgressControlling, completion: @escaping (Result<Void, Error>) -> Void)
```

**流程**：
1. **上传设备信息**（进度 0% → 18%）
   - 接口：`/app/v3/mobile/device`
   - 参数：`orderId` + 设备信息

2. **读取通讯录**（进度 18% → 42%）
   - 最多读取 `pushMaxCount` 条（默认 500）
   - 去重（按 contactPhone）
   - 规范化手机号（印度 10 位本地号；11 位带前导 0 时去 0；详见 `25-印度手机号规则.md`）

3. **分片上传通讯录**（进度 42% → 88%）
   - **重要**：如果通讯录数据为空，跳过此步骤，直接进入步骤 4
   - 接口：`/app/v3/mobile/contact`
   - 每片 `pushPerCount` 条（默认 50）
   - 并发上传所有分片
   - 进度按完成分片数计算

4. **通知抓取完成**（进度 88% → 100%）
   - 接口：`/app/v3/order/ready`
   - 参数：`orderId` + `allowContact`

**allowContact 值**：
- `""`：已完全授权（authorized）
- `"2"`：未授权（拒绝、受限、**iOS 18+ Limited 部分授权**；不上传通讯录）

**通讯录数据为空的处理**：
- 如果通讯录数据为空（用户拒绝权限、通讯录为空等），跳过 `/app/v3/mobile/contact` 接口
- 直接调用 `/app/v3/order/ready` 接口，传递正确的 `allowContact` 参数

### 6.2 配置参数

**配置字段**：
- `pushMaxCount` 或 `push_max_count`：最多上传通讯录条数（默认 500）
- `pushPerCount` 或 `push_per_count`：每片通讯录条数（默认 50）
- `retrieveMobileContact`：强抓模式（1=强抓，0=非强抓）

## 7. 好评引导详细流程

### 7.1 触发条件

**仅在产品下单页面（普通下单）触发**，复借不触发。

**判断逻辑**：
```swift
private func shouldShowRatingGuidance(isFirstOrder: Bool) -> Bool {
    // 1. 检查是否已在本安装周期显示过
    guard !hasShownRatingGuidanceInInstallCycle() else { return false }
    
    // 2. 获取配置
    let mode = feedbackGuidanceMode()
    
    // 3. 根据配置判断
    switch mode {
    case 1:
        return true  // 所有订单都显示
    case 2:
        return !isFirstOrder  // 仅非首单显示
    default:
        return false  // 不显示
    }
}
```

### 7.2 配置说明

**配置字段**：`feedbackGuidance` 或 `feedback_guidance`

**配置值**：
- `0`：不显示好评引导
- `1`：所有订单都显示好评引导
- `2`：仅非首单显示好评引导（首单不显示）

**会话控制**：
- 使用 `UserDefaults` 存储标记
- 每个安装周期只显示一次
- 卸载重装后重置

### 7.3 星级处理

**星级阈值**：4星

**处理逻辑**：
```swift
let threshold = 4
if stars >= threshold {
    // ≥4星：调用系统好评
    if #available(iOS 14.0, *) {
        if let scene = self.view.window?.windowScene {
            SKStoreReviewController.requestReview(in: scene)
        } else {
            SKStoreReviewController.requestReview()
        }
    } else {
        SKStoreReviewController.requestReview()
    }
    // 返回上一页
    self.navigationController?.popViewController(animated: true)
} else {
    // <4星：显示感谢弹框
    self.showRatingThankYouDialog()
}
```

### 7.4 感谢弹框

**标题**：Thank you

**消息**：We sincerely thank you for your feedback! We will carefully consider your suggestions to continuously improve.

**按钮**：
- Cancel：取消
- Confirm：确认 → 返回上一页

## 9. 注意事项

### 9.1 定位权限处理

- 强抓模式（retrieveMobileContact=1）：必须获取真实坐标
- 非强抓模式（retrieveMobileContact=0）：尝试获取真实坐标，拒绝后使用默认坐标
- 首页复借特殊：强抓模式拒绝后留在首页（不返回）

### 9.2 通讯录权限处理

- 强抓模式（retrieveMobileContact=1）：必须授权，拒绝后返回上一页
- 非强抓模式（retrieveMobileContact=0）：可选授权，拒绝或 iOS 18+ Limited 后继续（allowContact=2，不上传通讯录）

**H5 申请页 / 订单详情（`HQTOrderDataCaptureCoordinator`）**

- 强抓且已走过系统弹窗后，通讯录**二次引导**（去设置 / 关闭）→ 均 `uploadDataFail()`。
- **产品申请 H5**：`uploadDataFail` JS 执行完成后 **pop 一层**（非 popToRoot）。
- **订单详情 H5**：仅 `uploadDataFail`，不自动 pop。
- 详见 `05-数据抓取与通讯录分片.md` §5.4.1。

### 9.3 数据抓取

- H5 路径：产品申请 / 订单详情共用 `HQTOrderDataCaptureCoordinator`；成功/失败回传 `uploadDataSucc` / `uploadDataFail`。
- 首页复借等原生路径：逻辑一致，二次弹框默认不触发 H5 专用 pop（`failOnContactsSecondaryInteraction` 默认 false）。
- 进度弹框仅覆盖通讯录 + ready 阶段（device 阶段 HUD）。

### 9.4 好评引导

- 仅产品下单页面（普通下单）有好评引导
- 复借流程不显示好评引导
- 每个安装周期只显示一次

### 9.5 错误处理

- 定位权限拒绝：强抓模式返回上一页，非强抓模式继续
- 通讯录权限拒绝：强抓模式返回上一页，非强抓模式继续
- 数据抓取失败：订单已创建，H5 收 `uploadDataFail`；申请页通讯录二次弹框失败还会在回调后 pop 一层
