# 下单前银行卡检查

## 修改概述

在产品下单页面点击"Apply now"按钮时，增加银行卡检查逻辑：
- 检查是否已添加银行卡
- 如果没有银行卡，显示提示文案（p59）
- 阻止下单流程继续

## 1. 功能说明

### 1.1 检查时机

**触发位置**：`HQTProductApplyViewController` 的 `submitTapped()` 方法

**检查顺序**：
1. 检查协议是否勾选
2. **检查银行卡是否已添加**（新增）
3. 获取提交锁
4. 解析定位
5. 提交订单

### 1.2 检查逻辑

```swift
// 检查银行卡是否已添加
guard !bankRows.isEmpty, selectedBankRecordId != nil else {
    let message = configMessage(forKey: "p59") ?? "Please add a bank account before submitting your application."
    HQTToast.show(message, on: view)
    return
}
```

**检查条件**：
- `bankRows` 不为空（有银行卡列表）
- `selectedBankRecordId` 不为 `nil`（已选择银行卡）

**失败处理**：
- 显示 Toast 提示
- 阻止下单流程
- 不消耗提交锁

## 2. 提示文案

### 2.1 文案来源

**优先级**：
1. 配置文件中的 `p59` 键（categoryConfig 或 appConfig）
2. 默认英文文案：`"Please add a bank account before submitting your application."`

### 2.2 配置文案获取

**实现方法**：
```swift
/// 从配置中获取提示文案（支持 categoryConfig 和 appConfig）
private func configMessage(forKey key: String) -> String? {
    if let s = recursiveConfigString(forKey: key, in: HQTAppConfigStore.shared.categoryConfigJSON),
       !s.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty {
        return s
    }
    if let s = recursiveConfigString(forKey: key, in: HQTAppConfigStore.shared.appConfigJSON),
       !s.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty {
        return s
    }
    return nil
}

/// 递归查找配置字符串
private func recursiveConfigString(forKey want: String, in node: Any?) -> String? {
    guard let node else { return nil }
    if let dict = node as? [String: Any] {
        if let v = dict[want] as? String, !v.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty { return v }
        for (_, child) in dict {
            if let hit = recursiveConfigString(forKey: want, in: child) { return hit }
        }
    } else if let arr = node as? [Any] {
        for child in arr {
            if let hit = recursiveConfigString(forKey: want, in: child) { return hit }
        }
    }
    return nil
}
```

**查找顺序**：
1. 在 `categoryConfigJSON` 中递归查找 `p59`
2. 在 `appConfigJSON` 中递归查找 `p59`
3. 返回 `nil`（使用默认文案）

## 3. 银行卡数据来源

### 3.1 数据字段

**文件**：`HQTeConsmpton/Home/HQTProductApplyViewController.swift`

**关键字段**：
```swift
private var bankRows: [HQTBankCardModel] = []
private var selectedBankRecordId: String?
```

**说明**：
- `bankRows`：银行卡列表，从 termV3 接口或银行卡列表接口获取
- `selectedBankRecordId`：当前选中的银行卡 ID

### 3.2 数据加载

**来源 1：termV3 接口**
```swift
let termBanks = HQTBankCardModel.listFromTermV3Root(obj)
if !termBanks.isEmpty {
    bankRows = termBanks
}
```

**来源 2：银行卡列表接口**
```swift
HQTNetworkClient.shared.post(endpoint: "/app/v3/payAccountInfo/list", ...) { result in
    let rows = HQTBankCardModel.list(from: env)
    self.bankRows = rows
}
```

### 3.3 银行卡选择

**触发方式**：点击银行卡选择区域

**选择逻辑**：
```swift
@objc private func accountTapped() {
    let options = bankRows.enumerated().map { idx, row in
        HQTDialog.BankAccountOption(
            key: row.recordId.isEmpty ? "\(idx)" : row.recordId,
            label: bankOptionLabel(row)
        )
    }
    HQTDialog.showBankAccountPicker(
        on: self,
        options: options,
        selectedKey: selectedBankRecordId
    ) { [weak self] picked in
        // 更新选中的银行卡
        self.selectedBankRecordId = row.recordId
        self.accountSubtitleLabel.text = self.bankOptionLabel(row)
    } onAddBank: { [weak self] in
        // 跳转到添加银行卡页面
        let vc = HQTBankAccountEditViewController(mode: .add)
        self.navigationController?.pushViewController(vc, animated: true)
    }
}
```

## 4. 用户流程

### 4.1 正常流程（有银行卡）

```
用户点击 Apply now
    ↓
检查协议勾选 ✓
    ↓
检查银行卡 ✓
    ↓
获取提交锁
    ↓
解析定位
    ↓
提交订单
```

### 4.2 异常流程（无银行卡）

```
用户点击 Apply now
    ↓
检查协议勾选 ✓
    ↓
检查银行卡 ✗
    ↓
显示 Toast 提示
    ↓
停留在当前页面
    ↓
用户可以：
  - 点击银行卡区域添加银行卡
  - 重新点击 Apply now
```

### 4.3 添加银行卡流程

```
用户点击银行卡区域
    ↓
显示银行卡选择弹框
    ↓
用户点击 "+ Please add a receiving account"
    ↓
跳转到添加银行卡页面
    ↓
用户填写银行卡信息
    ↓
提交成功
    ↓
返回下单页面
    ↓
刷新银行卡列表
    ↓
用户可以重新点击 Apply now
```

## 6. 注意事项

### 6.1 检查顺序

银行卡检查必须在以下检查之后：
- 协议勾选检查

银行卡检查必须在以下操作之前：
- 获取提交锁
- 解析定位
- 提交订单

**原因**：
- 避免消耗提交锁
- 避免触发定位权限请求
- 提前拦截无效提交

### 6.2 提示方式

使用 Toast 而不是弹框：
- Toast 不阻断用户操作
- 用户可以立即点击银行卡区域添加
- 与其他表单验证提示保持一致

### 6.3 文案配置

配置文案键 `p59` 应该：
- 简洁明了
- 提示用户添加银行卡
- 使用英文（当前项目语言）

**建议文案**：
- `"Please add a bank account before submitting your application."`
- `"Bank account is required. Please add one to continue."`
- `"You need to add a receiving account first."`

### 6.4 与其他检查的关系

| 检查项 | 顺序 | 失败处理 | 说明 |
|--------|------|---------|------|
| **协议勾选** | 1 | Toast 提示 | 必须勾选协议 |
| **银行卡检查** | 2 | Toast 提示 | 必须有银行卡 |
| **提交锁** | 3 | 静默返回 | 防止重复提交 |
| **定位权限** | 4 | 弹框/返回 | 根据强抓模式 |
| **订单提交** | 5 | Toast/跳转 | 提交订单接口 |
