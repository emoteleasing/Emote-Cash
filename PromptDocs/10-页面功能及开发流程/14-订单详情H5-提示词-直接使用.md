# 14-订单详情 H5 提示词（直接使用）

## 使用目标
- 用于生成“订单详情 H5”原生容器与桥接能力，覆盖从订单列表进入、详情内交互、返回刷新等完整流程。
- 产出需可直接联调上线，且**不要求与当前页面实现一致**，可采用新的页面结构与状态管理。

## 原生必须实现的能力（描述性要求）

### 1) 入口与参数管理
- 订单详情页需支持多入口（订单列表、异常跳转、运营入口）。
- 打开 H5 时至少包含订单维度参数；其他参数按场景动态携带，禁止传空占位。
- 通用用户环境数据由原生统一注入，不要求全部堆到 URL。

### 2) 容器统一标准
- 支持加载中状态、进度可视化、失败兜底、返回控制。
- 支持 Web 页面中途请求重新同步原生环境数据。
- 支持账号态变化时的强制回收与重建流程。

### 3) 与申请页能力对齐（必须）
- 订单详情 H5 需具备与申请 H5 一致的核心桥接能力：
  - 定位能力请求
  - 抓取链路触发与回传（`uploadData&&orderId` → device → contact → ready → `uploadDataSucc` / `uploadDataFail`）
  - 成功回跳与后续引导能力
  - 会话退出类动作处理
- 统一权限、容错、埋点与频控口径，避免两套行为分叉。

**抓取与通讯录二次弹框（与申请页差异）**
- 强抓通讯录二次引导（`HQTPermissionSecondaryDialog`）：去设置 / 关闭 → 均 `uploadDataFail()`。
- 订单详情：**不**在 `uploadDataFail` 后自动 pop；产品申请页会在二次弹框失败且 H5 回调执行后 **pop 一层**（见 `04-产品申请与下单H5-提示词-直接使用.md` §9.4.1）。

### 4) 详情页专用“返回并刷新”
- H5 发起“关闭详情”后，原生需返回上一级并刷新当前订单列表数据。
- 刷新应保持当前筛选维度与当前 tab 上下文，不应重置到错误状态。
- 返回动作需防抖，避免重复触发导致多次刷新或导航异常。

### 5) 外链和非站内协议
- 详情中出现外部协议链接时，原生要判断是否可拉起系统能力。
- 无法拉起时给出统一提示，避免静默失败。

### 6) 失败分支与用户提示
- 参数缺失、链接无效、加载失败、桥接参数不完整时，必须有明确用户可见提示。
- 禁止出现“遮罩不消失”“返回无响应”“刷新不生效”等卡死态。

## 交付质量要求（必须）
- 能力闭环优先于页面复刻：允许页面结构、组件拆分、状态管理方式与当前页面不同。
- 桥接事件处理应可扩展，支持新增动作不破坏已有流程。
- 输出包含联调检查项：进入、抓取、返回刷新、账号态切换、异常兜底。

## 可直接粘贴给 AI 的 Prompt

```text
请实现“订单详情 H5 原生容器”能力，要求如下：

1. 总体目标
- 直接生成可联调上线的完整功能，允许重构，不要求与当前页面一致。
- 覆盖：多入口打开、参数管理、容器加载、桥接通信、返回刷新、异常兜底。

2. 页面能力
- 从订单相关入口进入 H5 详情，按场景动态带订单参数。
- 通用环境信息由原生注入，支持前端主动再次请求同步。
- 支持加载进度与失败反馈，不可出现无反馈失败。

3. 业务桥接
- 与申请 H5 对齐：定位请求、抓取触发（uploadDataSucc/uploadDataFail）、成功回跳、账号态退出等能力必须完整。
- 强抓通讯录二次弹框：两按钮均 uploadDataFail；详情页不自动 pop（申请页 uploadDataFail 后 pop 一层）。
- 详情页专用动作：关闭详情时返回上一页并刷新订单列表（保持当前筛选上下文）。

4. 交互与稳定性
- 对返回与刷新做防抖和幂等保护。
- 支持外链识别与系统拉起，失败统一提示。
- 权限拒绝、参数缺失、接口异常都要有可见反馈。

5. 输出要求
- 不写具体方法名设计说明，按能力描述输出实现。
- 给出：改动文件、关键流程、联调自测清单（含返回刷新校验）。
```
