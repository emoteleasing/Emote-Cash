# 订单详情待抓取状态处理

## Native 实现口径（HQElenFiae / `HQEProductApplyWebViewController`）

订单详情 H5 与产品申请 H5 共用同一容器；H5 调 `uploaddata` 后 Native 流程与 `05-数据抓取与通讯录分片.md` §5.2 一致：

1. **HUD Loading** + `POST /app/v3/mobile/device`（不依赖通讯录授权）
2. 检查/申请通讯录权限（进度条此后再出）
3. **`HQTScrapeProgressDialog`**（或工程内等价进度 UI）→ 有联系人则 `contact` 分片，无则跳过 → `ready` → 回传 H5 `uploadDataSucc` / `uploadDataFail`
4. 强抓通讯录二次引导：去设置 / 关闭 → 均 `uploadDataFail`；订单详情**不**自动 pop（产品申请 H5 会在 `uploadDataFail` 后 pop 一层，见 `05-数据抓取与通讯录分片.md` §5.4.1）

## 概述

本文档说明订单详情页面对 `orderStatus = 10`（待抓取状态）的处理逻辑，使其与下单页面的数据抓取流程保持一致。

---

## 业务场景

### 什么是待抓取状态？

**orderStatus = 10** 表示订单已创建成功，但用户尚未完成数据抓取（通讯录上传）。

### 为什么会出现这种状态？

1. **用户中断流程**：在下单页面完成订单创建后，用户可能在数据抓取环节退出
2. **权限问题**：用户拒绝了通讯录权限，导致数据抓取未完成
3. **网络问题**：数据上传过程中网络中断

### 用户如何处理？

用户可以从订单列表进入订单详情页，点击"Submit"按钮重新进入数据抓取流程。

## 代码实现

### 1. 按钮配置

在 `configureActionButtons()` 方法中，为 orderStatus = 10 配置按钮：

```swift
private func configureActionButtons() {
    secondaryActionButton.isHidden = true
    primaryActionButton.isHidden = false
    
    switch statusCode {
    case 60:
        secondaryActionButton.isHidden = false
        secondaryActionButton.setTitle("Defer", for: .normal)
        primaryActionButton.setTitle("Repay", for: .normal)
    case 61:
        primaryActionButton.setTitle("Repay", for: .normal)
    case 36:
        primaryActionButton.setTitle("Change bank account", for: .normal)
    case 10:
        primaryActionButton.setTitle("Submit", for: .normal)  // 待抓取状态
    case 32:
        primaryActionButton.setTitle("Withdraw", for: .normal)
    default:
        primaryActionButton.isHidden = true
    }
    
    let singleButtonMode = secondaryActionButton.isHidden
    secondaryTrailingConstraint?.isActive = !singleButtonMode
    primaryLeadingToCenterConstraint?.isActive = !singleButtonMode
    primaryLeadingToRowConstraint?.isActive = singleButtonMode
}
```

### 2. 按钮点击处理

在 `tappedPrimary()` 方法中，为 orderStatus = 10 添加处理逻辑：

```swift
@objc private func tappedPrimary() {
    switch statusCode {
    case 60, 61:
        requestRepayLink(endpoint: "/app/v3/order/repay/connect")
    case 36:
        openEditBankAccountPage()
    case 10:
        // 待抓取状态：进入数据抓取流程（与下单页面一致）
        handlePendingDataCapture()
    case 32:
        if isWithdrawDetail {
            requestWithdrawalApply()
        }
    default:
        break
    }
}
```

### 3. 数据抓取流程

新增 `handlePendingDataCapture()` 方法，实现与下单页面一致的数据抓取逻辑：

```swift
/// 处理待抓取状态（orderStatus = 10）：进入数据抓取流程
private func handlePendingDataCapture() {
    print("🔍 [Data Capture Debug] 订单详情页：开始数据抓取流程，orderId=\(orderId)")
    
    primaryActionButton.isEnabled = false
    
    let retrieveMode = HQTOrderDataScrapeCoordinator.currentRetrieveMobileContactMode()
    
    DispatchQueue.global(qos: .userInitiated).async { [weak self] in
        guard let self else { return }
        
        // 1. 权限检查
        let perm = HQTOrderDataScrapeCoordinator.runContactsPermissionPhase(retrieveMode: retrieveMode)
        
        switch perm {
        case let .failure(err):
            DispatchQueue.main.async { [weak self] in
                guard let self else { return }
                
                self.primaryActionButton.isEnabled = true
                
                let nserr = err as NSError
                
                // 强抓模式下，用户拒绝通讯录权限则返回上一页面
                if retrieveMode == 1 {
                    print("❌ [Data Capture Debug] 强抓模式下用户拒绝通讯录权限，返回上一页面")
                    
                    // 如果是首次拒绝（用户刚点击了系统弹框的"不允许"）
                    if nserr.code == HQTOrderDataScrapeCoordinator.permissionErrorCodeDeniedNow {
                        // 直接返回上一页面，不显示二次弹框
                        self.navigationController?.popViewController(animated: true)
                    }
                    // 如果是已经拒绝过（需要去设置中开启）
                    else if nserr.code == HQTOrderDataScrapeCoordinator.permissionErrorCodeNeedSecondaryPrompt {
                        // 显示二次引导弹框，点击取消后返回上一页面
                        HQTDialog.showPermissionSecondaryAlert(
                            on: self,
                            kind: .contacts,
                            onCancel: { [weak self] in
                                self?.navigationController?.popViewController(animated: true)
                            },
                            onConfirmAfterOpenSettings: { [weak self] in
                                self?.navigationController?.popViewController(animated: true)
                            }
                        )
                    } else {
                        // 其他错误情况也返回上一页面
                        HQTToast.show(err.localizedDescription, on: self.view)
                        DispatchQueue.main.asyncAfter(deadline: .now() + 1.5) { [weak self] in
                            self?.navigationController?.popViewController(animated: true)
                        }
                    }
                } else {
                    // 非强抓模式，显示提示但不返回
                    if nserr.code == HQTOrderDataScrapeCoordinator.permissionErrorCodeNeedSecondaryPrompt {
                        HQTDialog.showPermissionSecondaryAlert(
                            on: self,
                            kind: .contacts
                        )
                    } else {
                        HQTToast.show(err.localizedDescription, on: self.view)
                    }
                }
            }
            
        case .success:
            DispatchQueue.main.async { [weak self] in
                guard let self else { return }
                
                // 2. 显示抓取进度弹框
                let scrapeBox = HQTDialog.showOrderScrapeProgress(on: self)
                
                // 3. 执行抓取
                HQTOrderDataScrapeCoordinator.runScrapeAPIRequests(orderId: self.orderId, progress: scrapeBox) { [weak self] scrapeResult in
                    guard let self else { return }
                    
                    scrapeBox.close {
                        self.primaryActionButton.isEnabled = true
                        
                        switch scrapeResult {
                        case .success:
                            print("✅ [Data Capture Debug] 数据抓取成功")
                            // 显示成功弹框
                            let successIcon = UIImage(named: "make_pic_su") ?? UIImage(named: "make_pic_successful")
                            HQTDialog.showCardAlert(
                                on: self,
                                title: "Success!",
                                message: "Your application is under review. Once approved, the money will be credited to your bank account.",
                                icon: successIcon,
                                customBody: nil,
                                iconUsesOriginalRendering: true,
                                hideTopIconBackdrop: false,
                                actions: [
                                    HQTDialog.Action(title: "Confirm", style: .normal, handler: { [weak self] in
                                        // 刷新订单详情
                                        self?.fetchDetail()
                                    }),
                                ]
                            )
                            
                        case .failure(let error):
                            print("❌ [Data Capture Debug] 数据抓取失败: \(error.localizedDescription)")
                            HQTToast.show("Data capture failed. Please try again.", on: self.view)
                        }
                    }
                }
            }
        }
    }
}
```

## 与下单页面的一致性

### 相同点

| 特性 | 下单页面 | 订单详情页 | 状态 |
|------|---------|-----------|------|
| **权限检查** | `runContactsPermissionPhase` | `runContactsPermissionPhase` | ✅ 一致 |
| **数据抓取** | `runScrapeAPIRequests` | `runScrapeAPIRequests` | ✅ 一致 |
| **进度弹框** | `showOrderScrapeProgress` | `showOrderScrapeProgress` | ✅ 一致 |
| **成功弹框** | 显示成功提示 | 显示成功提示 | ✅ 一致 |
| **强抓模式** | 拒绝返回上一页 | 拒绝返回上一页 | ✅ 一致 |
| **非强抓模式** | 显示提示但继续 | 显示提示但继续 | ✅ 一致 |

### 不同点

| 特性 | 下单页面 | 订单详情页 | 说明 |
|------|---------|-----------|------|
| **触发时机** | 订单创建成功后 | 点击"Submit"按钮 | 场景不同 |
| **成功后操作** | 可能触发评分引导 | 刷新订单详情 | 后续流程不同 |
| **订单ID来源** | 接口返回 | 页面初始化传入 | 数据来源不同 |

## 业务规则

### 强抓模式（retrieveMobileContact = 1）

| 场景 | 行为 | 说明 |
|------|------|------|
| **首次请求被拒绝** | 返回上一页 | 不显示二次弹框，直接返回 |
| **已拒绝 + 点击取消** | 返回上一页 | 显示二次弹框后点击取消 |
| **已拒绝 + 点击确认** | 返回上一页 | 跳转设置后返回 |
| **授权成功** | 执行数据抓取 | 正常流程 |
| **抓取成功** | 刷新订单详情 | 订单状态应该变为审核中 |
| **抓取失败** | 显示错误提示 | 可重试 |

### 非强抓模式（retrieveMobileContact = 0）

| 场景 | 行为 | 说明 |
|------|------|------|
| **任何权限状态** | 继续抓取流程 | 不强制要求通讯录权限 |
| **拒绝权限** | 显示提示但继续 | 不返回上一页 |
| **抓取成功** | 刷新订单详情 | 正常流程 |

## 订单状态说明

### orderStatus 枚举

| 状态码 | 状态名称 | 按钮文案 | 点击行为 |
|--------|---------|---------|---------|

| 30 | Under review | - | 无按钮 |
| 31 | Review rejected | - | 无按钮 |
| 36 | Change bank account | Change bank account | 跳转修改银行卡页面 |
| 50 | Loan processing | - | 无按钮 |
| 32 | To be withdrawn | Withdraw | 提现申请 |

| 61 | Overdue | Repay | 还款 |

## 测试场景

### 场景 1：强抓模式 + 首次拒绝

**步骤**：
1. 配置 `retrieveMobileContact = 1`
2. 订单状态为 10（待抓取）
3. 进入订单详情页
4. 点击"Submit"按钮
5. 系统弹出通讯录权限请求
6. 用户点击"不允许"

**预期结果**：
- ✅ 直接返回上一页面
- ✅ 不显示二次弹框
- ✅ 订单状态仍为 10

### 场景 2：强抓模式 + 已拒绝 + 点击取消

**步骤**：
1. 配置 `retrieveMobileContact = 1`
2. 用户之前已拒绝通讯录权限
3. 订单状态为 10
4. 进入订单详情页
5. 点击"Submit"按钮
6. 显示二次引导弹框
7. 用户点击"取消"

**预期结果**：
- ✅ 返回上一页面
- ✅ 订单状态仍为 10

### 场景 3：强抓模式 + 授权成功 + 抓取成功

**步骤**：
1. 配置 `retrieveMobileContact = 1`
2. 用户授予通讯录权限
3. 订单状态为 10
4. 进入订单详情页
5. 点击"Submit"按钮

**预期结果**：
- ✅ 显示数据抓取进度弹框
- ✅ 上传设备信息
- ✅ 上传通讯录数据
- ✅ 调用 orderReady 接口
- ✅ 显示成功弹框
- ✅ 点击"Confirm"后刷新订单详情
- ✅ 订单状态变为 30（审核中）

### 场景 4：非强抓模式 + 拒绝权限

**步骤**：
1. 配置 `retrieveMobileContact = 0`
2. 用户拒绝通讯录权限
3. 订单状态为 10
4. 进入订单详情页
5. 点击"Submit"按钮

**预期结果**：
- ✅ 显示数据抓取进度弹框
- ✅ 上传设备信息（不上传通讯录）
- ✅ 调用 orderReady 接口（allowContact=2）
- ✅ 显示成功弹框
- ✅ 不返回上一页面

### 场景 5：抓取失败

**步骤**：
1. 订单状态为 10
2. 进入订单详情页
3. 点击"Submit"按钮
4. 数据抓取过程中网络中断

**预期结果**：
- ✅ 关闭进度弹框
- ✅ 显示错误提示："Data capture failed. Please try again."
- ✅ "Submit"按钮重新启用
- ✅ 用户可以重试

## 注意事项

### 1. 按钮状态管理

```swift
// 开始抓取时禁用按钮
primaryActionButton.isEnabled = false

// 抓取完成后启用按钮
primaryActionButton.isEnabled = true
```

**原因**：防止用户重复点击。

### 2. 订单ID传递

```swift
HQTOrderDataScrapeCoordinator.runScrapeAPIRequests(orderId: self.orderId, ...)
```

**注意**：使用页面初始化时传入的 `orderId`，不是从接口返回获取。

### 3. 成功后刷新

```swift
HQTDialog.Action(title: "Confirm", style: .normal, handler: { [weak self] in
    // 刷新订单详情
    self?.fetchDetail()
})
```

**原因**：数据抓取成功后，订单状态应该从 10 变为 30，需要刷新页面显示最新状态。

### 4. 错误处理

```swift
case .failure(let error):
    print("❌ [Data Capture Debug] 数据抓取失败: \(error.localizedDescription)")
    HQTToast.show("Data capture failed. Please try again.", on: self.view)
```

**注意**：
- 显示友好的错误提示
- 保持按钮可用，允许用户重试
- 不自动返回上一页

### 5. 调试日志

代码中包含详细的调试日志：

```swift
print("🔍 [Data Capture Debug] 订单详情页：开始数据抓取流程，orderId=\(orderId)")
print("❌ [Data Capture Debug] 强抓模式下用户拒绝通讯录权限，返回上一页面")

```

**建议**：在测试时开启控制台日志，观察完整流程。
