# 通讯录接口空数据优化

## 概述

优化数据抓取流程，当通讯录获取到的数据为空时，跳过 `/app/v3/mobile/contact` 接口调用，直接调用 `/app/v3/order/ready` 接口。

---

## 问题描述

### 原有逻辑

在数据抓取流程中，即使通讯录数据为空（`batches.isEmpty`），代码逻辑也会尝试调用 `/app/v3/mobile/contact` 接口。虽然实际上不会发送请求（因为循环体为空），但逻辑不够清晰。

### 优化需求

**明确要求**：如果通讯录获取到的数据为空，则不需要调用 `/app/v3/mobile/contact` 接口，直接跳过该步骤，调用 `/app/v3/order/ready` 接口。

## 通讯录数据为空的场景

### 场景 1：用户拒绝通讯录权限（非强抓模式）

**流程**：
1. 用户拒绝通讯录权限
2. `CNContactStore.authorizationStatus` 返回 `.denied`
3. `buildContactOutcomeForUpload` 返回 `ContactOutcome(allowCode: "2", batches: [])`
4. `batches.isEmpty` 为 `true`
5. **跳过 `/app/v3/mobile/contact` 接口**
6. 直接调用 `/app/v3/order/ready`，参数 `allowContact: "2"`

### 场景 1b：iOS 18+ 部分授权 Limited（按未授权）

**流程**：
1. 用户在系统弹窗选择「选择联系人」等 → `authorizationStatus == .limited`
2. **注意**：`requestAccess` 回调 `granted` 可能仍为 `true`，必须以弹窗后 `authorizationStatus` 判断
3. `buildContactRows` 因非 `.authorized` 返回 `[]`，**不调用** `/app/v3/mobile/contact`
4. **强抓**：首次 → Toast 中断；再次 → 通讯录二次引导后失败
5. **非强抓**：直接 `POST /app/v3/order/ready`，`allowContact: "2"`
6. 若误入 `runContactsPipeline` 且通讯录为空：`resolvedAllowContactForReady` 禁止 `allowContact=""` 误上报

**实现**：`handleContactsNotFullyAuthorized`；详见 `05-数据抓取与通讯录分片.md` §5.3（iOS 18+ 表）。

### 场景 2：用户授权但通讯录为空

**流程**：
1. 用户授权通讯录权限
2. `CNContactStore.authorizationStatus` 返回 `.authorized`
3. `buildContactRows` 读取通讯录，返回空数组 `[]`
4. `slice([], per: 50)` 返回空数组 `[]`
5. `buildContactOutcomeForUpload` 返回 `ContactOutcome(allowCode: "", batches: [])`
6. `batches.isEmpty` 为 `true`
7. **跳过 `/app/v3/mobile/contact` 接口**
8. 直接调用 `/app/v3/order/ready`，参数 `allowContact: ""`

### 场景 3：用户授权且通讯录有数据

**流程**：
1. 用户授权通讯录权限
2. `buildContactRows` 读取通讯录，返回数据数组（如 120 条）
3. `slice(rows, per: 50)` 分片，返回 3 个批次
4. `buildContactOutcomeForUpload` 返回 `ContactOutcome(allowCode: "", batches: [batch1, batch2, batch3])`
5. `batches.isEmpty` 为 `false`
6. **调用 `/app/v3/mobile/contact` 接口**，并发上传 3 个批次
7. 所有批次上传完成后，调用 `/app/v3/order/ready`，参数 `allowContact: ""`

---

## allowContact 参数说明

| 权限状态 | allowContact 值 | 说明 |
|---------|----------------|------|
| **已完全授权（authorized）** | `""` | 可读取完整通讯录并上传 |
| **部分授权（limited，iOS 18+）** | `"2"` | **按未授权处理**：不上传通讯录，走拒绝/强抓中断与非强抓降级流程 |
| **已拒绝或受限** | `"2"` | 同上 |

## 优化效果

### 1. 减少不必要的接口调用

- **优化前**：即使通讯录为空，也会进入接口调用逻辑（虽然不会实际发送请求）
- **优化后**：通讯录为空时，明确跳过接口调用，直接进入下一步

### 2. 提升代码可读性

- 添加了清晰的日志输出
- 明确了空数据的处理逻辑

### 3. 提升用户体验

- 通讯录为空时，进度条更新更快（直接从 42% 跳到 88%）
- 减少不必要的等待时间

## 相关代码

### buildContactRows 方法

```swift
/// 读取通讯录并生成上传 `list`（最多 `maxTotal` 条，去重按 `contactPhone`）。
static func buildContactRows(maxTotal: Int) throws -> [[String: Any]] {
    let store = CNContactStore()
    let keys: [CNKeyDescriptor] = [
        CNContactGivenNameKey as CNKeyDescriptor,
        CNContactFamilyNameKey as CNKeyDescriptor,
        CNContactPhoneNumbersKey as CNKeyDescriptor,
    ]
    let request = CNContactFetchRequest(keysToFetch: keys)
    var rows: [[String: Any]] = []
    var seen = Set<String>()
    try store.enumerateContacts(with: request) { contact, stop in
        guard rows.count < maxTotal else {
            stop.pointee = true
            return
        }
        let name = [contact.givenName, contact.familyName].filter { !$0.isEmpty }.joined(separator: " ").trimmingCharacters(in: .whitespacesAndNewlines)
        let displayName = name.isEmpty ? "Unknown" : name
        for labeled in contact.phoneNumbers {
            guard rows.count < maxTotal else {
                stop.pointee = true
                return
            }
            let raw = (labeled.value as CNPhoneNumber).stringValue
            guard let phone = normalizedSubmitPhone(raw) else { continue }
            guard !seen.contains(phone) else { continue }
            seen.insert(phone)
            let ts = String(Int64(Date().timeIntervalSince1970 * 1000))
            rows.append([
                "contactName": displayName,
                "contactPhone": phone,
                "contactUpdateTime": ts,
                "contactStorage": "0",
                "contactCount": "-99",
                "contactTime": "",
            ])
        }
    }
    return rows  // 如果通讯录为空，返回空数组 []
}
```

### buildContactOutcomeForUpload 方法

```swift
/// 权限已就绪后：按当前授权生成 `allowContact` 与通讯录分片（不再调用 `requestAccess`）。
private static func buildContactOutcomeForUpload(maxCount: Int, per: Int) -> Result<ContactOutcome, Error> {
    let sem = DispatchSemaphore(value: 0)
    var outcome: Result<ContactOutcome, Error> = .failure(NSError(domain: "HQTOrderScrape", code: -1))
    DispatchQueue.main.async {
        let status = CNContactStore.authorizationStatus(for: .contacts)
        let allow = HQTOrderContactScrapeBuilder.allowContactCode(for: status)
        if HQTContactsAuthorization.canEnumerateContacts(status) {
            DispatchQueue.global(qos: .userInitiated).async {
                do {
                    let rows = try HQTOrderContactScrapeBuilder.buildContactRows(maxTotal: maxCount)
                    let batches = HQTOrderContactScrapeBuilder.slice(rows, per: per)
                    outcome = .success(ContactOutcome(allowCode: allow, batches: batches))
                } catch {
                    outcome = .failure(error)
                }
                sem.signal()
            }
        } else {
            // 未授权或拒绝，返回空批次
            outcome = .success(ContactOutcome(allowCode: allow, batches: []))
            sem.signal()
        }
    }
    sem.wait()
    return outcome
}
```

## 注意事项

### 1. 空数据判断

- 使用 `batches.isEmpty` 判断通讯录数据是否为空
- 空数据包括：用户拒绝权限、通讯录为空、读取失败等情况

### 2. allowContact 参数

- 即使通讯录为空，也需要传递正确的 `allowContact` 参数
- 后端根据此参数判断用户的授权状态

### 3. 进度更新

- 通讯录为空时，进度直接从 42% 跳到 88%
- 通讯录不为空时，进度从 42% 逐步更新到 88%（根据上传批次）

### 4. 日志输出

- 添加了清晰的日志，便于调试和问题排查
- 日志前缀：`📋 [Contact Debug]`
