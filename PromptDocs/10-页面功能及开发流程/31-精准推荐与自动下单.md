# 31. 精准推荐与首页自动下单

## 31.1 适用范围

本文档描述 **印度（DC）市场「精准推荐」全链路** 与 **首页自动下单（静默批量首贷）** 的完整功能规格。实现时须复用项目既有网络层、统一弹框、HUD、防连点、金额格式化、定位二次引导、数据抓取协调器等基础能力，**禁止平行重复造轮子**。

**包含范围：**

- 首页入口：手动进精准推荐、自动下单触发条件与防重入
- 匹配中弹框 + `dcRecommend`（含 **10 秒超时**）
- 推荐结果页态：列表 / 无产品（含 `4102007`）/ View Now（其它错误码）
- 列表页：多产品勾选、额度滑档、期限选择、协议、汇总、Apply
- 定位（强抓 / 非强抓）→ `userSubmitDcUpgrade` 批量下单
- 下单成功后数据抓取 → 精准推荐成功页 → 好评 → 回首页刷新规则

**不包含：** 旧版单产品 `termV3` → 原生申请页 / `userSubmitV3` 链路（见 `28-印度产品下单完整流程.md`）；复借原生链路（见 `08-复借流程.md`）。抓取与好评细节以交叉文档为准，本节只规定本链路如何调用它们。

**关联文档：**

| 主题 | 文档 |
|------|------|
| 首页 `userStatus` / 弹框链 / Apply 总入口 | `02-首页Loan.md` |
| 数据抓取 device → contact → installApp → ready | `05-数据抓取与通讯录分片.md`、`30-installApp已安装应用上报.md` |
| 定位强抓/非强抓与二次引导 | `12-定位权限处理规范.md`（二次引导挂 keyWindow） |

| 网络签名 / 公共参数 | `00-基础框架/02-基础网络请求规范.md` |
| 字段总表 | `00-全流程字段与判断总表.md` |

## 31.2 端到端流程总览

### 31.2.1 手动精准推荐

```
首页 Apply / 提示语等（非自动下单态）
    ↓
展示匹配中弹框（Matching in progress）
    ↓
POST /app/v3/product/dcRecommend（signed: {}）
    ├─ 10 秒无响应 → 取消请求 → 按 4102007 进无产品页
    ├─ 业务失败 4102007 → 无产品页（notuijie）
    ├─ 其它业务失败 → View Now 页（dhktb）
    ├─ 成功但无产品 → 无产品页
    └─ 成功且有产品 → 精准推荐列表页
            ↓
用户勾选产品 / 调额度 / 选期限 / 勾协议 → Apply
            ↓
定位（§31.8）→ POST /app/v3/order/userSubmitDcUpgrade（批量）
            ↓
取全部 orderId；抓取用首个 orderId（§31.9）
            ↓
替换导航栈为精准推荐成功页（§31.10）
            ↓
Confirm → 好评（如需）→ pop 回首页根（由 Home viewWillAppear 刷新，不发 HomeShouldRefresh）
```

### 31.2.2 首页自动下单

```
满足自动下单态（§31.3）且触发（§31.3.2）
    ↓
独立协调器防重入；本轮跳过首页弹框链
    ↓
展示匹配中弹框 → 同 §31.2.1 的 dcRecommend（含 10s 超时与错误页分流）
    ↓
成功有产品：全部产品选中 + 各产品最大金额档 + 该档最高期限 + 视为已勾协议
    ↓
不进入列表交互页；直接定位 → userSubmitDcUpgrade → 抓取 → 成功页
    ↓
dcRecommend 失败/空态：push 与手动一致的错误/空态页后结束本轮
定位强抓取消：留在首页，不立刻补弹框链
```

## 31.3 自动下单态与触发

### 31.3.1 判定条件（须同时成立）

来自 `/app/v3/user/suphome`：

| 字段 | 条件 |
|------|------|
| 登录态 | 已登录 |
| `hasOrder` | `== 0`（兼容数字 / 数字字符串） |
| `userStatus` | `== 20`（待申请） |
| `firstLoanOptionLine` | 去空白后 **忽略大小写** 等于 `"system"` |

`suphome` 更新后重算只读布尔（如 `isAutoOrderEligible`）。**不依赖** `/app/v3/product/list`（首页不再请求该接口）。

> 说明：自动下单对 `dcRecommend` 返回的 **全部可下单产品** 批量提交。

### 31.3.2 触发场景（仅这两种）

1. **KYC 完成返回首页**  
   - KYC 收尾置会话标记（如 `pendingAutoOrderAfterKYC`）。  
   - 首页跑完流水线后：若 `isAutoOrderEligible == true` 且 **消费** 该标记 → 立即启动自动下单，并 **跳过本轮弹框链**。  
   - 先确认 eligible 再消费标记，避免未达标误清标记。  
   - **不**因冷启动、普通 Tab 切回仅因条件成立就自动开跑。

2. **自动下单态下用户点击首页主申请入口**（如 Apply Now / 与提示语同路由）  
   - 直接进自动下单协调器，**不**再进手动匹配 → 列表交互。  
   - 失败留在首页或已 push 的错误页时，条件仍成立可再次点击重试。

### 31.3.3 与弹框链关系

- 自动下单启动成功：**本轮不再跑** 版本 / 待提现 / 复借 / 通知弹框链。  
- 失败结束：可不立刻补弹框链（避免强抓用户去开定位时被打断）。  
- 与复借候选同时出现时：**自动下单优先于弹框链**。

### 31.3.4 防重入

同进程同时仅允许一条自动下单在跑；已在跑时再次触发视为已接管（返回成功接管，不重复启动）。

## 31.4 匹配中弹框 + dcRecommend

### 31.4.1 匹配中弹框

- 深色遮罩 + 文案 + 图标资源 `pipeitime_icon`。  
- 标题：`Matching in progress`  
- 正文：`We are reviewing your profile to provide more suitable products. Priority matching in progress, estimated time: 10 seconds...`  
- **点击遮罩不关闭**；仅在请求结束（成功/失败/超时）后关闭。  
- 挂载：当前页 window 或主视图；自动下单同样展示。

### 31.4.2 接口

| 项 | 口径 |
|----|------|
| 路径 | `POST /app/v3/product/dcRecommend` |
| signed | `{}`（空对象即可；公共参数仍由网络层附带） |
| unsigned | `nil` |
| Loading HUD | **不**用全局 Loading；用匹配中弹框 |
| 错误 Toast | 本链路关闭（由结果页承接） |

### 31.4.3 10 秒超时（必须）

- 自发起请求起 **10 秒** 仍无终态响应：  
  1. **中断/取消** 该次请求（后续迟到回调不得再进成功/失败 UI）；  
  2. 关闭匹配弹框；  
  3. 按 **`4102007`** 分流进入 **无产品推荐页**（与真实返回 `4102007` 一致）。  
- 超时错误文案可为空；无产品页优先后端文案，空则用默认文案（§31.5.3）。

### 31.4.4 成功 / 失败分流

关闭匹配弹框后：

| 情况 | 页面 |
|------|------|
| 网络/业务错误且 `resultCode == 4102007`（含超时伪造成） | 无产品页（`notuijie_icon`） |
| 其它业务错误码（如 `4102006` 等） | View Now 页（`dhktb_icon`） |
| 成功但 `productInfoList`/`productList` 为空或无可解析产品 | 无产品页 |
| 成功且至少 1 个可下单产品 | 列表页（自动下单则不展示列表，直接选额选期提交） |

手动入口进错误页时，须带上首页上下文：

- `homePromptCopy`：首页顶部 `promptCopy`  
- `homeUserStatus`：首页当前 `userStatus`  

供 View Now 文案与订单筛选项使用。

## 31.5 结果页三种页态

### 31.5.1 列表页（有产品）

见 §31.6、§31.7。

### 31.5.2 View Now 页（其它错误码）

- 图标：`dhktb_icon`  
- 文案：优先首页 `promptCopy`；否则接口 `resultMsg`；再否则无产品默认文案  
- 按钮：`View Now`  
- 点击：切到 **Order Tab**，**仅按进页时首页接口 `userStatus`** 选中订单列表筛选项（不看错误码、不读实时刷新态）：

| 首页 `userStatus` | 订单列表 `orderStatus` |
|-------------------|------------------------|
| 80 / 81 | `20`（待还款） |
| 41 / 32 / 30 | `10`（提交申请，与首页主按钮一致） |
| 其它（含待申请 20、拒量 51 等） | `30`（Processing） |

切换前先 pop 当前导航至根、展示 TabBar；对订单根页写入筛选项时注意首次 `viewDidLoad` 与 Tab 切换时序（可下一拍再选一次）。

### 31.5.3 无产品页（含 4102007 / 空列表 / 超时）

- 图标：`notuijie_icon`  
- 文案：优先后端 `resultMsg`；空则默认：  
  `You do not currently meet the requirements for this product. Once a more suitable loan product becomes available, we will notify you through the app. Please stay tuned.`  
- **无** View Now 按钮（仅提示）。

## 31.6 dcRecommend 响应解析（列表数据源）

### 31.6.1 产品列表根

- `data` 为字典时：`productInfoList` 优先，否则 `productList`  
- `data` 直接为数组时：视为产品数组  

无有效项 → 无产品页。

### 31.6.2 单产品节点

| 用途 | 字段（兼容别名） |
|------|------------------|
| 产品 ID（必填，否则跳过该产品） | `productId`，其次 `outward` / `beyond`；可从节点或嵌套 `productTermV3Response` 取 |
| 名称 | `productName`（节点或 termV3） |
| Logo | `productLogo` |
| 额度结构 | 优先 `productTermV3Response`；若无嵌套但节点自带 `amountDetailList`，则节点本身当作 termV3 |

### 31.6.3 额度档 `amountDetailList`

- 按 `loanAmount` 数值 **升序** 去重聚合。  
- 若某额度行含非空 `termDetailList`：保留嵌套期限。  
- 若同额度多行为 **扁平**（无嵌套期限）：把同额度行聚合成该档的 `termDetailList`。  
- 无任何有效额度档 → 跳过该产品。

### 31.6.4 期限项（`termDetailList` 或扁平行）常用字段

| 字段 | 用途 |
|------|------|
| `loanAmount` | 展示 / 提交金额 |
| `loanTerm` | **提交** `loanTerms` 优先值；比「最高期限」时优先用此数值 |
| `showTerm` | **展示**用（可补 Days）；提交缺 `loanTerm` 时回落 |
| `EMIs` / `EMITenure` | 判定 EMI；展示「n EMIS」；比期限时可作回落数值 |
| `EMIAmount` / `EMIRepayDate` | Loan details 弹框 EMI 行 |
| `feeAmount` | 服务费 |
| `arrivalAmount` | 到账金额；缺省可用 `loanAmount - feeAmount` |
| `interestAmount` / `taxAmount` | Interest / GST |
| `borrowingDate` / `repaymentDate` | 申请日 / 到期日 |

### 31.6.5 银行卡

- 从 `bankCardList` 取 **首条**（可在 data 根、产品节点或 `productTermV3Response`）。  
- 提交用 `bindId` → unsigned `bankCardBindId`（见 §31.7.5）。  
- 展示卡号：`accountNo` 或 `cardNo`，掩码形如 `9801 **** **** 4823`（≥8 位数字时头 4 + 尾 4）。

### 31.6.6 进入列表时的默认选中

每个可下单产品：

- `selected = YES`  
- 额度档 = **最大** `loanAmount` 档（升序数组最后一项）  
- 期限 = 该档 `termDetailList` 内按 §31.7.3 规则的 **最高期限**  
- 协议默认勾选 `agreed = YES`（列表页用户可取消）

## 31.7 精准推荐列表页交互与提交

### 31.7.1 UI 要点（逻辑层）

- 产品卡：勾选、Logo、名、最大可借展示、当前额度滑档（多档）、到账/费用等摘要、期限行（可点选，多期限时弹选择框）。  
- 期限行标题：EMI 为 `EMIs`，否则 `Loan term`；选择框标题：EMI 为 `Select EMIs`，否则 `Select the loan term`。  
- EMI 展示：`{n} EMIS`；非 EMI 天数展示可用 `showTerm`（如 `180 (Days)` 类格式按设计）。  
- Loan details：居中明细弹框（Cancel）；行字段同 §31.6.4（EMI 时多 1st EMI Date / EMI Amount）。  
- 底部汇总：已选产品合计 Loan amount / Fee / Arrival（Fee = 合计 loan − 合计 arrival，小于 0 记 0）。  
- 银行卡展示区：有卡显示掩码；无卡按设计隐藏或占位。  
- 协议：文案链接触发配置 Web，`configKey = conditionsHref`，标题 `Terms Of The Loan`。  
- 主按钮：`Apply Now`；提交/定位中禁用并降透明度；防连点。

### 31.7.2 勾选与额度/期限变更

- 切换勾选、改额度档、改期限：提交中禁止。  
- **改额度档后必须重新应用该档最高期限**（默认选中最高，用户仍可再改）。  
- Apply 前校验：  
  - 至少选中 1 个产品，否则 Toast `请至少选择一个`  
  - 必须勾选协议，否则 Toast `Please agree to the Terms Of The Loan before applying.`  
- `canApply` 逻辑：已勾协议且非提交中（选中数在点击时再校验）。

### 31.7.3 「最高期限」比较规则（同一金额档内）

对期限字典取可比数值，**越大越高**：

1. `loanTerm`（>0）  
2. 否则 `showTerm` 数值  
3. 否则 `EMIs` / `EMITenure`  
4. 否则从 `showTerm` 字符串抽数字  

**不要**用产品级无关字段覆盖「当前金额档内」的比较。

### 31.7.4 提交用期限值

对每个已选产品：取 **当前金额档** 内最高期限项的 `loanTerm`；缺省回落 `showTerm`，再回落 EMI 数值字符串。  
展示与提交可不同：展示用 `showTerm`，提交用 `loanTerm`（例如展示 361、提交 360）。

### 31.7.5 下单接口 `userSubmitDcUpgrade`

| 项 | 口径 |
|----|------|
| 路径 | `POST /app/v3/order/userSubmitDcUpgrade` |
| HUD | `Processing...`（本链路自管 Loading；`showLoading` 覆盖为关，避免双 HUD） |
| 错误 Toast | 开（走网络层统一） |

**signed（参与签名）：**

| 字段 | 规则 |
|------|------|
| `productIds` | 已选产品 ID，英文逗号拼接，顺序与金额/期限一致 |
| `loanAmounts` | 对应 `loanAmount` 原始字符串，逗号拼接 |
| `loanTerms` | 对应提交用期限（§31.7.4），逗号拼接 |
| `longitude` | 六位小数字符串；无坐标时 `"-360.000000"` |
| `latitude` | 同上 |
| `imei` | 固定字面量字符串 `"null"`（不是 JSON null） |
| `serialNo` | 与公共参数 `deviceId` **完全一致** |

**unsigned（不进签名，写入 data）：**

| 字段 | 规则 |
|------|------|
| `bankCardBindId` | 有 bindId 才传；取自推荐数据银行卡首条 |

**禁止**传 `orderType`（本链路为普通首贷批量，非复借）。

**成功：**

- 从 `response.data` 递归收集全部订单号（兼容键：`orderId` / `currentOrderId` / `orderIdList` / `orderList` / `records` / `list` / `objection` 等；去重保序）。  
- `resultCode == 200`：无论 `list` 是否有值，**不**错误提示。  
- 有订单号 → 进入抓取（§31.9），**保留全部 orderId 给成功页**。  
- 一个都没有 → 不 Toast，恢复可点，不进入抓取。

**失败：** Toast 后恢复提交态与按钮。

### 31.7.6 自动下单与列表页的差异（提交前）

| 项 | 手动列表 | 自动下单 |
|----|----------|----------|
| UI | 展示列表，用户可改 | 不展示列表 |
| 选品 | 用户勾选 | **全部**可下单产品选中 |
| 额度/期限 | 用户可改；默认最大额+最高期 | 强制最大额+最高期 |
| 协议 | 用户可取消 | 强制 `agreed = YES` |
| 定位与提交 | 点 Apply 后 | dcRecommend 成功后立刻 |
| 失败页 | push 错误/空态 | 同左 |
| 成功页 | 同 | 同 |

两侧共用同一套 ViewModel 解析与 `userSubmitDcUpgrade` 组包逻辑。

## 31.8 定位（Apply / 自动下单提交前）

配置键：`retrieveMobileContact`（`/app/v3/app/config`）。

| 值 | 模式 |
|----|------|
| `1` 或 `2` | **强抓**：必须真实坐标才可提交 |
| `0`（及其它） | **非强抓**：无权限/失败可传 `-360.000000` 继续 |

### 31.8.1 强抓（`retrieveMobileContact == 1` 或 `== 2`）状态机

| 时机 | 权限状态 | 行为 |
|------|----------|------|
| 点击申请 / 自动下单 | `NotDetermined` | 弹**系统**定位授权 |
| 系统弹窗**首次拒绝** | → `Denied` | **结束本轮、禁止下单**（不得 `-360`）；**不弹**自定义框；**停留当前页**（列表页 / 首页） |
| **再次**点击申请 / 再次自动下单 | `Authorized` | 取真实坐标 → **直接下单** |
| **再次**点击申请 / 再次自动下单 | `Denied` / `Restricted` | 弹**自定义**定位引导（keyWindow）；Confirm 去设置；Cancel/Confirm 后结束本轮并留当前页 |
| 去设置开启后再次申请 | `Authorized` | 取点 → 直接下单 |

### 31.8.2 非强抓（`0`）

- 拒绝或失败：`lng/lat = -360.000000` 可继续提交。  
- 不强制自定义定位引导。

### 31.8.3 其它

1. 定位更新：缓存可用则用（`horizontalAccuracy ∈ (0, 5000)` 且年龄 `< 600s`），否则 `startUpdatingLocation`；超时约 **20s**。  
2. 坐标六位小数（与下单页一致）。  
3. 埋点：授权成功 **15**；拒绝 **16**。  
4. 自动下单：匹配弹框保持到定位结束；二次引导叠 keyWindow，勿用 HUD 挡住。  
5. 列表页 / 自动下单定位权限失败：**不 Toast**，恢复按钮（列表）或结束本轮（自动下单），**不 pop**。

## 31.9 下单后数据抓取

- 协调器：与产品下单 / 复借共用的订单数据抓取流程（见 `05`、`30`）。  
- **抓取使用的 `orderId`**：批量结果中的 **第一个**。  
- **成功页使用的订单号列表**：提交返回的 **全部** orderId（去重保序）。  
- 抓取 UI：设备阶段 HUD；通讯录阶段起抓取进度弹框（与精准推荐同款资源/交互）。  
- 通讯录强抓二次引导、`allowContact`、印度号码清洗、分片字段等 **严格按 `05` / `30`**，本节不重复。  
- 抓取失败：恢复列表可再申请（手动）；自动下单结束本轮（success=NO）。  
- 抓取成功：进入成功页（§31.10）。

## 31.10 精准推荐成功页

### 31.10.1 进入方式

- 用成功页 **替换** 当前列表页（或自动下单时 push 成功页）：导航栈去掉列表页，压入成功页，避免返回再进列表。  
- 手动列表进成功页：过程中不提前刷首页；**自动下单**在本轮 `finish`（含进成功页）时发 `HomeShouldRefresh`（§31.12）。

### 31.10.2 拉详情

对每个 `orderId` **串行**：

| 项 | 口径 |
|----|------|
| 路径 | `POST /app/v3/order/detailV2` |
| signed | `objection` = orderId（空则兜底 `"1"`；与项目订单详情 wire 字段一致） |
| unsigned | `appType` = `"DC"` |
| 单笔失败 | 跳过该笔，继续后续；全部失败可提示加载失败 |

### 31.10.3 单笔展示字段

从 `product` / `productInfo` + `orderDetail`（或 data 本身）解析：

| UI | 字段 |
|----|------|
| 产品名 / Logo | `productName` / `productLogo` |
| 状态徽标 | `orderStatus` → 项目订单状态样式 |
| Loan amount | `loanAmount`（带 ₹） |
| EMI 场景（`EMIs > 0`） | `EMIRepayDate`、`EMIAmount`、`{n} EMIs` |
| 非 EMI | `loanTerm` 或 `showTerm`（纯数字则补 ` Days`） |
| Amount received | `receiptAmount` 或 `arrivalAmount` |
| Service fee / Interest / GST | `feeAmount` / `interestAmount` / `taxAmount` |
| Date of application | `applyDate` 或 `borrowingDate` |

日期：支持毫秒/秒时间戳与常见日期字符串，展示 `MMM dd, yyyy`。

### 31.10.4 底部操作

- **Feedback**：进反馈页（退出风格 pop 到导航根）；**进入反馈页后**按 Confirm 同口径弹好评引导（`13`，`userType=0` 首贷；安装周期内只弹一次）。  
- **Confirm**：先走好评引导（同上）；完成后 `popToRoot` 回首页。  
- 回首页：**只依赖** Home `viewWillAppear` / 导航栈变化刷新；**不要**在成功页 Confirm / 进成功页时发 `HomeShouldRefresh`。

## 31.11 首页手动入口路由摘要

在非 KYC / 非订单分流等状态下（详见 `02-首页Loan.md` §2.3.3）：

1. 若 `isAutoOrderEligible` → 启动自动下单（§31.3）。  
2. 否则 → 启动手动精准推荐匹配流程（§31.4）。  

首页当前可不展示产品列表；若仍保留产品点击入口，自动下单态下点击亦走自动下单协调器（与主 Apply 一致），**不再**进旧 `termV3` 申请页。

## 31.12 刷新与通知纪律

| 时机 | 是否发 `HomeShouldRefresh` |
|------|----------------------------|
| 匹配中 / dcRecommend 过程 | 否 |
| 提交成功、抓取过程中 | 否 |
| **自动下单本轮结束**（`finishWithSuccess`：进成功页 / dcRecommend 结果页 / 或留首页中断） | **是** |
| 成功页 Confirm pop 回根 | 否（Home `viewWillAppear` 仍会再刷一次） |
| KYC 完成标记待自动下单 | 按首页会话标记，流水线结束后启动 |

从其它 Tab 切回 Loan 的刷新仍按首页既有规则（`02`）。

## 31.13 接口一览（本模块）

| 接口 | 场景 | signed 要点 | unsigned 要点 |
|------|------|-------------|---------------|
| `/app/v3/user/suphome` | 自动下单资格 | 公共 | `hasOrder` / `userStatus` / `firstLoanOptionLine` / `promptCopy` 等 |
| `/app/v3/product/dcRecommend` | 匹配推荐 | `{}` | —；**10s 超时→4102007 页** |

| `/app/v3/mobile/device` 等 | 抓取 | 见 `05` | 见 `05`/`30` |
| `/app/v3/order/detailV2` | 成功页 | `objection`=orderId | `appType=DC` |

## 31.14 自测清单
