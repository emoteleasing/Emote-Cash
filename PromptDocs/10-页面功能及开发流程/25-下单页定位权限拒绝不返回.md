# 下单页定位权限拒绝不返回

## 修改概述

修改产品下单页面的定位权限处理逻辑：
- 定位权限拒绝时不返回上一页
- 停留在当前页面，允许用户重新尝试
- 适用于首次系统弹框和自定义二次弹框

## 0. H5 回传 payload（与 `04` 提示词一致，产品申请 H5 / 订单详情 H5）

| 场景 | 回传 |
|------|------|
| 首次系统弹窗拒绝 | 字面量 `""` |
| 强抓且拿不到坐标 / b3 Cancel / b3 Go to Settings | 字面量 `""` |
| 非强抓、非首次、无权限 | `{"longitude":"-360","latitude":"-360"}` |
| 有真实坐标 | `{"longitude":"…","latitude":"…"}` |

**禁止** `{"longitude":"","latitude":""}`。实现：`HQTProductApplyLocationBridge`。

## 1. 修改背景

### 1.1 原有逻辑

**强抓模式（retrieveMobileContact = 1）**：
- 首次系统弹框拒绝 → 返回上一页 ❌
- 自定义二次弹框点击取消 → 返回上一页 ❌
- 自定义二次弹框去设置 → 停留当前页面 ✓

**非强抓模式（retrieveMobileContact = 0）**：
- 首次系统弹框拒绝 → 使用默认坐标继续 ✓
- 不显示自定义二次弹框

### 1.2 新逻辑

**强抓模式（retrieveMobileContact = 1）**：
- 首次系统弹框拒绝 → **停留当前页面** ✓
- 自定义二次弹框点击取消 → **停留当前页面** ✓
- 自定义二次弹框去设置 → 停留当前页面 ✓

**非强抓模式（retrieveMobileContact = 0）**：
- 首次系统弹框拒绝 → 使用默认坐标继续 ✓
- 不显示自定义二次弹框

## 2. 代码修改

### 2.1 首次系统弹框拒绝处理

**文件**：`HQTeConsmpton/Home/HQTProductApplyViewController.swift`

**方法**：`locationManagerDidChangeAuthorization(_:)`

**修改前**：
```swift
// 强抓模式下，首次拒绝返回上一页
if mode == 1 {
    print("强抓模式，首次拒绝返回上一页")
    self.navigationController?.popViewController(animated: true)
} else {
    // 非强抓模式，使用默认坐标继续提交
    print("非强抓模式，首次拒绝使用默认坐标")
    self.sendUserSubmitV3(longitude: "-360", latitude: "-360")
}
```

**修改后**：
```swift
// 强抓模式下，首次拒绝也停留在当前页面（不返回）
if mode == 1 {
    print("强抓模式，首次拒绝停留当前页面")
    // 不执行任何操作，停留在当前页面
} else {
    // 非强抓模式，使用默认坐标继续提交
    print("非强抓模式，首次拒绝使用默认坐标")
    self.sendUserSubmitV3(longitude: "-360", latitude: "-360")
}
```

**说明**：
- 移除了 `popViewController` 调用
- 解锁提交锁，停止 loading
- 用户可以重新点击"Apply now"按钮

### 2.2 自定义二次弹框取消处理

**文件**：`HQTeConsmpton/Home/HQTProductApplyViewController.swift`

**方法**：`handleLocationDenied()`

**修改前**：
```swift
onCancel: { [weak self] in
    print("用户点击取消")
    guard let self = self else { return }
    self.isLocationAlertShowing = false
    self.submitLock.unlock()
    self.spinner.stopAnimating()
    
    // 强抓模式下，点击取消返回上一页
    if mode == 1 {
        self.navigationController?.popViewController(animated: true)
    }
}
```

**修改后**：
```swift
onCancel: { [weak self] in
    print("用户点击取消")
    guard let self = self else { return }
    self.isLocationAlertShowing = false
    self.submitLock.unlock()
    self.spinner.stopAnimating()
    
    // 点击取消停留在当前页面（不返回）
    print("停留在当前页面，用户可重新尝试")
}
```

**说明**：
- 移除了 `popViewController` 调用
- 移除了强抓模式判断
- 解锁提交锁，停止 loading
- 用户可以重新点击"Apply now"按钮

## 3. 用户流程

### 3.1 强抓模式 - 首次系统弹框拒绝

```
用户点击 Apply now
    ↓
检查协议 ✓
    ↓
检查银行卡 ✓
    ↓
获取提交锁 ✓
    ↓
检查定位权限（未决定）
    ↓
显示系统权限弹框
    ↓
用户点击"不允许"
    ↓
停留在当前页面 ✓
    ↓
用户可以：
  - 重新点击 Apply now
  - 返回上一页
  - 修改其他信息
```

### 3.2 强抓模式 - 自定义二次弹框取消

```
用户点击 Apply now
    ↓
检查定位权限（已拒绝）
    ↓
显示自定义二次弹框
    ↓
用户点击"Cancel"
    ↓
停留在当前页面 ✓
    ↓
用户可以：
  - 重新点击 Apply now
  - 返回上一页
  - 修改其他信息
```

### 3.3 强抓模式 - 自定义二次弹框去设置

```
用户点击 Apply now
    ↓
检查定位权限（已拒绝）
    ↓
显示自定义二次弹框
    ↓

    ↓
跳转到系统设置
    ↓
用户授权定位
    ↓
返回应用
    ↓
停留在当前页面 ✓
    ↓

  - 重新点击 Apply now（此时会成功）
  - 返回上一页
```

### 3.4 非强抓模式 - 首次系统弹框拒绝

```
用户点击 Apply now
    ↓
检查定位权限（未决定）
    ↓
显示系统权限弹框
    ↓
用户点击"不允许"
    ↓
使用默认坐标 (-360, -360)
    ↓
继续提交订单 ✓
    ↓
进入数据抓取流程
```

## 4. 状态管理

### 4.1 关键标志位

| 标志位 | 作用 | 重置时机 |
|--------|------|---------|
| `isWaitingForLocationToSubmit` | 标记是否正在等待定位以提交订单 | 定位成功/失败后 |
| `isFirstTimeLocationRequest` | 区分首次和非首次请求 | 首次请求后 |
| `isLocationAlertShowing` | 防止重复显示弹框 | 弹框关闭后 |
| `submitLock` | 防止重复提交 | 提交失败/取消后 |

### 4.2 状态重置

**首次系统弹框拒绝**：
```swift
self.isFirstTimeLocationRequest = false
self.isWaitingForLocationToSubmit = false
self.submitLock.unlock()
self.spinner.stopAnimating()
```

**自定义二次弹框取消**：
```swift
self.isLocationAlertShowing = false
self.submitLock.unlock()
self.spinner.stopAnimating()
```

**说明**：
- 所有标志位都正确重置
- 提交锁已解锁，允许重新提交
- Loading 已停止，UI 恢复正常

## 5. 与其他功能的关系

### 5.1 与银行卡检查的关系

**检查顺序**：
1. 协议勾选检查
2. 银行卡检查
3. 获取提交锁
4. **定位权限检查**
5. 提交订单

**说明**：
- 定位权限检查在银行卡检查之后
- 定位权限拒绝不影响银行卡检查
- 用户可以在停留页面时修改银行卡

### 5.2 与复借流程的关系

**复借流程**：
- 复借下单也使用相同的定位权限逻辑
- 复借定位拒绝也停留在当前页面
- 复借弹框不受影响

### 5.3 与强抓/非强抓模式的关系

| 模式 | 首次拒绝 | 非首次拒绝 | 说明 |
|------|---------|-----------|------|
| **强抓（mode=1）** | 停留当前页面 | 显示二次弹框 | 必须获取真实坐标 |
| **非强抓（mode=0）** | 使用默认坐标继续 | 使用默认坐标继续 | 尽量获取真实坐标 |

## 7. 注意事项

### 7.1 用户体验

**优点**：
- 用户不会被强制返回上一页
- 用户可以重新尝试，无需重新导航
- 用户可以在当前页面修改信息
- 减少用户操作步骤

**注意**：
- 确保提交锁正确解锁
- 确保 loading 正确停止
- 确保标志位正确重置

### 7.2 状态一致性

**关键点**：
- 定位拒绝后，所有状态必须重置
- 提交锁必须解锁，否则无法重新提交
- Loading 必须停止，否则 UI 卡住
- 标志位必须重置，否则逻辑错误
