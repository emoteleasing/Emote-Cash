# 08. 复借（Reloan）流程

## 8.1 复借引导开关
- 配置：`dynamicParameter.fjtip`
- fjtip：
  - on：允许展示复借入口
  - off：跳过复借逻辑

## 8.2 候选获取与筛选

### 8.2.1 候选接口
- 接口：`/app/v3/product/state`
- 请求参数：
  - **首页 (ee1)**：`signedData: [:]`, `unsignedData: [:]`（不传 productId）
  - **下单页 (ee2)**：`signedData: [:]`, `unsignedData: ["productId": productId]`（传 productId，不加密）
  - **订单详情 (ee3)**：`signedData: [:]`, `unsignedData: ["productId": productId]`（传 productId，不加密）

### 8.2.2 筛选规则
- 在返回结构 **`data`** 中解析（兼容两种形态）：
  1. **扁平**：存在 **`data.amountDetailList`**（数组）时，遍历元素，取第一个 **`userType == 2`** 的条目作为复借候选（行内通常含 `productId`、`productName`、`loanAmount` 等）。
  2. **嵌套**：存在 **`data.list`**（数组）时，在每个元素的 **`amountDetailList`** 中查找 **`userType == 2`**，命中则取 **该 list 元素**（外层产品对象）作为复借候选。
- 取第一个候选作为本次复借产品（与首页、弹框、下单页返回逻辑共用解析规则时应对齐）。

### 8.2.3 响应格式
```json
{
  "resultCode": 200,
  "resultMsg": "SUCCESS",
  "data": {
    "amountDetailList": [
      {
        "productId": "DC-CPPD90V1",
        "productName": "DC-CPPD90V1 合规",
        "productLogo": "https://...",
        "loanAmount": "8000.00",
        "userType": 2
      }
    ]
  }
}
```

## 8.4 Apply 后的完整链路

### 8.4.1 流程图（首页 ee1，PHI352-DC 实现）

```
用户点击 Apply Now（HQTReloanGuideDialog，按钮锁定；弹框不关闭）
    ↓
1. HQTProductApplyHandler.fetchTermV3(enterSource: .reloan)
    ├─ 失败 / 6234303 等 → resetActiveReloanApplyInteraction，解锁，弹框仍展示
    └─ 成功 ↓
2. HQTReloanFlowCoordinator.start(termData)
    ├─ pickAmountAndTerm：最高金额档 + 该档最低期限（见 §8.4.4）
    └─ 解析失败 → Toast，解锁，弹框仍展示
    ↓
3. 定位（HQTProductApplyLocationBridge.resolveForNativeOrderSubmit）
    ├─ 全程不展示 HUD（避免挡住 keyWindow 上定位二次弹框）
    ├─ 强抓：须真实坐标；b3 挂 keyWindow，叠在复借弹框上（§8.9.3）
    ├─ 强抓取消/失败 → resetActiveReloanApplyInteraction，弹框仍展示
    └─ 非强抓无坐标 → lon/lat = -360 继续
    ↓
4. dismissActiveReloanGuideDialog() → showLoading → userSubmitV3（orderType=1）
    ↓
5. 解析 orderId（HQTAPIFieldMapper.orderIdString，含 wire substantial 等）
    ↓
6. HQTOrderDataCaptureCoordinator：device（HUD）→ 通讯录权限 → 进度条 → contact? → ready
    ├─ 强抓通讯录未完全授权 → 抓取失败（Toast；无 H5 uploadDataFail）
    ├─ iOS 18+ Limited 按未授权（见 §8.11、05 §5.3）
    └─ 成功 ↓
7. HQTProductApplyFeedbackGuide（可选）→ Success 弹框
    ↓
8. Confirm → HQTHomeLoanPresenter.runPipeline(.afterReloanFlow) 刷新首页
```

**其它场景（ee2/ee3）**：下单页返回、订单详情进入的复借弹框与成功后跳转规则见 §8.6.1；抓取与通讯录口径与首页一致，协调器同为 `HQTOrderDataCaptureCoordinator`。

### 8.4.2 步骤1：拉取 termV3
- **接口**：`/app/v3/product/termV3`
- **参数**：
  - `signedData: ["productId": productId]`
  - `unsignedData: nil`
  - `requireBusinessSuccess: false`

### 8.4.3 步骤3：定位权限处理

#### 定位权限要求

复借流程的定位权限处理**与产品下单页面完全一致**：

##### 强抓模式（retrieveMobileContact = 1）

| 场景 | 行为 | 说明 |
|------|------|------|
| **首次请求被拒绝** | 返回上一页（首页除外） | 不显示二次弹框，直接返回 |
| **已拒绝 + 点击取消** | 返回上一页（首页除外） | 显示二次弹框后点击取消 |
| **已拒绝 + 点击去设置** | **停留当前页面** | 用户从设置返回后可以重新尝试 |
| **授权成功** | 获取位置并提交订单 | 正常流程 |
| **定位失败（GPS）** | 显示重试弹框 | 提供重试选项 |

##### 非强抓模式（retrieveMobileContact = 0）

| 场景 | 行为 | 说明 |
|------|------|------|
| **已授权** | 获取真实坐标并提交 | 与产品下单 H5 一致 |
| **未决定** | 请求系统定位权限 → 授权则取真实坐标 | 与产品下单 H5 一致 |
| **拒绝 / 定位失败** | 使用默认坐标 `-360,-360` 仍可提交 | 与产品下单 H5 一致 |

#### 实现要点

1. **定位管理器配置**：
   - 设置代理
   - 配置精度：`kCLLocationAccuracyHundredMeters`
   - 配置距离过滤：100米

2. **标志位管理**：
   - `isWaitingForLocationToSubmit`：标记是否正在等待定位以提交订单
   - `isLocationDataSent`：防止重复发送位置数据
   - `isFirstTimeLocationRequest`：区分首次和非首次请求
   - `isLocationAlertShowing`：防止重复显示弹框

3. **回调管理**：
   - 使用回调保存提交逻辑
   - 定位成功/失败后调用回调并清空

4. **与产品下单页面的一致性**：
   - 使用相同的定位权限处理逻辑
   - 使用相同的二次弹框提示
   - 使用相同的返回行为

#### 首页复借的特殊性

首页是根页面，不能返回上一页，因此：
- 强抓模式下拒绝后**留在首页**（不返回，因为首页就是根页面）
- 用户可以重新尝试或选择其他产品

### 8.4.4 步骤 2–4：策略、定位、提交订单

#### termV3 策略（`HQTReloanFlowCoordinator.pickAmountAndTerm`）
- **金额列表**：`data.amountDetailList` 或 wire `lamp`
- **金额字段**：`loanAmount` / `review` / `certain` / `furnish`（取第一个非空）
- **期限列表**：`termDetailList` / wire `mission`
- **展示期限**：`showTerm` / `brick` / `examination`
- **规则**：金额降序取第一档；该档内期限取数值最小

#### 提交复借订单
- **金额选择**：取最高金额档（降序第一档）
  ```swift
  let sortedAmounts = amountList.sorted {
      loanAmountInt(from: $0) > loanAmountInt(from: $1)
  }
  let highestAmount = sortedAmounts.first
  ```
- **期限选择**：在该金额档内取最低期限（数值最小）
  ```swift
  let lowestTerm = termList.min { term1, term2 in
      extractNumericValue(from: term1) < extractNumericValue(from: term2)
  }
  ```

- **接口**：`/app/v3/order/userSubmitV3`
- **定位权限处理**：
  - **强抓模式（retrieveMobileContact = 1）**：
    - 必须获取真实定位坐标
    - 权限处理流程与产品下单页面完全一致
    - 首次拒绝：返回上一页（首页除外）
    - 已拒绝 + 点击取消：返回上一页（首页除外）
    - 已拒绝 + 点击去设置：停留当前页面
  - **非强抓模式（retrieveMobileContact = 0）**：
    - 使用默认坐标 `"-360", "-360"`
    - 不请求定位权限
- **参数**（签名字段明细见 `02-基础网络请求规范.md` §2.4.4）：
  ```swift
  // 参与签名（6 字段）；经纬度必须为 6 位小数字符串，与 JSON body 一致
  let signed = HQTAPIFieldMapper.userSubmitV3SignedData(
      productId: productId,
      loanAmount: loanAmount,
      longitude: longitude,  // 强抓：真实坐标；非强抓：-360 → "-360.000000"
      latitude: latitude
  )
  let unsigned: [String: Any] = [
      "showTerm": showTerm,
      "orderType": "1"  // 复借固定为字符串 "1"，不参与签名
  ]
  ```
- **requireBusinessSuccess**: `false`

### 8.4.5 步骤 6–9：数据抓取（`HQTOrderDataCaptureCoordinator`）

**协调器**：`HQTOrderDataCaptureCoordinator`（与产品申请 H5、订单详情 H5 共用；首页复借 **不** 传 `failOnContactsSecondaryInteraction`，默认 `false`）。

**顺序**：
1. `POST /app/v3/mobile/device`（`showLoading` / `hideLoading`；与通讯录无关）
2. `resolveContactsThenScrape`：系统通讯录权限（`CNContactStore`；含 iOS 18+ `.limited` 处理，见 §8.11）
3. 权限已决后展示 `HQTScrapeProgressDialog`（仅通讯录 + ready）
4. 有有效联系人则分片 `POST /app/v3/mobile/contact`，否则跳过
5. `POST /app/v3/order/ready`（`allowContact`：`""` 或 `"2"`）
6. 失败：`completion(false)` → 复借链路 Toast / 解锁，**不** 调 H5 `uploadDataFail`

**入口（首页复借）**：
```swift
// HQTReloanFlowCoordinator.beginDataCapture
dataCaptureCoordinator.start(orderId: orderId, host: host, overlayHostView: overlay) { success in
    // success → 好评(可选) + Success 弹框；failure → unlock + isNotificationDeferred = false
}
```

**orderId**：从 `userSubmitV3` 响应 `data` 读取，须兼容逻辑字段与 wire 字段：
```swift
HQTAPIFieldMapper.orderIdString(from: envelope.data) // orderId / objection / orderNo / substantial
```

### 8.4.7 步骤11：好评引导（可选，在成功弹框之后）

用户点击成功弹框的 Confirm 后，检查是否显示好评弹框：

#### 好评条件
- 本次安装周期未显示过好评弹框
- 好评模式配置（`feedbackGuidance`）：
  - `1`：总是显示
  - `2`：仅非首单显示（复借视为非首单）
  - 其他：不显示

#### 好评弹框交互
1. **用户评分 ≥ 4 星**：
   - 跳转 App Store 评分
   - 标记已显示好评
   - 完成流程，刷新首页

2. **用户评分 < 4 星（如3星）**：
   - 显示感谢弹框（"Success!" - "We sincerely thank you for your feedback!..."）
   - 用户点击 Confirm 后完成流程，刷新首页

3. **用户关闭好评弹框**：
   - 标记已显示好评
   - 完成流程，刷新首页

#### 完整流程示例（3星评价）
```
数据抓取完成
    ↓
显示复借成功弹框（第1个弹框）
  标题："Success!"
  内容："Your application is under review..."
    ↓
用户点击 Confirm
    ↓
检查好评条件（满足）
    ↓
显示好评弹框（第2个弹框）
  五星评分条 + Submit 按钮
    ↓
用户选择3星并点击 Submit
    ↓
显示感谢弹框（第3个弹框）
  标题："Success!"
  内容："We sincerely thank you for your feedback!..."
    ↓
用户点击 Confirm
    ↓
完成流程，刷新首页
```

#### 持久化存储
- Key：`"HQT_feedbackGuidanceShownOnce"`
- 一旦显示过好评弹框，应用内不再显示
- 三个场景（首页复借、下单页、订单详情）使用统一的key

#### 实现要点（`HQTReloanFlowCoordinator.showReloanCompletion`）
```swift
/// §8.8 成功弹框 → 好评（可选）→ 刷新首页
private func showReloanCompletion(
    productId: String,
    termData: [String: Any],
    host: HQTBaseViewController,

    let pipelineKey = "reloan_pipeline_\(productId)"

        primaryTitle: "Confirm",

            HQTProductApplyFeedbackGuide.presentAfterSuccessIfNeeded(
                termData: termData,
                in: host.view.window ?? host.view,
                onFinished: finishFlow
            )
        }
    )
}
```

## 8.5 防连点与收口规则
- 复借弹框 Apply 按钮必须防连点锁定（`HQTActionLock`）
- 锁定解除必须发生在"异步流程提前结束或失败"的对应收口处
- 成功路径通常由业务链路关闭弹框后自然结束，无需在弹框内部重复解锁

## 8.6 实现要点

private func parseReloanCandidate(from envelope: HQTAPIEnvelope) -> (productId: String, productName: String, productLogoURL: String?, amountText: String)? {
    guard let obj = envelope.dataObject else { return nil }
    
    if let amountDetailList = obj["amountDetailList"] as? [[String: Any]] {
        return parseFromAmountDetailList(amountDetailList)
    }
    return nil
}

private func parseFromAmountDetailList(_ amountDetailList: [[String: Any]]) -> (...) {
    for item in amountDetailList {
        let userType = intValue(item["userType"] ?? item["user_type"]) ?? -1
        guard userType == 2 else { continue }
        
        let pid = stringValue(item["productId"]) ?? ""
        guard !pid.isEmpty else { continue }
        
        let name = stringValue(item["productName"]) ?? "Reloan \(pid)"
        let logo = stringValue(item["productLogo"])
        let loanAmount = stringValue(item["loanAmount"])
        let amountText = loanAmount.map { "₱\($0)" } ?? "—"
        
        return (productId: pid, productName: name, productLogoURL: logo, amountText: amountText)
    }
    return nil
}

#### 选择复借期限
```swift
private func selectReloanTerms(from termData: [String: Any]) -> (loanAmount: String, showTerm: String)? {
    let amountList = HQTTermV3JSON.amountList(from: termData)
    guard !amountList.isEmpty else { return nil }
    
    // 按金额降序排序，取第一个（最高金额）
    let sortedAmounts = amountList.sorted {
        HQTTermV3JSON.loanAmountInt(from: $0) > HQTTermV3JSON.loanAmountInt(from: $1)
    }
    guard let highestAmount = sortedAmounts.first else { return nil }
    
    let loanAmount = HQTTermV3JSON.loanAmountString(from: highestAmount)
    
    // 获取该金额档的期限列表
    let termList = HQTTermV3JSON.termList(from: highestAmount)
    guard !termList.isEmpty else { return nil }
    
    // 选择最低期限（数值最小）
    let lowestTerm = termList.min { term1, term2 in
        extractNumericValue(from: term1) < extractNumericValue(from: term2)
    }
    
    guard let selectedTerm = lowestTerm else { return nil }
    let showTerm = HQTTermV3JSON.string(selectedTerm["showTerm"] ?? selectedTerm["show_term"]) ?? ""
    
    return (loanAmount: loanAmount, showTerm: showTerm)
}

private func extractNumericValue(from termDetail: [String: Any]) -> Int {
    if let val = HQTTermV3JSON.int(termDetail["loanTerm"] ?? termDetail["loan_term"]) {
        return val
    }
    if let val = HQTTermV3JSON.int(termDetail["term"]) {
        return val
    }
    if let showTerm = HQTTermV3JSON.string(termDetail["showTerm"] ?? termDetail["show_term"]) {
        let digits = showTerm.components(separatedBy: CharacterSet.decimalDigits.inverted).joined()
        if let val = Int(digits) {
            return val
        }
    }
    return Int.max
}
```

## 8.9 复借弹框关闭时机与交互优化

### 8.9.1 弹框关闭时机

复借弹框在以下两种情况下关闭：
1. 用户点击关闭按钮
2. 开始请求下单接口时

**关键原则**：
- 用户点击 Apply 按钮时，弹框**不立即关闭**
- 在 termV3 请求、选择策略、定位获取等步骤中，弹框保持显示
- 只有在真正开始请求下单接口时，弹框才关闭

### 8.9.2 按钮锁定与解锁

#### 按钮锁定
- 用户点击 Apply 按钮时，按钮立即锁定
- 按钮变灰，不可点击
- 防止用户连续点击

#### 按钮解锁
在以下失败情况下，解锁按钮让用户可以重试：
- termV3 请求失败
- 没有可用的贷款选项
- 定位获取失败（强抓模式）
- 定位权限被拒绝（强抓模式）

### 8.9.3 定位权限弹框覆盖

**原则**：复借弹框与定位二次引导均为 `addSubview` 全屏遮罩，**禁止**在复借流程中再 `present` 一层 VC。

**实现（PHI352-DC）**：
- `HQTReloanGuideDialog`：Apply **不** `dismiss`，仅锁定按钮并走 `termV3`。
- `HQTHomeSessionState.activeReloanGuideDialog` 持有当前复借弹框；`userSubmitV3` 发起前 `dismissActiveReloanGuideDialog()`。
- `HQTProductApplyLocationBridge.resolveForNativeOrderSubmit`：`locationSecondaryUsesKeyWindow = true`，`HQTPermissionSecondaryDialog.makeLocation` 挂在 **keyWindow**，叠在复借弹框之上。
- 强抓定位失败 / b3 取消或去设置：结束定位流程、`resetActiveReloanApplyInteraction()`，**复借弹框仍展示**。
- 非强抓：无真实坐标时 `longitude/latitude = -360` 继续下单，拿到坐标后同样先关复借弹框再 `userSubmitV3`。

### 8.9.4 完整交互流程

```
用户点击 Apply
    ↓
按钮锁定（变灰）
    ↓
拉取 termV3
    ├─ 失败 → 解锁按钮，弹框保持显示
    └─ 成功 ↓
       选择金额和期限
       ├─ 失败 → 解锁按钮，弹框保持显示
       └─ 成功 ↓
          获取定位（如果需要）
          ├─ 失败 → 解锁按钮，弹框保持显示
          ├─ 拒绝 → 显示定位权限弹框（覆盖在复借弹框上）
          │   ├─ 取消 → 解锁按钮，弹框保持显示
          │   └─ 去设置 → 解锁按钮，弹框保持显示
          └─ 成功 ↓
             关闭复借弹框
             ↓
             请求下单接口
             ├─ 成功 → 进入抓取流程
             └─ 失败 → 显示错误提示
```

### 8.9.5 与订单详情 H5 的区分

本节仅 **首页复借弹框**；订单详情 H5 的定位/抓取见 `14-订单详情H5.md`，无复借弹框叠层问题。

## 8.11 iOS 18+ 通讯录部分授权（Limited）

业务口径与 `05-数据抓取与通讯录分片.md` §5.3 一致：**Limited 按未授权**，不上传通讯录，`ready` 传 `allowContact=2`。

| 场景 | 首页复借（`failOnContactsSecondaryInteraction=false`） |
|------|------------------------------------------------------|
| 非强抓 + Limited | 跳过 contact，直接 `ready(allowContact=2)` |
| 强抓 + 首次系统弹窗选 Limited / 拒绝 | Toast「Contacts permission is required.」，抓取失败，复借弹框仍展示 |
| 强抓 + 已走过系统弹窗且仍为 Limited/denied | 通讯录二次引导；去设置/关闭均 `completion(false)`（无 H5 回调） |

**实现要点**（`HQTOrderDataCaptureCoordinator`）：
- 仅以 `CNAuthorizationStatus == .authorized` 视为可抓取（`HQTContactsScrapeBuilder.isContactAccessGranted`）
- `requestAccess` 回调 **不得** 单独依赖 `granted`：iOS 18 选「选择联系人」时 `granted` 可能为 `true` 但状态为 `.limited`
- 系统弹窗后须 `authorizationStatus` 再分支；误入 `runContactsPipeline` 且通讯录为空时，`resolvedAllowContactForReady` 兜底为 `"2"`

## 8.10 注意事项

### 8.7.1 定位权限处理（重要）

复借流程的定位权限处理**与产品下单页面完全一致**：

#### 强抓模式（retrieveMobileContact = 1）

| 场景 | 行为 | 说明 |
|------|------|------|
| **首次请求被拒绝** | 返回上一页 | 不显示二次弹框，直接返回 |
| **已拒绝 + 点击取消** | 返回上一页 | 显示二次弹框后点击取消 |
| **已拒绝 + 点击去设置** | **停留当前页面** | 用户从设置返回后可以重新尝试 |
| **授权成功** | 获取位置并提交订单 | 正常流程 |
| **定位失败（GPS）** | 显示重试弹框 | 提供重试选项 |

#### 非强抓模式（retrieveMobileContact = 0）

| 场景 | 行为 | 说明 |
|------|------|------|
| **任何情况** | 使用默认坐标 `-360,-360` | 不请求定位权限 |

#### 实现要点

1. **定位管理器配置**：
   ```swift
   locationManager.delegate = self
   locationManager.desiredAccuracy = kCLLocationAccuracyHundredMeters
   locationManager.distanceFilter = 100
   ```

2. **标志位管理**：
   - `isWaitingForLocationToSubmit`：标记是否正在等待定位以提交订单
   - `isLocationDataSent`：防止重复发送位置数据
   - `isFirstTimeLocationRequest`：区分首次和非首次请求
   - `isLocationAlertShowing`：防止重复显示弹框

3. **回调管理**：
   - 使用 `reloanSubmitCompletion` 保存提交回调
   - 定位成功/失败后调用回调并清空

4. **与产品下单页面的一致性**：
   - 使用相同的定位权限处理逻辑
   - 使用相同的二次弹框提示
   - 使用相同的返回行为

### 8.7.2 接口参数
- **首页**：不传 productId，用于通用复借检查
- **下单页和订单详情**：传 productId（放在 `unsignedData` 中，不加密），用于针对特定产品的复借检查

### 8.7.3 下单页特殊逻辑
- 点击返回按钮时才检查复借，不是进入页面时
- 有复借候选时，不展示返回确认弹框，直接展示复借弹框
- 复借弹框关闭时，返回上一页

### 8.7.4 数据抓取
- 所有三个场景的复借成功后，都必须执行完整的数据抓取流程
- 抓取失败不影响订单状态，用户体验上直接跳转
- 抓取进度弹框让用户感知到数据上传过程

### 8.7.5 成功弹框
- 统一使用 `HQTDialog.showCardAlert`
- 图标：`make_pic_su` 或 `make_pic_successful`
- 标题："Success!"
- 消息："Your application is under review. Once approved, the money will be credited to your bank account."

### 8.7.6 调试日志
- 所有关键步骤都应该有详细的调试日志
- 日志格式：`🔍 [Reloan Debug] xxx页：操作描述`
- 便于问题排查和流程追踪
