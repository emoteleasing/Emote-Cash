# 09-拒量功能

## 概述

拒量功能用于处理被拒绝的用户，通过展示第三方推荐产品列表（H5页面），为用户提供其他贷款选择。用户可以点击推荐产品，跳转到外部浏览器打开第三方产品链接。

## 配置门控（必读）

所有拒量入口均依赖配置字段 **`rejectH5`**（`appConfig` 优先，其次 `categoryConfig` 递归解析为合法 `http/https` URL）。  
工程内通过 `+[HQERejectH5ViewController HQE_isRejectH5Configured]` 判断是否已配置。

| 场景 | 已配置 `rejectH5` | 未配置 `rejectH5` |
|------|-------------------|-------------------|
| 首页提示词（`userStatus == 51`） | 显示箭头；点击进拒量 H5 | **不显示箭头**；点击**无反应** |
| 首页产品 `termV3` 返回 `6234303` | **直接**进拒量 H5（**不弹框**） | 弹统一处理中弹框（`resultMsg`）；**不跳转**（Know More / Confirm 均不导航） |
| 订单列表 `status == 31` | 进拒量 H5 | 进**订单详情 H5**（与普通订单一致） |

`6230002` / `6230003` 仍按 `02-首页Loan.md` §2.5：弹框 + Know More 可进订单详情，与拒量配置无关。

### termV3 错误码与拒量关系

| resultCode | 含义（业务） | 与 `rejectH5` 关系 | 用户可见行为 |
|------------|--------------|-------------------|--------------|
| `6230002` / `6230003` | 已有处理中订单等 | **无关** | 统一弹框；Know More → 订单详情 H5；**不 Toast** |
| `6234303` | 拒量/拒绝导流 | **有关** | 见上表配置门控；**不 Toast** |

- 上述三码均走 `suppressErrorToast` / 不展示接口错误 Toast（见 `00-项目基础规范.md` §00.10）。
- 复借原生链路（`enterSource=reloan`）命中 `6234303` 时：Toast 失败文案并解锁，**不进**拒量 H5。

## 功能触发条件

拒量功能有三个触发入口（均需结合上表配置门控）：

### 1. 首页提示词点击（userStatus == 51）

**触发条件**：
- 首页 `/app/v3/user/suphome` 接口返回 `userStatus == 51`（拒绝状态）
- **`rejectH5` 已配置**
- 用户点击提示词区域

**实现要点**：
- 仅当 `HQE_isRejectH5Configured == YES` 时：提示词显示箭头、区域可点击
- 点击后 `push` 拒量 H5（`HQERejectH5ViewController`）
- 未配置：不显示箭头，点击无反应（不 Toast、不跳转）

### 2. 产品列表点击（termV3 接口返回 code == 6234303）

**触发条件**：
- 用户在首页产品列表点击某个产品
- 调用 `/app/v3/product/termV3` 接口
- 接口返回 `resultCode == 6234303`

**实现要点**：
- **已配置 `rejectH5`**：直接跳转拒量 H5，**不显示**处理中弹框
- **未配置**：使用 `HQE_presentHomeProcessingOrderDialogInWindow` 展示 `resultMsg`，**不进行任何页面跳转**（Know More 不打开订单详情）
- 与 `6230002` / `6230003` 分支分开处理

### 3. 订单列表点击（orderStatus == 31）

**触发条件**：
- 用户在订单列表中看到拒绝状态的订单（`status == 31`）
- 用户点击该订单

**实现要点**：
- **已配置 `rejectH5`**：跳转拒量 H5
- **未配置**：按 `06-订单列表.md` §6.6 跳转**订单详情 H5**（`orderId` / `productId` / `orderType` 等同其它状态）
- 列表展示名为 "Reject"

## 拒量H5页面实现

### 技术架构

**核心组件**：
- 使用 `WKWebView` 加载 H5 页面
- 实现 `WKNavigationDelegate` 处理页面加载
- 实现 `WKScriptMessageHandler` 处理 H5 调用原生

**关键技术点**：
1. 使用 `lazy var` 延迟初始化 WebView
2. 在 WebView 初始化时注册 message handler
3. 使用 Auto Layout 布局
4. 支持手势返回（`allowsBackForwardNavigationGestures`）

### 配置获取

**配置字段名**：`rejectH5`

**获取优先级**：
1. `appConfig` 配置（`/app/v3/app/config` 接口返回）
2. `categoryConfig` 配置（`/app/v3/category/config` 接口返回）

**实现要点**：
- 递归搜索配置 JSON 中的 `rejectH5` 字段
- 支持嵌套对象和数组
- 去除首尾空白字符
- 如果两个配置都没有，返回 nil

### URL 参数传递

**传递方式**：URL 查询参数

**必传参数**：
- `appId`：应用 ID（从项目配置获取）
- `mobile`：用户手机号（从会话存储获取，可能为空）

**URL 构建示例**：
```
原始 URL: https://example.com/reject
构建后: https://example.com/reject?appId=hqteconsmpton&mobile=9123456789
```

**实现要点**：
- 使用 `URLComponents` 构建 URL
- 添加查询参数到 `queryItems`
- 手机号为空时传空字符串

### 用户数据注入

**注入时机**：页面加载完成后（`didFinish` 回调）

**注入方式**：JavaScript 函数调用

**注入数据**：
```json
{
    "appId": "应用ID",
    "salt": "签名盐值",
    "mobile": "用户手机号",
    "baseUrl": "当前API域名",
    "userId": "用户ID",
    "token": "用户token"
}
```

**注入函数**：`rejectData(jsonString)`

**实现要点**：
1. 将数据字典序列化为 JSON 字符串
2. 清理 JSON 字符串中的特殊字符（反斜杠、单引号、换行符等）
3. 调用 H5 页面的 `rejectData` 函数，传入清理后的 JSON 字符串
4. 使用标记变量避免重复注入（页面重新加载时重置标记）

**字符串清理规则**：
- `\` → `\\`
- `'` → `\'`
- `\n` → `\\n`
- `\r` → `\\r`

**H5 接收示例**：
```javascript
window.rejectData = function(jsonString) {
    const userData = JSON.parse(jsonString);
    console.log('接收到用户数据:', userData);
    // 使用 userData 调用后端接口
};
```

### H5 调用原生方法

**通信机制**：`WKScriptMessageHandler`

**Handler 名称**：`iosHandler`（必须与 H5 约定一致）

**消息格式**：字符串格式 `"thirdUrl=<url>&type=<type>"`

**参数说明**：
- `<url>`：第三方产品链接（完整 URL）
- `<type>`：产品类型或备注（用于埋点）

**H5 调用示例**：
```javascript
function openProduct(url, type) {
    if (!window.webkit?.messageHandlers?.iosHandler) {
        console.error('原生环境不可用');
        return;
    }
    
    var message = 'thirdUrl=' + url + '&type=' + type;
    window.webkit.messageHandlers.iosHandler.postMessage(message);
}

// 示例调用
openProduct('https://example.com/product', 'loan');
```

**原生处理流程**：
1. 接收消息，验证 handler 名称
2. 验证消息体是字符串类型
3. 验证消息以 `thirdUrl` 开头
4. 解析消息：移除前缀，按 `&` 分割参数
5. 提取 URL 和类型
6. 上报埋点 502
7. 打开外部浏览器

**消息解析逻辑**：
```
输入: "thirdUrl=https://example.com&type=loan"
步骤1: 移除 "thirdUrl=" → "https://example.com&type=loan"
步骤2: 移除 "type=" → "https://example.com&loan"
步骤3: 按 "&" 分割 → ["https://example.com", "loan"]
结果: url = "https://example.com", type = "loan"
```

### 外部浏览器跳转

**跳转方式**：`UIApplication.shared.open()`

**实现要点**：
- 验证 URL 有效性
- 使用系统默认浏览器打开
- 不需要等待回调结果

**错误处理**：
- URL 无效时静默失败（不显示错误提示）
- 浏览器打开失败时不影响页面继续使用

## 埋点

### 502 - 跳转外部浏览器消息

**触发时机**：H5 页面调用原生方法，准备跳转外部浏览器时

**埋点参数**：
- `eventCode`: "502"
- `eventContent`: "NULL"
- `remark1`: 产品类型（从 H5 传递的 `type` 参数）
- `remark2`: "NULL"
- `remark3`: "NULL"

**实现要点**：
- 在打开浏览器之前上报埋点
- 使用项目的埋点工具类
- `remark1` 使用 H5 传递的类型参数，如果没有则为空字符串

## 注意事项

### 技术实现

1. **WebView 初始化**：
   - 必须使用 `lazy var` 延迟初始化
   - 在初始化时注册 message handler
   - 避免在 `deinit` 中清理（可能导致 actor isolation 错误）

2. **Handler 名称**：
   - 原生端和 H5 端必须使用相同的名称
   - 当前约定为 `iosHandler`
   - 如果 H5 使用其他名称，需要同步修改

3. **消息格式**：
   - 必须是字符串格式，不能是 JSON 对象
   - 格式：`"thirdUrl=<url>&type=<type>"`
   - H5 不能使用 `postMessage({thirdUrl: url, type: type})`

4. **数据注入**：
   - 必须清理 JSON 字符串中的特殊字符
   - 使用单引号包裹 JSON 字符串（因为 JSON 内部使用双引号）
   - 避免重复注入（使用标记变量）

5. **错误处理**：
   - 配置为空时不加载页面
   - URL 无效时不加载页面
   - 消息格式错误时静默失败
   - 浏览器打开失败时不影响页面

### 用户体验

1. **页面标题**：统一使用 "Accurate Recommendation"
2. **加载状态**：WebView 自带加载指示器
3. **手势返回**：支持左滑返回上一页
4. **错误提示**：不显示技术错误信息给用户
5. **外部跳转**：使用系统默认浏览器

### 安全性

1. **数据传输**：确保 H5 页面使用 HTTPS
2. **敏感信息**：token 和 userId 通过 JS 注入传递
3. **URL 验证**：验证 URL 有效性后再打开
4. **消息验证**：验证消息格式和来源

### 兼容性

1. **iOS 版本**：支持 iOS 13+（WKWebView 标准功能）
2. **Swift 版本**：支持 Swift 5.5+（使用 lazy var 和 guard）
3. **H5 兼容**：H5 需要检测 `window.webkit.messageHandlers` 是否存在

### WebView 初始化模式
