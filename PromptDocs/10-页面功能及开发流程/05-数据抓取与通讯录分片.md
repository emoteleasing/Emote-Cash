# 05. 数据抓取（设备上传 -> 通讯录分片 -> installApp -> ready）

## 5.1 抓取入口与控制策略
- 抓取从订单下单成功后开始，依赖 `orderId`。
- 通过 `/app/v3/app/config` 的 `retrieveMobileContact` 控制强抓策略：
  - `1` 或 `2`：强抓（强制权限策略：拒绝可能中断）
  - `0`（及其它）：非强抓（可降级继续）

## 5.2 抓取流程（两阶段 UI：设备 Loading + 通讯录抓取进度条）

**阶段 A — 设备信息（不含抓取进度弹框）**

1. H5 调 Native `uploadData`（`HQTProductApplyH5ViewController` / `HQTOrderDetailH5ViewController`）；首页复借走 `HQTReloanFlowCoordinator` → `HQTOrderDataCaptureCoordinator`。
2. **无论通讯录是否已授权**，先 `POST /app/v3/mobile/device`（`signed.orderId` + 设备信息 `unsigned`）。
3. 设备上传期间展示 **HUD Loading**（`showLoading` / `hideLoading`），**不**展示抓取进度弹框（`HQTScrapeProgressDialog`）。
4. 设备上传失败：关闭 Loading，通知 H5 `uploadDataFail`（或复借 Toast），**不**进入通讯录阶段。

**阶段 B — 通讯录 → installApp → ready（抓取进度弹框仅覆盖本阶段）**

5. 设备成功后，**先**解析/申请系统通讯录权限（`NotDetermined` 时系统弹窗；此时尚未展示抓取进度条）。
6. 通讯录权限结果已决后，展示 **`HQTScrapeProgressDialog`**（自然增长进度，不代表 device 接口进度）。
7. 读取并清洗联系人；若有效条数为 **0**：**跳过** `POST /app/v3/mobile/contact`，进入步骤 9。
8. 若有有效联系人：按 `pushPerCount` 分片上传 `POST /app/v3/mobile/contact`；全部分片成功后再进入步骤 9。
9. **`POST /app/v3/mobile/installApp`**（已安装 App 上报；与强抓无关；**有 list 才请求**，空 list 跳过；失败不阻断）。详见 [`30-installApp已安装应用上报.md`](./30-installApp已安装应用上报.md)。
10. `POST /app/v3/order/ready`（`allowContact` 按授权态）。
11. `ready` 成功 → 进度条 100% 关闭 → H5 `uploadDataSucc` / 复借成功弹框等。

**实现类**：`HQTOrderDataCaptureCoordinator` / 本仓库 `HQITOrderDataCaptureCoordinator`（`device` → contacts → **`installApp`** → `ready`）。

## 5.3 关键接口与 signed/unsigned 字段口径

### 通讯录权限解析（本地逻辑，不是接口）
- 读取系统通讯录权限状态：
  - **已完全授权（`CNAuthorizationStatusAuthorized`）**：允许读取并上传联系人
  - **未决 `NotDetermined`**：先弹**系统**权限框；弹窗后须再读 `authorizationStatus`（勿只信 `granted`）
  - **iOS 18+ `Limited`（部分授权）** / **已 Denied / Restricted**：业务按未授权
- **系统弹窗首次结果为 Denied 或 Limited（选部分联系人）**：**不弹**自定义引导，按不授权处理——首页自动下单 / 精准推荐 / 产品下单 **结束本轮**；其它入口可降级 `ready`（`allowContact=2`）。再次进入且仍为 Denied/Limited 时才出自定义引导。
- allowContact 口径（用于 `/app/v3/order/ready`）：
  - 空串：已完全授权
  - 2：未授权（含拒绝、受限、**iOS 18+ Limited 部分授权**）
  - ~~3：部分授权~~（**不再使用**；Limited 与拒绝同等上报 `2`）

#### 自定义通讯录引导触发（与定位二次引导对齐）

| 时机 | 是否弹自定义引导 |
|------|------------------|
| 系统弹窗**首次**拒绝（Denied）或**首次**选部分联系人（Limited） | **否**（首页自动下单 / 精准推荐结束流程；非强抓其它入口可降级 ready） |
| 进入抓取时已是 Denied / Restricted / Limited | **是** |
| Authorized | 否，继续上传 |

#### iOS 18+ 部分授权（`CNAuthorizationStatus.limited`）

| 检查点 | 规则 |
|--------|------|
| 是否可读通讯录 | **仅** `.authorized` |
| 枚举联系人 | 非 `.authorized` 返回 `[]` |
| 系统弹窗后 Limited | 与 Denied 相同：按不授权，**不**弹自定义引导，退出当前抓取（首页自动下单 / 精准推荐） |

### 上传设备：`/app/v3/mobile/device`
- signed：`orderId`
- unsigned：设备信息大字段字典（来自 `HQTDeviceInfoCollector`；**不得**包含 `03-设备信息收集器.md` §3.6 禁止字段）
- 关键成功条件：resultCode 为成功

### 上传通讯录分片：`/app/v3/mobile/contact`
- signed：`orderId`
- unsigned：`list`（印度联系人切片数组）
- `list` 单条字段（全部必传，字符串类型）：
  - `contactName`：姓名
  - `contactPhone`：手机号（印度规范化 10 位本地号，详见下文）
  - `contactUpdateTime`：最近更新时间，毫秒级时间戳（iOS 无真实来源时传当前时间戳字符串）
  - `contactStorage`：存储位置（`0`=未知，`1`=手机，`2`=SIM；iOS 当前统一 `0`）
  - `contactCount`：联系次数（取不到传 `"-99"`）
  - `contactTime`：最后联系时间（取不到传空字符串 `""`）
- 分片规则：
  - 抓取条数与单次上传条数由 `/app/v3/app/config` 返回值控制：
    - `pushMaxCount`：总上传条数上限
    - `pushPerCount`：单次上传条数
  - 若过滤/去重后有效通讯录条数为 **0**：**不调用** `/app/v3/mobile/contact`，进入 `installApp` → `ready`
  - 联系人清洗完成后，若总条数超过 `pushMaxCount`，按顺序截断，再按 `pushPerCount` 切片
  - 对切片后的 `mobile/contact` 发起多次并发上传（同一批次异步）
  - 任一分片上传失败，则判定抓取失败并中断流程

#### 印度手机号过滤与去重（必须执行）

> 实现类 `HQTIndianPhoneValidator`；规则全文见 `00-基础框架/25-印度手机号规则.md`。

1. 从系统通讯录读取原始联系人（一个姓名多个号码要拆分为多条）。
2. 手机号清洗：去掉字母和特殊字符，**仅保留数字**（粘贴/读取后输入框只显示数字）。
3. 仅保留印度有效号段：
   - **10 位**：首位为 `6`、`7`、`8`、`9`
   - **11 位**：前两位为 `06`、`07`、`08`、`09`
4. 统一规范化为 **10 位本地号**（11 位且以 `0` 开头时去掉首位 `0`）后上传到 `contactPhone`。
5. 去重按规范化号码执行（如 `09876543210` 与 `9876543210` 视为同一号码）。
6. 去掉空号码、无效号码后再做最大条数截断。
7. **姓名为空或仅空格**：仍须上传该条，`contactName` 传 `""`（不得因无姓名丢弃有效号码）。

### 已安装应用上报：`/app/v3/mobile/installApp`

> 完整规格（取数算法、`LSApplicationQueriesSchemes`、signed/unsigned、失败策略）：见 [`30-installApp已安装应用上报.md`](./30-installApp已安装应用上报.md)。

- 时机：contact 结束后、`order/ready` **之前**（无 contact 时同样在 ready 前判断）；强抓/非强抓均走此步骤
- signed：`orderId`（本包 wire：`objection`）
- unsigned：`list`（本包 wire：`exact`）；元素 `{ "appName": "<scheme>" }`
- `list` 来源：`Info.plist` → `LSApplicationQueriesSchemes` + `canOpenURL`（方法名参考 `getAppsIsExitResult`）
- **禁止**传 `remarks`；**无命中（空 list）时不请求**，直接 `ready`
- 失败：**best-effort**，仍继续 `order/ready`，建议不弹 Toast

### 通知 ready：`/app/v3/order/ready`
- 调用前须已完成（或跳过）contact；若有已装 App 则须已完成（或失败尝试）`installApp`；空 list 可直接 ready
- signed：`orderId`
- unsigned：`allowContact`
- 成功后：进入后续成功弹窗与好评流程

## 5.4 强抓权限拒绝的行为规则（你当前需求）

自定义通讯录引导**仅**在「再次进入且已是 Denied/Restricted/Limited」时弹出；**系统弹窗首次拒绝或首次选部分联系人都不弹**。

| 场景 | 自定义引导 | 首页自动下单 / 精准推荐 / 产品下单 |
|------|------------|-----------------------------------|
| 系统弹窗**首次拒绝**或**首次 Limited** | **否**（不 Toast） | 结束流程；精准推荐 `popToRoot`；首页只结束不返回 |
| 非首次已 Denied / Restricted / Limited | **是**；任意按钮均退出 | 精准推荐回首页；首页只结束不返回 |
| Authorized | 否 | 继续上传 |

- 系统弹窗后写入 `kHQITContactsPromptShownKey`（`HQTContactsSystemPrompted`）。
- H5 页二次引导交互：去设置/关闭均 `uploadDataFail`（见 §5.4.1）。

### 5.4.1 通讯录二次引导弹框 → H5 回传（产品申请 H5 / 订单详情 H5）

实现：`HQTOrderDataCaptureCoordinator`，启动参数 `failOnContactsSecondaryInteraction: true`（产品申请页、订单详情页均开启；首页复借默认 `false`）。

| 用户操作 | Native 行为 | H5 回调 |
|----------|-------------|---------|
| 去设置 | 打开系统设置；结束本次抓取 | `window.uploadDataFail()` |
| 关闭 | 结束本次抓取（**不**再 Toast「Contacts permission is required」） | `window.uploadDataFail()` |

- 回调方式：`evalH5Callback` 执行 `typeof window.uploadDataFail==='function' && uploadDataFail()`。
- **产品申请 H5 额外**：二次弹框触发失败时，在 `uploadDataFail` **JS 执行完成后** `popViewController` 返回上一页（`shouldPopAfterContactsSecondaryUploadDataFail` + `onContactsSecondaryDismiss`）；**不** `popToRoot`。
- **订单详情 H5**：仅回传 `uploadDataFail`，**不**自动 pop（留在详情页由 H5 处理）。

其它失败（device 失败、contact 分片失败、ready 失败、强抓首次系统拒权等）同样 `uploadDataFail`，但产品申请页**仅**在「通讯录二次弹框」路径下才在回调后自动返回上一页。

## 5.5 UI 与错误收口
- **设备阶段**：HUD Loading（与通讯录授权无关，必调 device）。
- **通讯录阶段**：`HQTScrapeProgressDialog`（权限已决后再展示；**不包含** device 上传）。
- 任一阶段失败须关闭对应 UI 并中断本次抓取；下次进入须从头（device + 通讯录 + ready）。
- 强抓通讯录首次系统拒绝：不展示二次引导，直接 `uploadDataFail`（产品 H5 是否 pop 见 §5.4.1）。
- 强抓通讯录二次引导（去设置/关闭）：`uploadDataFail`；产品申请 H5 再在回调完成后 pop 一层。

## 5.6 数据抓取进度弹框（交互口径）
- **仅用于阶段 B**（通讯录分片 + ready）；**不**在 device 上传时展示。
- 进度条采用自然增长，不直接绑定单次接口返回进度。
- 默认展示策略：
  - 起始值约 12%
  - 进度在 15-20 秒内自然增长到 99%/99.99%
  - 数据抓取全部完成后立即置为 100%，弹框自动关闭，进入申请成功页
- 增长方式可选（满足任一即可）：
  - 匀速增长：每 1-1000ms 更新一次，匀速增长
  - 跳跃增长：每 1-2000ms 更新，单次随机增长 0.01%-10%，总时长控制在 15-20 秒到 99%
  - 随机增长：每次随机 1-3000ms 更新，单次随机增长，总时长控制在 10-20 秒到 99%
- 当前项目实现建议：
  - 使用匀速增长方案，200ms 一次 tick，随机总时长 15-20 秒
  - 抓取流程结束回调优先于自然增长，结束即自动关闭弹框
