# 04-产品申请与下单 H5 提示词（直接使用）

## 使用目标
- 用于生成“产品申请与下单”的原生 H5 容器与桥接能力。
- 输出要求是**功能完整可运行**，但实现结构、UI 组织、代码分层**不必与当前页面一致**，可重构优化。

## 原生必须实现的能力（描述性要求）

### 1) 入口与页面打开策略
- 从产品入口进入时，先完成产品可申请性与额度期限数据准备，再进入 H5。
- H5 链接由配置下发，支持绝对链接与相对链接（相对链接需拼接当前可用域名）。
- 页面打开时需要携带业务维度参数（如产品标识），并补齐通用环境参数注入。

### 2) 容器基础能力
- 使用统一 H5 容器标准：
  - 导航控制与返回策略一致
  - 加载遮罩与进度可视化
  - 可重复注入用户上下文数据
  - 异常兜底（链接非法、域名不可用、加载失败）
- 支持 H5 主动请求“再次同步环境数据”。

### 3) 定位与权限分级
- 原生需处理 H5 发起的位置能力请求，并按配置区分强依赖与非强依赖：
  - 强依赖：无权限时中断下单主流程
  - 非强依赖：可降级使用默认值继续流程
- 权限拒绝、受限、首次授权、回到前台后权限变化等分支都要闭环。

### 4) 数据抓取与就绪链路
- H5 触发“开始抓取”后，原生串行执行设备信息上报、通讯录分片上传、就绪确认。
- 通讯录权限需支持强抓与非强抓分支；拒绝时要按策略决定失败中断或降级继续。
- 成功与失败结果必须回传 H5，且可被前端明确感知与重试。

### 5) 成功回跳与后续引导
- H5 成功页触发返回后，原生需要执行后续流程（如引导弹层、评分引导、返回首页或指定页）。
- 引导策略需要受配置控制，并支持“安装周期内频控/仅展示一次”。
- 成功页与反馈入口类动作都应复用同一套后续决策逻辑。

### 6) 账号态与安全退出
- H5 触发退出登录/注销等安全动作时，原生必须清理会话并重建登录入口。
- 要避免仅关闭当前页面导致脏会话残留。

### 7) 外链与非标准跳转处理
- H5 内出现非站内协议或外部链接时，原生要做协议识别：
  - 支持系统可打开的外链拉起
  - 打开失败给出统一提示
  - 避免无响应或空白页卡死

### 8) 防连点与幂等
- 对“会触发网络提交/状态迁移”的桥接动作必须防重复触发。
- 原生侧需保证关键链路幂等，避免重复提交订单、重复抓取、重复回跳。

## H5 交互与消息约定（必须实现）

### A) 通道与通用规则
- H5 与原生交互使用统一通道 `iosHandler`。
- 消息 action 大小写不敏感处理，并兼容历史别名。
- 所有 H5 -> 原生动作都要有异常保护：消息体缺失、参数非法、状态不满足时不能崩溃。

### B) 关键动作清单
- 环境数据同步类：H5 主动请求原生重新下发用户与设备上下文。
- 定位权限类：H5 请求当前位置与权限状态，原生按强抓/非强抓策略回传。
- 抓取触发类：H5 传入订单标识后，原生启动“设备 -> 通讯录 -> ready”链路。
- 成功页动作类：返回、反馈入口、去评分等动作统一进入“成功后处理器”。
- 返回导航类：申请页返回时，原生按当前导航栈回退并恢复上层页面状态。
- 账号态类：退出登录/注销动作触发原生清会话并重建登录根流程。

### C) 下单交互时序（什么时候传什么）
1. **页面打开后（原生 -> H5）**
   - 首次注入运行环境数据：
     - 身份与会话：`userId`、`token`
     - 运行环境：`baseUrl`、`UA`、`appId`、`clientVersion`、`countryCode`
     - 设备标识：`deviceId`
     - 业务上下文：`productId`、来源场景（如首页/复借）
2. **H5 需要刷新上下文时（H5 -> 原生 -> H5）**
   - H5 发送“请求用户数据”动作；
   - 原生立即回传最新同口径数据（用于 token 更新、域名切换后重同步）。
3. **H5 请求定位时（H5 -> 原生 -> H5）**
   - H5 发起位置请求；
   - 原生回传定位结果对象：
     - 有权限：`longitude`、`latitude`（JSON 对象）
     - 非强抓、非首次且无权限：`{"longitude":"-360","latitude":"-360"}`
     - 首次拒绝 / 强抓且无权限 / b3 取消或去设置：回传字面量 `""`（**禁止** `{"longitude":"","latitude":""}`）
4. **H5 下单成功后（H5 -> 原生）**
   - H5 必须回传订单标识（`orderId`）和可选业务标识（如 `productId`、`orderType`）；
   - 原生收到后才允许启动抓取链路。
5. **原生抓取链路完成后（原生 -> H5）**
   - 成功：回传统一成功信号（供 H5 跳成功页）
   - 失败：回传统一失败信号（供 H5 显示错误并允许重试）
6. **成功页交互（H5 -> 原生）**
   - H5 “返回/去反馈/去评分”入口动作回传给原生；
   - 原生按配置执行好评分流并导航到目标页面。

### D) 原生 -> H5 回调方法名（必须对齐）
- 用户环境数据注入方法：`mobileUserdata(payload)`
  - 用途：页面首屏注入、H5 主动请求时再次注入
- 定位结果回调方法：`positionPermission(payload)`
  - **payload 类型与取值（iOS 必须按下列口径，不得混用）**：
    | 场景 | payload |
    |------|---------|
    | 成功 | `{ "longitude": "…", "latitude": "…" }` |
    | 非强抓、非首次且无权限 | `{ "longitude": "-360", "latitude": "-360" }` |
    | 首次系统弹窗拒绝 | 字面量 `""` |
    | 强抓且拿不到定位（含 b3 取消 / 去设置） | 字面量 `""` |
  - **禁止**：`{"longitude":"","latitude":""}`（空对象 JSON）代替空串。
  - storage 键 `positionPermission` 与 `window.positionPermission` 参数保持一致（空串时均写 `""`）。
  - Native 须**依次尝试** `positionPermission(对象)` 与 `positionPermission(JSON.stringify(对象))`（联调常见 `ok_str`）。
- 抓取成功回调方法：`uploadDataSucc()`
- 抓取失败回调方法：`uploadDataFail()`

说明：
- 为兼容历史页面，可同步写入 `localStorage/sessionStorage`（键名与方法名保持一致）。
- 若 H5 使用命名空间（如 `window.xxx`），需确保调用入口统一且可降级到全局函数。

## 下单与数据抓取流程（可直接实现）

### 1) 下单前准备
1. 获取产品申请页链接配置与域名可用性。
2. 拉取产品额度期限信息用于校验与渲染。
3. 确认定位与通讯录策略开关（强抓/非强抓）。

### 2) 下单发起口径（H5 主导）
- 该页面下单由 H5 发起，原生不调用下单接口。
- H5 下单成功后将订单标识通过桥接消息回传给原生，原生再启动后续抓取链路。
- H5 下单失败时，原生仅负责承接错误提示与页面状态恢复，不重复提交下单请求。

### 3) 抓取链路时序
收到 H5 抓取触发动作后，原生串行执行：
1. 设备信息上传：`/app/v3/mobile/device`
2. 通讯录分片上传：`/app/v3/mobile/contact`
3. 订单就绪确认：`/app/v3/order/ready`

链路规则：
- 任一步失败进入失败回传；成功则回传抓取完成。
- 通讯录权限拒绝时：
  - 强抓：本次链路失败
  - 非强抓：按降级参数继续到 ready
- 分片上传需支持大数据量与重试，不允许阻塞主线程。

### 4) 与 H5 的抓取结果回传
- 成功：回传统一成功信号，由 H5 进入成功页。
- 失败：回传统一失败信号，并允许 H5 触发再次尝试。
- 回传必须保证“同一订单同一轮链路只回一次最终态”。

## 传参与环境注入口径（必须）

### URL 业务参数
- 打开申请 H5 时携带业务主参数（如 productId），其余按场景补充。
- 不传空字符串占位参数。

### 原生注入数据（给 H5）
- 必含：`baseUrl`、`userId`、`token`、`UA`、`deviceId`、`clientVersion`、`appId`、`salt`、`countryCode`。
- 业务扩展：`productId`、订单标识、来源场景等。
- 支持“首次注入 + 页面完成后延迟补注入 + H5 主动请求时再次注入”三段式同步，减少 H5 初始化时序问题。

## 好评模块入口衔接（成功后流程）

- 触发来源：
  - H5 成功页“返回”
  - H5 成功页“去反馈/去评价”入口
- 原生处理：
  - 统一读取引导配置（如 `feedbackGuidance`）
  - 执行展示频控（安装周期仅一次或按配置）
  - 按评分结果分流：
    - 高分：进入系统评分或应用商店评价
    - 低分：进入应用内感谢/反馈承接
- 无论是否展示好评，都要保证主流程可回到首页或业务目标页。

## 交付质量要求（必须）
- 允许与当前页面视觉或代码结构不同，但必须满足同等或更强业务能力。
- 不写死临时字段名，关键参数、开关、文案均从配置或接口返回驱动。
- 所有失败分支都有可见反馈（toast/弹窗/状态提示），且不会卡死加载态。
- 可直接进入联调：包含必要日志点与最小自测清单。

## 9. 联调已通过实现要点（PHI352-DC，按此直接实现）

> 以下与当前工程 `HQTProductApplyH5ViewController` 等实现一致；2026-05 全链路验证：termV3 → H5 → positionPermission → uploadData&&orderId → device/contact/ready → uploadDataSucc。

### 9.1 入口 termV3
- 首页点产品 → `POST /app/v3/product/termV3`，signed **仅** `data.productId`（wire 勿混 `productNo`）。
- `resultCode == 200` 后 push `HQTProductApplyH5ViewController`，URL = `productApplyLink` + `?productId=xxx`（相对链拼接 `HQTDomainManager` 当前域名）。

### 9.2 H5 消息体格式（iosHandler）
| H5 发送 | Native 解析 |
|---------|-------------|
| 字符串 `uploadData&&2059164805263581184` | `parseAction` → `uploaddata`；`parseUploadDataOrderId` 取 `&&` 后 orderId |
| `positionPermission` / JSON `{type:...}` | action → `positionpermission` |
| `productGoBack` | **直接** `popToRootViewController`，**无**返回确认弹框 |
| `successfulGoBack` / `successfulGoFeedback` | 先好评弹层，再 pop + 刷新首页 |

### 9.3 positionPermission（必须与 H5 双形态回调）
- 实现类：`HQTProductApplyLocationBridge`。
- payload 表见上文 §C；**禁止** `{"longitude":"","latitude":""}`。
- 注入 JS（base64）须**依次**调用：
  1. `window.positionPermission(对象)`
  2. `window.positionPermission(JSON.stringify(对象))`
- 空串分支：`positionPermission("")`，storage 键 `positionPermission` 也为 `""`。
- 联调日志：`H5 回调 status=ok_obj` 或 `ok_str`（本包 H5 多为 `ok_str`）。
- 防重：`isPositionPermissionInFlight`；定位中收到 `uploadData` → `pendingUploadOrderId`，定位结束再抓。
- 超时 45s 未结束 → 按强抓空串 `""` 结束并释放 in-flight。
- `finishPayload` 内 `completion` 只交付一次，避免重复回传。

### 9.4 uploadData 抓取时序
1. **device**（HUD，无进度弹框）
2. 通讯录权限（强抓首次系统拒 → `uploadDataFail`）
3. **`HQTScrapeProgressDialog`**（通讯录权限已决后展示；15–20s 进度至 99%）
4. **contact** 分片（无有效联系人可跳过上传，`allowContact=2`）
5. **ready** → `window.uploadDataSucc()` / `uploadDataFail()`
- 协调器：`HQTOrderDataCaptureCoordinator`；**不**调 `userSubmitV3`（下单在 H5）。

### 9.4.1 通讯录二次引导弹框（强抓，系统已弹过后）
- `failOnContactsSecondaryInteraction: true`（与订单详情一致）。
- **去设置** / **关闭** 均：`uploadDataFail()`（`evalH5Callback` 调 `window.uploadDataFail`）。
- **产品申请页专有**：`uploadDataFail` JS **执行完成后** `popViewController` 回上一页（非 `popToRoot`）。
- 实现：`onContactsSecondaryDismiss` → `shouldPopAfterContactsSecondaryUploadDataFail` → `popPreviousPageIfContactsSecondaryCaptureFailed()`。

### 9.4.2 H5 必须注册的全局回调
```javascript
window.uploadDataSucc = function () { /* 进入成功页 */ };
window.uploadDataFail = function () { /* 失败态；申请页可能在 Native pop 前短暂展示 */ };
```
未注册时 Native 仍会调 JS，但无业务效果（联调注意）。

### 9.5 mobileUserdata 注入
- `didFinish` 后延迟重试（base64 注入 `mobileUserdata(...)`），日志：`mobileUserdata 注入成功 attempt=N`。
- 桥接 `getUserData` / `getMobileUserdata` 可触发重新注入。

### 9.6 调试日志（建议保留）
- `📩 [Apply] iosHandler action=... body=...`
- `HQTNetworkLogger`：Debug 下全量打印请求/响应 body（含 termV3、device、contact、ready）。

### 9.8 与原生 TermV3 下单页的差异
- §4.9.4「返回确认弹框」仅适用于**原生**申请/复借页；**H5 申请页 `productGoBack` 不弹确认**。
- H5 下单由前端发起；Native 只在 `uploadData&&orderId` 后抓数。
